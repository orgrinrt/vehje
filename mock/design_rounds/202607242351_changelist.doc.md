# Doc changelist: Core binders become Sym

**Round:** 202607242351
**Phase:** DOC
**Scope:** `vehje-ir/DESIGN.md.tmpl` only. The Core binder positions (`Var`, `Let.name`, `Lambda.param`) become the generic identity handle `Sym` from `hilavitkutin-sym`; a source name is a `Str` widening losslessly to `Sym`, a minted binder a `Sym` from a `Generator<BinderDomain>`. `Literal::Str` and `Project.key` stay `Str`.

## `vehje-ir/DESIGN.md.tmpl`

- The Core-forms description: where it says a binder form carries "`Str` for names," state that binder identity is a `Sym` (the generic handle from `hilavitkutin-sym`), of which a source name is one domain (a `Str` widened) and a minted binder another; literal payloads and the `Project` key stay `Str`.
- The name-identity paragraph (currently "`Str` (the interned handle from `hilavitkutin-str`) is the name identity in Core"): rewrite to name `Sym` as the binder identity, `Str` as the string-literal-and-label identity, and note that `Str` is now a view over a string-kind `Sym` so widening is zero-cost.
- Add `BinderDomain` (vehje-ir's `GenerativeDomain` marker, kind `0b001`) to the exported surface, so a following round's `Anf` can mint binders from a `Generator<BinderDomain>`.
- Dependencies: add `hilavitkutin-sym` (for `Sym`, the domain traits, and the binder domain) alongside the existing `hilavitkutin-str`.

## Not in this changelist
