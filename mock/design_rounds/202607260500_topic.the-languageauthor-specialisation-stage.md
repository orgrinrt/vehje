# The LanguageAuthor specialisation stage

**Date:** 2026-07-26
**Phase:** TOPIC
**Scope:** `vehje-signature`, `vehje-runtime-gen`, `mock/runtime-zig/`
**Task:** #52

The canon requires that the shipped runtime be specialised to a language
definition at our build, and that the language's own computation live inside that
specialised artifact. Neither exists. This round is the stage that makes both
true, starting with arithmetic as the first family whose semantics must reach the
runtime as data.

## What the canon fixes

Three statements, all from `mock/research/canon/the-soul-of-vehje-positive-catalogue.md`,
which is ratified with the lead designer in the loop and governs.

Frontier A places the work and names the technique: "Ahead-of-time work lives at
LanguageAuthor (specialising the general Zig runtime to the language definition
at our build, which is the first Futamura projection as a build step, the
technique weval demonstrates for wasm interpreters in production)".

Section 3 names the shipped artifact: "a shipped Zig composed runtime (one
hand-authored engine comptime-specialised to the Rust-emitted data)". The engine
is hand-authored and general; the shipped thing is that engine after
specialisation. Family-freedom is a property of the engine before specialisation,
not of what ships.

Frontier E fixes the medium and forbids the alternative: Rust emits validated
*data*, never Zig *source*, the latter being killed at topic 1627 as the
LMS-hard, hard-to-certify route (restated in the inverse catalogue's Part C).

op's standing call 2 (`mock/research/202607260100_op-standing-design-calls.md`)
states the consequence directly: the host configures the runtime and lends it
allocations, and does not supply arithmetic.

## What is actually there

The stage is absent, and its absence is why the language's operators ended up
outside the runtime.

`mock/crates/vehje-runtime-gen/src/lib.rs:108`: `generate` takes `_signature`,
underscore-prefixed, and never reads it. It composes caller-supplied byte slices
and content-addresses them. The negative catalogue's Part H already lists
"runtime-gen ignores the signature" as claimed-but-not-built.

`mock/runtime-zig/src/runtime.zig:410-415`: with no specialisation stage, every
family operation is dispatched to a host callback, refusing with
`EvalError.NoHost` when none is supplied. The comment there defends this as what
"keeps the framework family-free", which conflates the general engine with the
shipped artifact.

`mock/crates/vehje-signature/src/lib.rs`: `Operation` carries a `FamilyId`, an
`EffectMask`, and a `LeaseRule`. It carries nothing that says what the operation
*computes*.

## The open question this round has to settle

**By what concrete representation do the semantics of a family operation cross
from Rust into the Zig runtime as data, such that Zig comptime can specialise the
engine against them?**

The crux, stated so it is not papered over: the canon says the framework owns no
family, so the general engine cannot hardcode arithmetic. It also says Rust emits
data, not source, so the semantics cannot arrive as Zig text. An operation's
meaning therefore has to be expressible in some data language that Zig comptime
can turn into an evaluator, and that data language's expressive range is the
design decision. A fixed opcode table serves arithmetic and fails an arbitrary
family; something richer risks becoming an interpreter for a second IR.

Subsidiary questions that ride on the answer:

- What `Signature::Operation` gains, given it currently carries no semantics.
- What `SliceKind::FamilyTable` and `SliceKind::LoweringRules` actually contain.
- Whether `Raw` remains the vehicle for a specialised family operation once the
  runtime computes it, or whether the distinction between `Raw` and `Perform`
  shifts. The purity argument that shaped `Perform` (arithmetic lowers to `Raw`
  and must not acquire an effect, `mock/research/202607252100_handle-clause-representation.md`)
  bears on this.
- How the emitter seam is closed, given the canon names it as the trust seam and
  refuses a trusted emitter (Frontier F).

## Status

The question is dispatched to a domain expert under the canon gate
(`.claude/rules/expert-dispatch-defends-the-canon.md`); the deliverable lands at
`mock/research/202607260400_family-semantics-as-data.md`. Per that rule no call

independent read is owed before this topic records a resolution.

If the canon fixes the representation, this topic records it with the quoted text
and the round proceeds to a doc CL. If the canon leaves it open, the call is the
lead designer's and this topic records the question rather than an answer.

## Blocked on, and not blocked on

Not blocked on the open question about where a front end runs. The specialisation
stage is required under every reading of that question: whatever parses a script,
the shipped runtime must own computation and must be specialised to the language
definition to do it.

The first red test this round owes, per `catalogue-edge-cases-as-tests.md`: a
program computing `1 + 2` evaluated with a null host returns 3. It fails today at
`runtime.zig:414` with `NoHost`, and that red is correct until the stage lands.
