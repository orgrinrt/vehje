# Current state

Clause ships 11 crates with ~3800 lines of source. Every public
fallible path in the compiler and the runtime boundary currently
uses bare `core::option::Option<T>` and `core::result::Result<T, E>`
inherited from the pre-notko seed. The `no-bare-option` and
`no-bare-result` lints fire at error severity for every public
signature; tightened #117 enforcement also flags intra-module use.

Count per the 2026-04-21 scan:

- `Option<T>` — 43 occurrences across clause-lex (17), clause-resolve
  (13), clause-syntax (9), clause-codegen (1), plus ast/tokeniser
  internals.
- `Result<T, E>` — 13 occurrences. 8 are pub (lint-flagged):
  `clause_codegen::emit`, `clause_codegen::native::emit`,
  `clause_codegen::jomini::emit`, `clause_resolve::resolve`,
  `clause_resolve::manifest::parse`, `clause_syntax::parse`,
  `clause_runtime_driver::loader::load`,
  `clause_runtime_driver::RuntimeHandle::execute`, and
  `clause_runtime_tests::test_runtime_roundtrip`. 5 more are
  internal.

Neither `notko` nor any notko re-export is in
`[workspace.dependencies]` today. The prior arvo and hilavitkutin
sweeps proved the substitution pattern; the clause repo hasn't
picked it up yet.

Two bodies of context sit outside scope of this slice and belong
to #73.2 and #73.3:

- `Vec<T>` / `HashMap<K, V>` collection retirement — clause-typecheck
  alone has 16 `Vec<Diagnostic>` returns. Handled in #73.2 via
  `DiagnosticSink`.
- Raw `usize` / `u8` / `u32` / `i32` / `String` — handled in #73.3,
  which adds `hilavitkutin-str` and uses existing arvo primitives.

# Changes proposed

## Dependency addition

Add to `mock/Cargo.toml` `[workspace.dependencies]`:

```toml
notko = { git = "ssh://git@github.com/orgrinrt/notko.git", branch = "dev" }
```

Every clause phase crate that imports `Maybe` or `Outcome` declares
`notko.workspace = true` under its `[dependencies]`. The direct
dep pattern mirrors arvo and hilavitkutin; notko stays a leaf in
the clause-dev DAG.

## Type substitution

`Option<T>` → `notko::Maybe<T>` everywhere across public and
internal surfaces of the clause phase crates. `Option` remains
permitted inside `core::`/`std::` trait method impls (the `next()
-> Option<Item>` / `fmt() -> fmt::Result` escape hatch) and in
`#[cfg(test)]` modules. No other exemption.

`Result<T, E>` → `notko::Outcome<T, E>`. Same exemption envelope.

`None` constructs become `Maybe::Isnt`; `Some(x)` becomes
`Maybe::Is(x)`. `Ok(v)` / `Err(e)` become `Outcome::Ok(v)` /
`Outcome::Err(e)`. Conversion sites at `std`/`core` trait-impl
boundaries carry a trailing-inline `lint:allow(bare_option)`
`tracked: #73` with a one-line why. No unprefixed comments.

## Crate-by-crate scope

Eight crates gain a `notko` dep:

- clause-lex — 17 `Option`, 0 `Result`. Cursor / tokeniser / stream
  peek/bump paths.
- clause-syntax — 9 `Option`, 2 `Result`. AST accessors, parser
  entry. The `Vec<SyntaxError>` stays (handled in #73.2).
- clause-resolve — 13 `Option`, 3 `Result`. Scope tree, symbol
  lookup, resolver, manifest.
- clause-typecheck — 0 `Option`, 0 `Result`. Skipped this slice.
  (Its drift is entirely collection-shaped; #73.2.)
- clause-codegen — 1 `Option`, 8 `Result`. TargetRegistry lookup +
  every emit path.
- clause-runtime-driver — 0 `Option`, 2 `Result`. Loader + handle
  execute.
- clause-runtime-tests — 0 `Option`, 1 `Result`. Roundtrip test.
- clause-runtime-abi — 0 `Option`, 0 `Result` in Rust. The ABI
  already uses `ClauseResult` (i32 sentinel). No change.
- clause-ir — 0 `Option`, 0 `Result`. Skipped.
- clause-schedule — 0, 0. Empty crate.
- clause — 0, 0. Binary shell.

## Internal-error-type carryover

`clause-codegen::CodegenError`, `clause-resolve::ResolveError`,
`clause-syntax::SyntaxError`, `clause-runtime-driver::LoaderError`,
`clause-runtime-driver::DriverError`, `clause-runtime-tests::
LoaderError` keep their shapes. Only the outer `Result<T, E>` shell
changes to `Outcome<T, E>`. Interop with the `?` operator is
preserved; `Outcome<T, E>` implements `Try` via the notko
`try_trait_v2` integration (verified in prior hilavitkutin sweep).

## Doc-comment cleanup

Every `///` / `//!` that names `Option` or `Result` explicitly
updates to the new type name. References in BACKLOG.md.tmpl and
DESIGN.md.tmpl under `mock/crates/*/` update in the doc CL.
Parity-oracle comments pointing at the Python prototype do not
change (the oracle uses exceptions, so the comparison is already
loose).
