# Source Changelist: clause fallibility sweep

**Date:** 2026-04-21
**Phase:** SRC
**Scope:** clause-codegen, clause-resolve, clause-runtime-driver,
clause-runtime-tests, clause-syntax, clause-lex. Plus
`mock/Cargo.toml` to declare the `notko` workspace dep.

**Source topics:**
- 202604211741_topic.fallibility-sweep.md

## Purpose

Retrofit every clause source site that currently carries
`Option<T>` / `Result<T, E>` to the notko equivalents (`Maybe<T>`
/ `Outcome<T, E>`). This is the first of three planned #73 slices;
collection retirement (#73.2) and numeric / string / pub-marker
retrofit (#73.3) land after this.

Neither trait bounds nor inner error types change. Only the outer
shell of fallible return types and of optional-value fields /
locals shifts from the std-prelude types to the notko types. The
`?` operator remains usable via notko's `try_trait_v2` integration
(proven in the earlier arvo and hilavitkutin sweeps).

Doc counterpart is `202604211741_changelist.doc.lock.md`. That
changelist already updated the five DESIGN / BACKLOG templates
that name `Option` / `Result` in type signatures.

### Change S2 — `clause-lex`: Option → Maybe (17 sites)

Add `notko.workspace = true` to `mock/crates/clause-lex/Cargo.toml`
`[dependencies]`. Import `notko::Maybe` at each call site via
`use notko::Maybe;` at the top of each module below.

Files and sites:

- `cursor.rs` — 4 `Option<u8>` / `Option<char>` returns in
  `peek_byte`, `peek_char`, `next_byte`, `next_char`.
- `keyword.rs` — 1 `Option<TokenKind>` return in `lookup_keyword`.
- `lexer.rs` — 6 `Option<Token>` sites across `next_token`,
  `peek`, and internal scan helpers.
- `stream.rs` — 5 `Option<Token>` sites in `peek`, `next`, and
  cursor-forward helpers.
- `tokenizers.rs` — 6 `Option<...>` across scan helpers.
- `trivia.rs` — 7 `Option<Trivia>` sites in trivia scanners.

At every call site, `None` becomes `Maybe::Isnt`, `Some(x)`
becomes `Maybe::Is(x)`. Pattern matches that destructure
(`Some(t) => ...`, `None => ...`) become `Maybe::Is(t) => ...` /
`Maybe::Isnt => ...`. `.unwrap_or(default)` → `.unwrap_or(default)`
— the notko method has the same name.

### Change S8 — eight parity-oracle doc-comments

Any `///` or `//!` line in the seven crates above that mentions
`Option<T>` or `Result<T, E>` as the actual return type (not as
an example of the stdlib type being replaced) updates to the
notko name. Lines that describe the ban rule or reference `fn
next() -> Option<Item>` as a std-trait escape hatch stay.

Verified by `grep -rn "Option<\|Result<" mock/crates/clause-*/src/`
after S2–S7; any remaining hits on non-`#[cfg(test)]` lines must
fall into the escape-hatch envelope (`core::Iterator::next`,
`core::cmp::PartialOrd::partial_cmp`, `core::fmt::Result`,
`core::convert::TryFrom`). Each escape carries a trailing-inline
`lint:allow(bare_option) tracked: #115` (core-freedom directive)
or `lint:allow(bare_result) tracked: #115`.

### Change S8 — lib.rs reorganization: move top-level pub fns to submodules

The `no-bare-pub` lint scans only each crate's `lib.rs`, not its
submodule files. Sibling repos (hilavitkutin, arvo) pass this
lint because their `pub fn`s live in submodules and re-export
via `pub use` (which the lint treats as exempt). Clause carried
five pub fns directly in lib.rs files as a seed-round artifact.

Move each to the existing per-crate submodule infrastructure
with a `pub use` re-export in `lib.rs`. No public API changes
for callers; import paths stay identical.

- `clause-runtime-tests`: `test_runtime_roundtrip` → new
  `src/roundtrip.rs`. `lib.rs` keeps `pub use roundtrip::
  test_runtime_roundtrip`.
- `clause-codegen`: `emit` → existing `src/registry.rs`
  alongside `TargetRegistry`. `lib.rs` keeps `pub use
  registry::{emit, TargetRegistry}`.
- `clause-resolve`: `resolve` → existing `src/resolver.rs` as
  a free fn alongside `Resolver`. `lib.rs` keeps `pub use
  resolver::{resolve, Resolver}`.
- `clause-syntax`: `parse` → existing `src/parser.rs` as a free
  fn alongside `Parser`. `lib.rs` keeps `pub use parser::
  {parse, Parser, TokenCursor}`.
- `clause-typecheck`: `typecheck` → existing `src/registry.rs`
  alongside `ValidatorRegistry`. `lib.rs` keeps `pub use
  registry::{typecheck, ValidatorRegistry}`.

The trailing-inline `lint:allow(bare_collection)` comments move
with their respective fns; nothing else changes about their
bodies or signatures.
