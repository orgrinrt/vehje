# Doc changelist: compound values across the host boundary

**Date:** 2026-07-25
**Phase:** DOC
**Topic:** `202607251700_topic.compound-values-across-the-host-boundary.md`

Three documents describe the seam this round changes. The operand contract is stated in the ABI crate, the
value model and its arena in the runtime, and the mirrored host surface in the driver. Each edit below names
the section and what it says after the edit.

## `mock/crates/vehje-runtime-abi/DESIGN.md.tmpl`

The operand record itself is documented in `runtime-zig`, where the family-dispatch contract is stated, so
this document takes only the value-image half.

**Section: the value image (`### The value image: the pinned byte layout`).** Add that the image is the
marshalling format for the host boundary in both directions, not only for the produced value crossing back.
Name the two properties that make that work rather than merely being convenient: the header carries a root, so
an image can describe a subtree rather than only a whole result, and the reader bounds-checks every index and
span. Name the consequence: a compound arriving from a handler is validated by the same decoder that validates
a value leaving for the host, rather than by a second decoder written to the same specification and trusted to
agree. Add that an image the decoder rejects is a named refusal, distinct from a handler reporting failure.

## `mock/runtime-zig/DESIGN.md.tmpl`

**Section: `## Family operations reach their handler`, the operand paragraph.** State that the record serves
three shapes without changing its own: a scalar carries its value in the payload word with a null pointer, a
string carries its bytes with their length in the payload, and a compound carries a value image with that
image's byte length in the payload. Say plainly that this is the string convention generalised rather than a
new one, so the common case is unchanged in size and cost, and that the tags remain the value image's tags.

**Same section, a new paragraph on why the image is the format.** State that a compound crosses as a value
image in both directions, and give the three reasons: the image already exists as the produced-value format,
it carries a root so it can describe a subtree, and its reader already bounds-checks and proves acyclicity by
the one monotone check that children-before-parents emission buys. Name the consequence, one decoder rather
than two specifications trusted to agree.

**Same section, the return paragraph.** Extend it so a compound return uses the same scratch and the same
out-slot as a string return, with the bytes being an image the runtime materialises into its value arena. Add
the rejected-image refusal alongside the exhausted-scratch one, and say what it buys: a handler that produced
something unusable stays distinct from one that failed.

**New section `## The value arena`, between `## Environments` and `## The evaluated set`.** State-labelled
intended. Four things. Where a compound lives: a caller-lent arena in the same shape as the environment arena,
host-lent, bump-allocated, owned by the runtime no longer than the call, with a record being a node with its
fields in a child pool so materialising an image is a walk rather than a translation. That its record carries
operands inline rather than through a pool indirection, with the measurement that decides it
(`value-arena-throughput`: 10.7 ns per node pool-indirected against 4.4 ns inline, attributable to the
indirection rather than to transport). That values are stored plainly with no interning and no deduplication,
stated as a design position rather than an omission, with both refusing measurements (`string-interning` 2.2x
to 3.1x slower across three regimes including the one built to remove the bias favouring the do-nothing
strategy; `dedup-vs-reuse` 9x to 19x slower than reuse and 6x to 7x slower than plain). And that the update
path is written so a per-site uniqueness bit selects in-place against copy, with copy as the behaviour until
the bit exists, why that direction is the safe one, and why reuse and deduplication cannot both be defaults:
the deduplication table is itself a referrer, so interning a value forfeits reuse on it permanently.

**Section: `## The refusal set`.** Add the exhausted value arena and the rejected returned image.

**Section: `## Intended, not shipped`.** Drop the two compound entries, which this round moves into the
shipped text. Add the reuse analysis as its own entry, naming that the runtime side is designed for it while
the emit-time verdict is not built and its derivation from the lease masks is intended rather than
demonstrated. Extend the remaining-Core-forms entry: `Project` becomes implementable once records exist and
its strategy is already settled by measurement (0.54 ns fixed offset where the shape is static, 0.61 ns
monomorphic inline cache otherwise, 1.27 ns hashed rather than 1.57 ns scanned at a polymorphic site), and
`Handle` is what non-local control flow lowers to and needs only the non-resuming discharge for it.

## `mock/crates/vehje-runtime-driver/DESIGN.md.tmpl`

**Section: the host surface the driver passes through.** State that the operand the driver carries now has a
compound form, and that the driver continues to interpret none of it: it moves the contract, it does not read
the family's values. Keep the existing posture sentence about the sink and extend it to cover compounds.

**Section: the lent buffers.** State that a host servicing a family operation that returns a compound writes
into the same session scratch already lent for returning strings, so the round adds no new lending channel.

## Not in this round

`Project` evaluation, though it becomes possible with this round. Its strategy is already settled by
measurement and it is a well-specified follow-on; keeping it out keeps this round's boundary claim auditable
alone.

The pattern representation and `Handle`'s clause representation, both deferred with their own rounds owed.

The reuse analysis itself, which needs the emit-time uniqueness verdict whose derivation from the lease masks
is still only intended.
