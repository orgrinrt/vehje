# Topic: the runtime executes, and a produced value crosses back

**Date:** 2026-07-25
**Phase:** TOPIC
**Scope:** correct the `runtime-zig` design to what the runtime actually is (the residual executor), and define the byte contract a produced value crosses back in. The Rust side of that contract lands with this round; the Zig writer and the driver embedding follow in their own rounds.

The Zig runtime now evaluates a program. It decodes the serialized residual arena, tree-walks the Core forms under a caller-lent environment, and produces a value: literals, `Var`, `Let` including the recursive form, `If`, `Lambda`, and `Apply` with closures that capture lexically. What it cannot do is tell anyone the answer. `vehje_runtime_execute` returns a result code and discards the value, so the only evidence a program computed anything is a Zig test asserting on an internal union. A runtime whose results cannot leave it is not yet a runtime the host can use.

The design already says how a value should leave. `vehje-runtime-abi` carries a `ValueArena` (fixed-width value-node records, a flat child pool, a self-contained byte blob, a region table) and a `VehjeSink` (the reserve-then-commit protocol named as the one transfer contract for both boundaries, an iteratee whose backpressure is inherent, with host-lent backing so the runtime holds no output memory after a call). Those are the right mechanisms and this round does not relitigate them. What is missing is one level below: the `ValueArena` types are Rust `#[repr(C)]` structs whose field widths are the platform's, and no byte layout is pinned. The residual solved exactly this problem by choosing fixed little-endian word records so the Zig side reads the same bytes on every target. The value arena needs the same treatment before any Zig code can write one.

The second thing this round corrects is a design document that no longer describes its subject. `runtime-zig/DESIGN.md.tmpl` still specifies the Phase 6 skeleton, three exported stubs that return an error code, and casts the Zig side as a compile-time macro interpreter with a scratch-variable evaluator and a token-stream emitter. That was a plausible role in an earlier architecture. It is not the settled one: the compile side reduces every build-environment effect away in Rust, and the Zig side executes the residual against the runtime environment. Leaving the document as it stands is the failure the second-direction audit named, where a finished-looking doc describes something the source is not, so a reader trusts the wrong thing.

## Current state

`mock/runtime-zig/src/runtime.zig` decodes the tier-0 wire image (a seven-word header, seven-word node records, the flat child pool, the string blob, little-endian throughout) and evaluates it. Environments are a caller-lent bump arena of linked bindings, so capturing one costs recording an index and a closure that outlives its defining scope still reads what it captured. Nine Zig tests cover the value forms, lexical capture, currying, recursion, and the refusal paths (unbound variable, non-callable application, corrupt index, exhausted environment arena). `vehje_runtime_execute` evaluates and then discards the value, returning only `VEHJE_RESULT_OK` or `VEHJE_RESULT_ERR`, with a FIXME naming this gate.

`mock/crates/vehje-runtime-abi/src/value.rs` defines `ValueArena`, `ValueNode` (`tag`, `region`, `children`, `blob`), `ValueTag` (`Unit`, `Bool`, `Int`, `Str`, `Seq`, `Record`, `Outcome`), `ValueList`, `BlobSpan`, `Region`, `RegionId`, and `ValueRef`. Every one is a Rust type. `USize` is platform-width and `ValueTag` takes the C enum width, so the in-memory form is not a cross-language contract. `mock/crates/vehje-runtime-abi/src/wire/serialize.rs` is the precedent: it pins the residual to fixed little-endian words and documents the layout in its module header. There is no counterpart for values.

`mock/runtime-zig/DESIGN.md.tmpl` describes the Phase 6 stub skeleton and a compile-time macro-interpreter role, neither of which matches the shipped source or the settled architecture.

## Changes proposed

Pin the value-arena wire layout, mirroring the residual's proven choice rather than inventing a second convention. A value image is a header of fixed little-endian words (magic, version, node count, pool count, blob length, region count, root), then fixed-width value-node records, then the flat child-index pool, then the region table, then the byte blob. Records are fixed width so a reader indexes node `i` in constant time without scanning, and the whole image is position-independent and self-contained, which is what lets the wire form equal the in-process form. Depth-first, children-before-parents emission stays the ordering rule, so a parent records already-known child indices with no back-patching and a structural decode over an untrusted image is a single monotone index check.

Ship the Rust side of that contract in `vehje-runtime-abi`: the layout constants, a writer that serialises a `ValueArena` into a caller-provided buffer, and a reader that decodes an untrusted image back into typed value nodes with every span and index bounds-checked against the image. The reader is the half the host uses to read what the runtime produced, and the half that must never trust its input.

State plainly that a closure has no representation in the value arena. A closure names an environment inside one run of the runtime, so it cannot be a value the host holds after the call returns. Producing a closure as a program's final value is a refusal with a named reason, not a partially-written record. This is a real constraint of the design worth writing down rather than discovering later.

Correct `runtime-zig/DESIGN.md.tmpl` to describe the runtime as it is: the residual executor, its tier-0 tree-walk over the serialized arena, the value set it evaluates, the caller-lent environment model and why capture is by index, the refusal set, and the exported C ABI surface. Mark the parts that are intended rather than shipped with their status, per the assurance-verb discipline, and move the superseded macro-interpreter and scratch-variable role out of the scope section. Record the produced-value crossing as the next gate, with this round's byte contract as its specification.

## Not in this round

The Zig writer that serialises a produced value into the pinned layout and streams it through a `VehjeSink`, the sink parameter on `vehje_runtime_execute`, and the `vehje-runtime-driver` embedding that dlopens the artifact and reads the value back. Each is its own round, and each is unblocked by the contract this round pins. Family operations and host calls (how `Raw` reaches a consumer-provided handler, which is how arithmetic and host services arrive) are a separate design question and a separate round; the framework owns no family, so that seam is dispatch on this side and handlers on the consumer's.
