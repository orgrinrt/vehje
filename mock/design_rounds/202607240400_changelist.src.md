## Expert review outcome (pr-reviewer-senior, MERGE AFTER FIXES)

Verdict MERGE AFTER FIXES; the core soundness fixes verified correct (target-axis mint unforgeable, `Graded`
unminta ble outside `check` and tied to the checked program, let-rec correct in both walks, hash regression
tests strict). Two findings, both addressed:
- **`Arena::list` overflow (fixed).** The clamp computed `start + len` before bounding it, so a malformed
  `NodeList` with a huge start/len (the exact case the clamp guards) would overflow and panic in debug.
  Switched to `saturating_add`.
- **`hash_of` interner-handle stability (scoped, not silently overclaimed).** The leaf fold mixes a name's
  interner HANDLE, which is stable within one interner but not across interners, so `hash_of` is sound for
  within-compilation hash-consing (its only current consumer, `vehje-lower::Cse::hash`, itself a stub) but is
  not interner-stable. Confirmed `vehje-fixpoint`'s cross-artifact dedup keys on a separate byte-image
  `xxhash3_64` (`incr.rs:77`), not on `hash_of`, so the system's cross-artifact soundness does not depend on
  this fold. Narrowed `hash_of`'s module doc to within-interner distinctness and added a FIXME (tracked #29)
  noting that a cross-interner consumer would need the interned content folded (threading the interner), which
  is premature now (no interner is wired through the pipeline at M-level and the cross-artifact hash-cons
  consumer does not exist). Threading the interner into `hash_of` now was judged premature complexity for an
  unbuilt consumer, so the reviewer's "at minimum FIXME" path was taken.
