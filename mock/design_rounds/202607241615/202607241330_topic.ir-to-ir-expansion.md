# Macro expansion and const fold are IR to IR passes, iterated to a fixpoint

## The correction

A prior audit concluded macro expansion (`MacroExpand`), const fold over primitives,
and A-normal-form (`Anf`) were deferred because the redirecting `Rewrite` side-table
cannot create nodes, and creating nodes was framed as needing an undesigned
"mutable-arena rewrite path" that a no-alloc crate "should not want". op corrected the
framing: that vehicle is wrong.

The intended architecture: macro expansion and const fold do NOT mutate one arena in
place. They are **IR to IR** passes. Each reads the current IR and EMITS an expanded IR
into a fresh arena, the same fold-and-emit machinery the codegen already uses in the
output direction (`fold_core` folds IR to bytes; an expansion pass folds IR to IR). This
runs over **several runs**: expand produces an expanded IR, which feeds back in and is
expanded again, iterated to a fixpoint (no further change). Only the stable expanded IR
then feeds the intended pipe (resolve/check, the cheap subset, inclusion, emit).

Two IR-production directions name the shape: **input to IR** is the grammar (a consumer
front-end lowering source to IR); **output to IR** is expansion (a pass emitting IR).
Both build into a caller-lent arena via `Builder`, so both are fully no-alloc: the caller
provides the input arena and the output arena, and the pass never allocates. The premise
that "a pass that inserted nodes would need write access a no-alloc crate should not want"
was wrong: you do not mutate the input arena, you build a new one.

## Decision (op)

1. `MacroExpand` and const fold are IR-to-IR emit passes, not in-place redirects. Each
   folds an input arena and emits an expanded IR into a fresh output arena through
   `Builder`.
2. The passes iterate to a fixpoint: run expansion, and if it changed the IR, run it
   again on its own output, until a run produces no change. That fixpoint is the
   "several runs" that produce the expanded IR fed to the pipeline.
3. Core const fold (an `If` whose condition folds to a literal bool emits only the taken
   branch; a Core primitive over literal operands emits the folded literal) needs no
   consumer family and is built now.
4. Family macro operations expand through a family hook, `FamilyExpand`, parallel to the
   existing `FamilyResolve` / `FamilyCheck`: `expand_raw(family, payload, in, &mut Builder)
   -> Maybe<NodeRef>`, returning the expansion root when the Raw node is a macro, or
   `Isnt` to pass the Raw through unchanged. The default hook expands nothing (Core-only
   works; a consumer's family plugs its macros in). The Core mechanism (fold, emit,
   iterate to fixpoint) is built now; the family SEMANTICS arrive with a consumer, through
   the hook.
5. This supersedes `DEEPDIVE_LOWERING`'s "mutable-arena rewrite path" / "unconditional
   no-op is honest" framing for `MacroExpand` and const fold. The redirecting `Rewrite`
   stays valid for the annotate-in-place passes it already serves (`Cse` sharing); the
   IR-to-IR emit path is the distinct mechanism for the node-producing passes.
6. `Anf` follows the same IR-to-IR emit shape (hoist each non-trivial subexpression into a
   fresh `Let` while emitting the new arena). It is in scope for the mechanism but the Core
   const-fold and the family-macro hook are the load-bearing pieces op named; `Anf` lands
   on the same path.

## Not in one run

The implementation itself is iterative (the fixpoint), and the work is sequenced across
commits: the IR-to-IR fold + Core const fold first, then the `FamilyExpand` hook + fixpoint
driver, then the pipeline wiring that feeds the stable expanded IR to check/lower/emit.
