# Topic: the value arena's state label is stale

**Date:** 2026-07-25
**Phase:** TOPIC
**Scope:** `runtime-zig` documentation only.

The value-arena section carries `State: intended`. It was accurate when the doc changelist that introduced it
locked, because the source had not been written yet and the round deliberately locked the design before the
implementation. It is no longer accurate: the arena, its constructors, the tree writer, the reader, and the
compound marshalling all shipped in the same round, and `Project` reads records out of it in the round after.

This is a one-word correction, and it gets its own round rather than riding along inside a larger one because
the assurance verbs are load-bearing. The whole point of labelling every claim `proven`, `demonstrated`,
`measured`, or `intended` is that a reader can tell what exists from what is designed. A section that reads
`intended` while its code is shipped erodes that in the direction that matters least visibly and costs most:
it teaches a reader that the labels are decorative. The second-direction audit found nine of these at once, and
the discipline that came out of it was to fix them as they appear rather than let them accumulate into another
audit.

The correction is `intended` to `shipped`, plus the two sentences inside the section that describe the update
path in the future tense, which should say what the code does and name the uniqueness bit as the part that is
genuinely still owed. That distinction is the one worth preserving: the arena is shipped, the reuse verdict it
is shaped to read is not.
