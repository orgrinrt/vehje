# Current state

`Vec<T>` / `HashMap<K, V>` occurrences across seven clause phase
crates total 25 sites. Six are return types of public functions
and trait methods; five are public struct fields; one is a
parameter; three are local variables or test-only.

The trait home for sink-shaped replacements is
`hilavitkutin-api`, which already ships `DiagnosticSink<E>` (as a
blanket alias over `Push<E> + Len`) and `ByteEmitter` (over
`Push<u8> + BulkPush<u8>`). Both are trait-alias shims suitable
for `impl DiagnosticSink<Diagnostic>` consumer bounds.
`hilavitkutin-api` is declared in `mock/Cargo.toml`
`[workspace.dependencies]` but no clause crate depends on it
yet. This round adds the direct dep where needed.

The no-bare-vec lint is currently silenced at three sites via
`lint:allow(bare_collection) tracked: #73`. After this round
every such directive is removed from the affected sites.

# Changes proposed

## Dependency addition

For each clause crate that takes a `DiagnosticSink` or
`ByteEmitter` parameter after this round, add
`hilavitkutin-api.workspace = true` under `[dependencies]`. The
direct-dep pattern matches how notko is wired in the #73.1
slice.

## Sink-shaped retrofit — validators

`clause-typecheck::Validator::validate` trait method and all ten
validator struct impls (`Strict1..7`, `Coherence`, `OrphanRule`,
`BindTargetShape`) change signature from

```
fn validate(&self, ctx: &ValidatorCtx) -> Vec<Diagnostic>
```

to

```
fn validate(&self, ctx: &ValidatorCtx, sink: &mut impl DiagnosticSink<Diagnostic>)
```

`ValidatorRegistry::run_all` and the crate-level `typecheck`
entry propagate the same change: they accept a sink instead of
returning a vec.

## Sink-shaped retrofit — parser

`clause-syntax::parse` moves from

```
pub fn parse(tokens: &[Token]) -> Outcome<Ast, Vec<SyntaxError>>
```

to

```
pub fn parse(
    tokens: &[Token],
    errors: &mut impl DiagnosticSink<SyntaxError>,
) -> Outcome<Ast, ()>
```

The `Outcome` return shell stays for the non-recoverable path
(an AST must exist even with errors; the R4 BACKLOG already
describes this pattern). `Parser::parse` follows the same
retrofit.

## Sink-shaped retrofit — codegen

`clause-codegen::CodegenArtifact` drops its `bytes: Vec<u8>` and
`diagnostics: Vec<Diagnostic>` fields. The struct becomes a thin
tag carrying only `kind: ArtifactKind` and whatever per-target
metadata needs to be typed at that level. Callers of `emit`
provide sinks:

```
pub fn emit(
    resolved: &Resolved,
    target_name: &str,
    bytes: &mut impl ByteEmitter,
    diagnostics: &mut impl DiagnosticSink<Diagnostic>,
) -> Outcome<CodegenArtifact, CodegenError>
```

`CodegenTarget::emit` (the trait method on native / jomini)
changes in lockstep. Per-target internal `emit_for` helpers do
the same.

## Sink-shaped retrofit — runtime driver

`clause-runtime-driver::RuntimeHandle::execute` changes from

```
fn execute(&self, input: &[u8]) -> Outcome<Vec<u8>, DriverError>
```

to

```
fn execute(
    &self,
    input: &[u8],
    output: &mut impl ByteEmitter,
) -> Outcome<(), DriverError>
```

The `Vec<u8>` input parameter already passes through `&[u8]`
(ByteEmitter-free; callers allocate). No per-target driver impls
ship this round, so only the trait signature moves.

`clause-runtime-tests::test_runtime_roundtrip` follows the
change. The harness constructs a local `Vec<u8>` as the sink
implementation (fine; the harness crate is host-side and
test-only).

## lint:allow directive removal

Every `lint:allow(bare_collection) tracked: #73` directive in
source is removed as part of the retrofit. After the sweep the
`no-bare-vec` lint reports zero suppressions.

## Out of scope — deferred to #73.3

- `Scope::symbols: HashMap<String, Symbol>` — needs string
  interning; ties to `String → hilavitkutin_str::Str`.
- `ScopeTree::scopes: Vec<Scope>` — needs bounded-cap decision
  for how many scopes a program carries (const generic vs.
  runtime-growable vector).
- `Resolved::resolution: Vec<Maybe<Symbol>>` — same bounded-cap
  question, indexed by `NodeId`.
- `Manifest::dependencies: Vec<String>` — same interning story.
- `Resolved::new`'s `resolution: Vec<Maybe<Symbol>>` parameter —
  trivially `impl IntoIterator`, but ships with the Resolved
  structural change.

All of the above belong with the primitives+strings sweep
because their shape is tangled with `Str` and `Cap`.

# Notes on downstream effect

`clause-resolve::resolver::Resolver::resolve` and
`clause-codegen::emit` internally call `Vec::new()` to build
accumulators. Those internal locals are unaffected by this
sweep — they are caller-side implementations behind the public
sink contract. The lint only fires on public signatures and
source patterns, not on internal locals.

Empty-sink callers (tests, dry-run paths) can use
`hilavitkutin_api::NullSink`, which already has blanket `Push`
and `BulkPush` impls.
