# The consumer-facing public API, proven end to end

A framework-readiness assessment established that a consumer (a grammar plus a family plus a target) can
attach to the framework and produce a checked residual, and the family-extension dispatch seam closed the one
blocker it found. What remains is to prove that end to end with a working consumer rather than by analysis,
and to make the top `vehje` crate the single import a consumer needs, which its own role as "the public API
and composition crate" implies but the code does not yet deliver.

Today `vehje` re-exports only `Grammar`, `Target`, `Checked`, `CodegenError`, `run`, and `DebugTarget`. A
consumer that builds a program, defines a family, and declares a target must reach into `vehje-ir` (the
builder, the arena, the node forms, `Family`, `FamilyId`), `vehje-resolve` (`resolve_into`, `Resolution`,
`FamilyResolve`), `vehje-typecheck` (`check`, `GradeTable`, `Grade`, `FamilyCheck`), and `vehje-codegen`
(`check_for`, `TargetSets`, `fold_core`) directly. Importing from the sub-crates works, so this is ergonomics
rather than a blocker, but the composition crate should present the consumer surface as one coherent import,
matching its DESIGN.

## What lands this round

1. `vehje` re-exports the consumer-facing surface: the IR-building types (`Arena`, `Builder`, `Node`,
   `NodeRef`, `NodeList`, `Literal`, `Span`, `FamilyId`), the family machinery (`Family`, `Core`, the
   `AccessSet` set constructors `Cons`/`Empty` and the inclusion witnesses), the pass entries and their
   side-tables and hooks (`resolve`/`resolve_into`/`resolve_with`, `Resolution`, `FamilyResolve`,
   `CoreFamilies`, `check`/`check_with`, `GradeTable`, `Grade`, `Graded`, `FamilyCheck`), and the output
   surface (`TargetSets`, `check_for`, `fold_core`, the grade vocabulary a target reads). A consumer imports
   from `vehje` alone.

2. An integration test that is a minimal consumer, importing only from `vehje`: it defines a small family
   marker and a target declaring that family plus `Core`, builds a program that puts a Core sub-expression
   inside a family (`Raw`) node, runs the pipeline (resolve, graded check, mint the `Checked`, emit), and
   asserts the emitted output. The test is the experiment: a passing run is proof the framework hosts a
   consumer, and it doubles as the reference a real consumer (the mockspace DSL) follows.

## Not in scope

The re-export set is the consumer surface, not every internal type. The deferral boundary is unchanged: the
family payload encoding shapes, the scope-participating binding hook, the research-grade strata, the
runtime-coupled export, and the open `run` interleave all stand. This round proves and streamlines the
consumer attachment the framework already supports; it does not build a consumer (the mockspace DSL is the
next scope) nor implement any deferred mechanism.
