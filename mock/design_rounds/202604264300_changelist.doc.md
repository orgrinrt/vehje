## Purpose

Address three concrete review findings on the shipped front-end
(clause-ir / clause-lex / clause-syntax / clause-resolve /
clause-typecheck / clause-codegen) and record a fourth as a
BACKLOG note for the already-planned Symbol-interning round.

The front-end currently compiles, passes all its tests, and satisfies
the mockspace strict lint pipeline, but three small shape gaps make
the phase boundary less precise than it could be:

1. Diagnostics carry no indication of which compiler phase produced
   them. Once the driver merges `Vec<Diagnostic>` from lex, syntax,
   resolve, typecheck, and codegen into a single queue for rendering,
   there is no way to route or filter by producing phase; only the
   static `&'static str` message differentiates them, and messages
   will become non-unique as follow-up rounds add real per-rule
   messaging.
2. `parse()` returns `Result<Ast, SyntaxError>` — at most one error
   per parse. Real parsers want multi-error recovery so the user
   sees the whole syntax-error batch in one compile round-trip, not
   one error per re-run. This round widens the error surface to
   `Vec<SyntaxError>` so future recovery-mode parsing slots in
   without another signature churn.
3. `Parser.cursor: u32` is a raw index, typed identically to any
   other `u32` the parser module might hold. A `TokenCursor(u32)`
   newtype with `#[repr(transparent)]` costs nothing at runtime and
   gives the type system the handle it needs to prevent future
   bugs that confuse a token cursor with any other u32 counter
   (byte offset, span index, AST node id).

A fourth finding — `ResolveError` is not `Copy` because the two
variant payloads hold owned `String` — is noted as a BACKLOG entry
pointing at the already-planned Symbol-interning round, which will
fix it naturally.

## Deliverables this round

### Change 1 — `DiagPhase` discriminant on `Diagnostic`

In `clause-ir`:

- Add `pub enum DiagPhase { Lex, Syntax, Resolve, Typecheck, Codegen, Runtime }`.
  `#[repr(u8)]`, `#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]`.
- Add a `phase: DiagPhase` field to `Diagnostic`. `Diagnostic`
  remains `Copy` because `DiagPhase` is `Copy`.
- Update `Diagnostic::new` signature to take the phase as the first
  parameter: `pub const fn new(phase: DiagPhase, severity: Severity, span: Span, message: &'static str) -> Self`.
- Update `Diagnostic::error` to also take a phase as first parameter.
- Re-export `DiagPhase` at crate root (via `pub use` from the
  `diagnostic` module).

In each downstream phase crate, update the site(s) that construct
`Diagnostic`:

- `clause-lex`: the two `Diagnostic::new` call sites inside
  `lexer.rs` (`scan_one` for unclassifiable-byte diagnostics,
  `consume_leading_trivia` / `consume_trailing_trivia` for
  unterminated-block-comment diagnostics) pass `DiagPhase::Lex`.
- `clause-syntax`: `impl From<SyntaxError> for Diagnostic` passes
  `DiagPhase::Syntax`.
- `clause-resolve`: `impl From<ResolveError> for Diagnostic` passes
  `DiagPhase::Resolve`.
- `clause-typecheck`: no `From<X> for Diagnostic` impl exists today
  (the skeleton's validators all return empty `Vec<Diagnostic>`
  without producing any) — no update required this round. Noted
  in src CL.
- `clause-codegen`: no `From<X> for Diagnostic` impl exists today
  (the skeleton's `emit` returns `Err(CodegenError)`, not
  `Diagnostic`) — no update required this round. Noted in src CL.

Tests in `clause-ir/tests/diagnostic.rs` update to pass a
`DiagPhase` argument to `Diagnostic::new` / `Diagnostic::error` and
to populate the new field in the struct-literal test. Add one new
test verifying `DiagPhase` variants are distinct.

### Change 2 — Broader `parse()` return type in clause-syntax

Change `pub fn parse(tokens: &[Token]) -> Result<Ast, SyntaxError>`
to `pub fn parse(tokens: &[Token]) -> Result<Ast, Vec<SyntaxError>>`.

The existing happy path stays clean: success is still `Ok(Ast)`.
The error path upgrades to `Err(Vec<SyntaxError>)`; the skeleton
produces a single-element `Vec` today, and future multi-error
recovery extends the `Vec` without another signature change.

Justification for picking `Result<Ast, Vec<_>>` over the
`(Ast, Vec<_>)` alternative: less invasive for downstream consumers
that already match on `Result`, the Ok path stays the clean success
path, and the switch to `(Ast, Vec<_>)` can happen later if
partial-AST recovery actually needs it (the partial-AST API change
is additional orthogonal design work that does not need to block
this round).

`SyntaxError` inside `Vec` trips the `no-bare-vec` lint; add a
`// lint:allow(bare_collection)` suppression with a ≥21-word
justification on the return type. Pattern follows the
`clause-typecheck/src/lib.rs:71` precedent already shipping in-tree
(diagnostic return surface across every compiler phase crate).

Update three test files under `mock/crates/clause-syntax/tests/`:

- `empty_input.rs` — no error path, compiles as-is (Ok path).
- `single_literal.rs` — no error path, compiles as-is (Ok path).
- `unexpected_token.rs` — three tests `unwrap_err()` a
  `Vec<SyntaxError>`, then index `[0]` to reach the kind. Update
  accordingly.

Inside `Parser::parse`, the internal `Result<Ast, SyntaxError>`
stays as-is (the driver returns one at most today); the lib.rs
wrapper lifts the single-error `SyntaxError` into a one-element
`Vec`.

### Change 3 — `TokenCursor` newtype in clause-syntax

In `mock/crates/clause-syntax/src/parser.rs`:

- Add `pub struct TokenCursor(pub u32);` with
  `#[repr(transparent)]`, derives `Copy, Clone, Eq, PartialEq, Ord,
  PartialOrd, Hash, Debug, Default`.
- Add `impl TokenCursor { pub const fn new(idx: u32) -> Self { Self(idx) }
  pub const fn as_usize(self) -> usize { self.0 as usize }
  pub const fn advance(self) -> Self { Self(self.0 + 1) } }`.
- Change `Parser::cursor: u32` to `Parser::cursor: TokenCursor`.
- Update `peek`, `peek_at`, `bump`, `current_span` to use the
  newtype's `as_usize` / `advance` helpers.
- The field stays private; no public API change.

No new tests required — the existing parser tests exercise the
cursor through the public `parse()` entry and remain unchanged.

### Change 4 — BACKLOG note in clause-resolve

Append a new `## Front-end review notes` section to
`mock/crates/clause-resolve/BACKLOG.md.tmpl`:

- `ResolveError is not Copy`: the two variant payloads
  (`UnresolvedIdentifier.name`, `DuplicateDefinition.name`) hold
  owned `String`, which breaks the `E: Copy + Into<Diagnostic>`
  symmetry the rest of the front-end preserves (`SyntaxError` is
  `Copy`, `Diagnostic` is `Copy`). The fix lands naturally with
  the already-planned Symbol-interning round listed above in this
  BACKLOG: once `Symbol::name` is an `InternedSymbol` (or similar
  small Copy handle), the two `ResolveError` variants become
  `Copy` at no extra cost, and the whole phase crate retains its
  `Copy + Into<Diagnostic>` contract.
