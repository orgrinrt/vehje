## The short version

We were about to build a form-by-dispatch matrix that measures one wall-clock number per cell at a hidden
operating point (parse once, run sixteen passes). That measures the right cells over the wrong program,
at the wrong granularity, with one cell that cheats. The rearchitecture is: measure each composition as a
cost-model line rather than a point, over a set of designed program profiles rather than one random
sample, decomposed against two reference floors so the numbers are legible in absolute terms, across a
warm and a cold regime, as a path through the full pipeline of stages the corpus has benched in isolation,
with an adaptive selector judged against the theoretical best. And before any of that, fix a fairness bug
that two independent audits found in the variants already shipped, because the current threaded numbers
are confounded.

## Part 0: the fidelity gate (do this first, it is not optional)

Two of the three forks independently read the variant source line by line and found the same confound, by
the same method, with the same conclusion. That level of agreement makes it established, not one
reviewer's take.

### The bounds-check confound (a shipped headline is overstated)

The switch, function-table, if-chain, and predecoded-switch interpreters read operands and results through
**checked slice indexing** (`interp.rs:35,64`, `predecode.rs:67,73`). The two threaded interpreters read
them through **unchecked raw-pointer arithmetic** (`interp_threaded.rs:67,50`, `predecode.rs:203-204,202`:
seven unchecked sites in the wire-threaded module, fifteen in the flat-threaded path). So the threaded
cells elide two bounds checks per node (a compare plus a predictable branch each) that every other cell
pays. Operand and result access is a large share of per-node cost, so the threaded-versus-switch delta
confounds preserve-none dispatch with bounds-check elision.

This is not a property of threaded dispatch. It is an artefact of how the variants were written (the
preserve-none handlers thread a raw `*mut u64`, and the raw pointer silently dropped the bounds check
along with the lifetime). The magnitude aligns with the findings: the elided checks matter most in the
L1-resident small-n regime where a predictable branch is a real fraction of a few-nanosecond per-node
cost, which is exactly where A1 had threaded winning by ~2% and A3 had flat-threaded winning by
1.24-1.49x; at large n the checks hide under memory latency, which is exactly where A3 had flat-threaded
merely tying plain flat. **A1's small-n threaded win and A3's "flat-threaded best-or-tied everywhere" are
overstated by an unquantified amount and must be re-run before any "threaded wins" claim is trusted.** A2
(predecode flat beats wire, 10-26%) is clean: both its variants are switch and both are bounds-checked.

The fix is one shared `#[inline(always)]` operand-load and result-store primitive used identically by
every dispatch shape, so the only thing the dispatch axis varies is dispatch. The honest normalization is
**unchecked everywhere**: the program is validated once at load (children-before-parents, every operand an
earlier index, asserted by `is_well_formed` and the untrusted-load verifier), so post-validation every
access is provably in range and the bounds check is pure overhead a real runtime elides anyway. Keep
checked-versus-unchecked as its own axis only if the cost of validation-elided checks is itself
interesting.

### The other fidelity faults

- **The if-chain is a strawman as written.** `interpret_ifchain` (`interp.rs:155+`) orders its cascade by
  ascending opcode, so hot binary ops sit behind cold comparisons. The match-lowering finding it exists to
  test was about a *frequency-ordered* chain. As written, an "if-chain loses" result would be an ordering
  artefact. Frequency-order it (and state the ordering is part of the strategy), or carry both orders as a
  sub-axis.
- **Setup asymmetry favours flat.** Every cell excludes its setup from the timed region, but the flat
  forms exclude parse plus predecode while the wire forms exclude only parse. At a fixed iteration count
  the flat forms move strictly more work out of the measurement, a per-variant free ride a run-once program
  would never grant. There is also a likely form-side check asymmetry (the flat loop's node index may be
  provably in range and its checks elided, while the wire loop's `from_le_bytes`-derived indices are harder
  to prove). The cost-model line fit (Part 1) dissolves the setup asymmetry; the shared operand primitive
  fixes the check asymmetry. It must be verified that the A2 flat-over-wire margin survives normalization
  (it should: footprint and wire-arithmetic differences are real and independent of checking).
- **Labels unconfirmed at the ISA level.** "switch = jump table" and "threaded = elides callee-saved
  spills" are assumed, not verified. `rust_preserve_none_cc` is an incomplete nightly feature; if it
  silently fell back to the standard ABI on some handler, the threaded cell measures something that is not
  preserve-none. Confirm with `cargo-show-asm` or focused disassembly that switch emits a jump table,
  fntable keeps its indirect `blr` (already verified to survive LTO), and a threaded handler shows no
  `stp`/`ldp` of x19-x28 around the dispatch. Record any cell that fails to match its label as mislabelled
  rather than shipping it.
- **Isolation is clean (stated affirmatively).** Each variant is its own `cdylib` with `lto = "fat"` and
  `codegen-units = 1`, statically linking its own carrier copy, dlopened in a separate subprocess; the
  program crosses FFI as bytes generated at runtime in a `OnceLock`, so the optimizer cannot see it and
  cannot partial-evaluate the interpreter over it; every variant generates from the same fixed seed, so all
  interpret the byte-identical program. Cross-variant isolation, program opacity, and the shared-program
  property are sound as built. The faults are in the variant bodies and the framing, not the harness.

The gate: unify operand access into one shared primitive, frequency-order the if-chain, move the checksum
out of the hot loop (Part 1), decouple the input seed from program size (Part 1), floor the timed region
(Part 1), ISA-confirm the labels, then re-run A1 and A3 and correct the beating-attempts log. Only then do
the composition cells measure their strategy and nothing else. A matrix built on variants that each cheat
differently measures the cheats, not the compositions.

## Part 1: the measurement backbone (measure a line, not a point)

Model every composition's cost as `total(k) = S + k * I`: a one-time setup cost `S` to get from wire bytes
to a dispatch-ready form, a per-evaluation cost `I` for one interpretation pass, and `k` evaluations.
Every composition is a line in `(k, time)`. Measure `S` and `I` by sweeping `k` over a geometric ladder
(1, 2, 4, ... 128) and fitting by least squares with a reported R^2. A clean fit means the two numbers
fully describe the composition; a poor fit means a cache tier was crossed or setup is not amortising, and
that non-linearity is itself a finding rather than noise.

This subsumes the whole predecode-honesty question analytically: predecode pays exactly when
`k > S_predecode / (I_wire - I_flat)`. "Flat wins at sixteen iterations" becomes "flat pays for itself
after N evaluations, so it wins for per-frame and per-entity work and loses for run-once scripts," which is
the honest claim A2's caveat was gesturing at. This is the answer to op's Q1 (iteration count): it is not
an added axis, it is the central measurement.

### Attribution: two reference floors

A slope on its own says a composition is faster, not why. Carry two reference cells that bracket every
real composition:

- **Native ceiling** (the existing shape-specialised native loop): the irreducible compute-and-memory
  floor, no dispatch.
- **Null-dispatch interpreter**: the same operand loads, result store, and checksum, but every node
  executed as one fixed op with no opcode dispatch. Its slope is the interpreter's memory-and-bookkeeping
  structure with dispatch removed.

Every measured slope then decomposes into native-compute + interpretation-structure + dispatch, with
dispatch isolated exactly. This is what makes a 2% end-to-end difference legible as, say, a 30% dispatch
difference diluted by a large shared memory term. Without it the matrix numbers are uninterpretable in
absolute terms.

### Measurement-fidelity fixes (carrier-wide)

- **Checksum out of the hot loop.** The per-node `rotate_left(7) ^ v` is a keep-alive and cross-validation
  device, not interpretation, and it dilutes the dispatch signal uniformly. Fold one checksum over the
  whole results array after the pass: keep-alive preserved (the checksum escapes through FFI),
  cross-validation strengthened (a full fold is a stricter witness than a rolling hash that can alias).
  This shifts the A1-A3 absolute numbers by design; the relative conclusions must be re-established on the
  clean signal.
- **Decouple the input seed from program size.** The current `input[k % N] ^ k` ties the input index to
  node count and folds the loop counter into the value. Use a fixed pre-generated seed array indexed by the
  eval counter alone, identical across every size and composition.
- **Floor the timed region.** At 24 MHz the CNTVCT quantum is ~42 ns; the smallest programs run in a
  couple of microseconds. Size the internal repeat count so every timed region runs at least ~10 us. Measure
  `S` directly in its own rebuild-each-repeat region and cross-check it against the regression intercept; a
  disagreement flags a broken assumption.

### Two regimes, unified as a warmup curve

The single-program-many-times loop measures the warm steady state (the per-frame, per-entity regime),
which is exactly the regime that most favours the shapes the arc has promoted. A runtime also loads many
distinct small programs and runs each a few times, cold at every boundary (the load-many-scripts regime),
which punishes the many-indirect-branch-site shapes. The dispatch ranking plausibly inverts between them,
and that inversion maps onto the runtime's two real usage patterns.

Measure both. The strongest framing (from 1530) unifies them into one warmup-curve fit
`total(k) = S + sum_{j<k} I(j)` where the per-evaluation cost `I(j)` decays from a cold first-eval slope
to a warm asymptote, extracting the cold slope, the warm slope, AND the warmup length from one richer
k-sweep. The warmup length is exactly the "how many evaluations until a program is hot" quantity a tiering
runtime needs, measured directly rather than inferred. The cold-many batch regime becomes the cross-check
that the curve's cold end agrees.

## Part 2: the program is the dominant variable (designed profiles, not one sample)

Every dispatch-shape difference is mechanistically a difference in how a shape handles the opcode stream's
predictability; every record-form difference is a difference in working-set size and operand-load
locality. `generate(default_point())` fixes all of these at one unknown coordinate and hands the matrix a
single sample of program-space. The v4-versus-v17 result already showed the crossovers MOVE with a program
property. So one program measures one coordinate and calls it the answer. This is op's Q2, and the answer
is: the program properties ARE the axes.

Use a set of designed profiles, each a fixed `GenParams` preset stressing one mechanism (from 1530):

- **P_madd** (single-motif, native-anchored): the clean native-ceiling calibration point and the
  maximally-predictable dispatch case.
- **P_tight** (predictable + local): high `op_correlation`, small `locality_window`. The hot-loop-body
  case; predicts threaded/ifchain win on dispatch, flat wins on locality.
- **P_scatter** (unpredictable + cache-hostile): zero correlation, uniform locality, full vocab. The
  adversarial case; predicts fntable/switch single-site prediction win, threaded punished.
- **P_wideselect** (arity-heavy): weights concentrated on ternary SELECT plus binary ops; stresses record
  width and the spill path.
- **P_leaf** (decode-bound): weights heavy on CONST/INPUT; dispatch-light, shows where form dominates.
- **P_real** (balanced): the current `default_point`, the "typical program" reference and the matrix
  centre.

This needs one minimal, orthogonal generator upgrade: replace uniform op selection with an
`op_weights: [u16; op::COUNT]` field on `GenParams` (opcodes sampled proportional to weight, with
`op_correlation` still governing run-length on top). This makes arity mix, leaf fraction, and heavy-op
fraction all controllable by reweighting the vocabulary, and subsumes `op_vocab`. No IR change.

Reporting is native-normalized per profile: every cell reported as a multiple of that profile's native
ceiling, turning relative interpreter trivia into the interpret-versus-tier-up decision the runtime
actually faces.

The cross-validation contract extends: within a profile all cells agree on the checksum; across profiles
the checksums differ (asserted), proving the profiles are genuinely distinct programs.

## Part 3: the matrix as a staged pipeline (compose everything we have benched)

The form-by-dispatch pair is a small corner of what the corpus measured. The shared IR program flows
through a pipeline, and nearly every isolated bench was measuring one stage with the others pinned. The
maximal meaningful matrix unpins every stage; a composition is one strategy per stage, end to end, over
the identical program (from 1615).

The eight stages, with the isolated bench each came from:

1. **optimize** (none / CSE / bounded eqsat / CSE+eqsat) from `cheap_lowering` + `egraph-saturation`. The
   highest-leverage axis nobody composed: a pre-pass that shrinks node count changes the working set every
   downstream stage pays.
2. **intern** (none / hashed / sharded) from `interner_intern`.
3. **record form** (wire12/16/20/24/32 / flat16) from `carrier_record_width` + `carrier_predecode`.
4. **value representation** (static / tagged / nanbox) from `carrier_valrepr`. Does NOT compose today
   (valrepr runs a separate mixed-type mini-IR); gated on the IR type-tag extension (Part 5).
5. **operand access** (inline / pool-spill / interned-ref) from `project_field_access`.
6. **dispatch** (switch / fntable / threaded / ifchain / bittree / perfecthash) from `carrier_dispatch` +
   the match-lowering suite. This is op's Q4: branch strategies enter as dispatch shapes over the shared
   opcode; the synthetic `ab_*` branch benches stay a separate workload (they do not run the IR program).
7. **fusion** (none / pairwise superinstructions) from `iter_fusion`.
8. **output building** (overwrite / cow / reuse) from `interp_output_building` + `iter_output_reuse`.

Stages 1-3 are the build half (they set `S`); 4-8 are the run half (they set `I`). Genuinely separate
workloads (reach, retract, incr, thermo, arena-locality, value-arena) stay their own benches; `cfg` is a
second IR (control-flow-block machine) worth its own parallel matrix.

The full logical cross is ~70k cells (~20k coherent after removing incoherent ones like flat-form +
pool-spill).

**Initially suggested, but superseded and ignored:** the tiered evidence-commitment below (build/run a
Tier-0 spine, commit evidence outward tier by tier, run the rest on demand) was the original resolution of
"maximal but tractable." Op superseded it: ALL coherent cells are built and, after the expert review, run.
The tier labels are retained ONLY as an implementation order-of-operations (some code must exist before
other code can use it), never as a scope gate, an evidence subset, or a stopping point. Read the tier list
below as build order, not as what gets measured.

Do not shrink the axis set; make the matrix
**generatable on demand and (per the superseding directive) run in full, in the tier order below purely as
build sequence** from one axis catalogue:

- **Tier 0, the spine:** the full record-form x dispatch grid (6 x 6 = 36) at the canonical shape, hot
  regime, everything else canonical. Baseline cell = wire24 + switch = the shipped default. This subsumes
  and replaces the original two-axis plan.
- **Tier 1, single-axis slices:** each remaining stage swept alone through the spine with the others pinned
  canonical (a few hundred cells).
- **Tier 2, targeted pairwise:** the interactions predicted strong (optimize x form, fusion x dispatch,
  value-rep x dispatch).
- **Tier 3, full coherent cross:** generated and run only where Tier 2 reveals a non-additive interaction,
  or on demand.

Maximal in definition, meaningful in what machine time it spends. The canonical centre is the shipped
default so every slice reads as a delta from what ships.

### Per-stage sub-timing

The highest-upside timing idea: measure, per composition run, both the end-to-end time AND a named
sub-timing per stage that executes in that path, on one warm state. That decomposition turns a 2%
end-to-end difference into "the dispatch stage is 30% cheaper but it is one fifth of the run." This needs
one upstream mockspace-bench-harness feature: a `timed_stage!("name") { .. }` form recording each
sub-region's CNTVCT delta into a per-stage slot, and a per-(variant, size, stage) CSV schema. Build-half
stages (decode, optimize, intern) get direct sub-timing; run-half stages (dispatch, operand access,
output) are fused in the hot loop and would be destroyed by an in-loop barrier, so they get differential
attribution against the reference floors (the null-dispatch floor IS the run-half dispatch sub-timing). So
the two-floor decomposition and per-stage sub-timing are the same mechanism at different granularity. The
build-half direct sub-timing is the only piece that needs the upstream change; the run-half floor
differencing works today, so start there and add the harness feature for build-half detail.

## Part 4: the champions (does adaptive selection beat every fixed shape?)

Three, in increasing sophistication; the relationships are the results. This is op's Q3, made honest.

- **Oracle envelope:** at each `(profile, n, k, regime)` point, the fastest cell actually measured. The
  theoretical best the space contains; the target every real selector is judged against.
- **Whole-program cost-model selector:** a runtime selector holding a small `(S, I)` calibration table,
  computing predicted `total(k)` at the actual `(node_count, expected_k, sampled program features)`,
  picking the cheapest, paying the branch and lookup. Selection is a RUNTIME branch on measured values, not
  a compile-time const (the original const-`N` gate was not a selection a runtime can make). Measured as a
  real cell, judged against the envelope with a regret curve (how much adaptivity leaves on the table).
- **Per-stage + per-region selector (the payoff):** two orthogonal adaptivities fused. Per-stage (1615)
  picks each pipeline stage independently from the calibration table, composing a path the fixed matrix
  never enumerated (tests whether the stages are independent). Per-region (1530) segments the program by a
  cheap forward pass and dispatches each region with the locally-best shape (tests whether intra-program
  adaptivity beats whole-program choice). The maximal champion does both: per-stage strategy with the
  dispatch stage additionally per-region. If it beats the whole-program selector on the mixed profiles,
  that is the genuinely novel result and the "far beyond what these can" op is chasing.

All selector measurement runs inside the timed region (or is amortised like predecode and that
amortisation is swept), so the overhead is paid honestly.

## Part 5: make the carrier final-like, as artifact-removal not runtime-mimicry

Even a perfectly fair comparison between naive variants of a toy interpreter yields conclusions about the
toy. Three strawman properties of the current carrier bury real approaches' merits and should be removed,
each promoted to a measured axis with the naive form kept as a labelled reference cell:

- **Store-every-node-forever → liveness slot allocation.** `results[i] = v` for every node, kept the whole
  pass, makes the working set the entire program (node_count u64 slots); every form/cache crossover we have
  measured is over that whole array. A real runtime allocates values into a reused arena sized to the
  liveness width (a small constant for typical DAGs), via a cheap backward last-use pass at predecode. This
  is the highest-leverage realism fix because it attacks the exact term that dominated the large-program
  regime (A2/A3 were memory-bound at large n because of this array). Without it the form axis measures a
  fiction.
- **1:1 predecode → optimize-on-load.** A real runtime folds constants, does CSE, eliminates dead nodes,
  and fuses superinstructions while it predecodes, so the flat form it runs is smaller than the source. The
  optimize stage belongs inside the predecode path for the final-like cells. Its predecode cost is an
  honest part of `S`; the line fit captures the amortisation.
- **Rolling-hash keep-alive → real output sink.** The post-pass checksum (Part 1) already removes the
  per-node hash; the final-like step is that the "output" is the live-out values written through the
  output-building stage into the FFI region, which is real work.

Two deeper IR changes, higher priority than they look:

- **Control flow.** The IR is straight-line (a DAG in index order, no branches or loops). This structurally
  understates the dispatch axis: threaded dispatch's whole advantage is that the indirect branch at each
  handler tail learns the local opcode-successor distribution, which is largest in hot loop bodies where a
  handler sequence repeats. A linear stream never exercises it, so the threaded numbers are understated in
  the direction that matters for the runtime. Add basic blocks and terminators (branch, loop back-edge,
  call); this subsumes the separate `cfg` bench into the shared IR.
- **Typed values.** The u64-only model is why value representation cannot compose. A per-node result type
  (at least int and float) makes static/tagged/nanbox interpret the one shared program and cross-validate.
  Off by default on the static canonical path so the spine stays comparable to the A1-A3 baselines up to
  the checksum move.

### The posture: a design-space explorer, not a shipped-shape validator

This is the reconciliation of the one tension between the forks, and it is the correct frame. A bench does
not conform to the already-chosen runtime shape to validate it; it measures every shape on its merits, as
equals, including shapes the runtime does not use and might be better off adopting. Concretely:

- **No privileged baseline.** wire24 + switch stays only as a fixed normalization anchor that makes tables
  readable, explicitly NOT "the default" or "the thing to beat." Every cell is judged against native and
  against every other cell on merit; the oracle envelope is the best measured shape regardless of whether
  the runtime would pick it. (Do not pre-decide that predecode is "the baseline" because a real runtime
  predecodes; that pre-decides an answer the measurement should produce.)
- **The fidelity fixes stay, for the honest reason:** each removes an artifact that buries some approach's
  true merit (store-every-node buries storage-reuse shapes; straight-line buries the loop regime; mixed
  operand access measures something other than dispatch). Keep store-every-node and wire-decode-per-node as
  real measured cells, not just worst-case references.
- **The tier mapping is a reporting lens, offered not imposed:** reading the form axis as cold-residual
  (the serialized wire residual crossing the ABI) versus baseline-arena (the predecoded form the runtime
  builds on load) versus native is useful for the tiering decision, applied after the fact, not a
  constraint on what is measured.

### Beyond-runtime shapes worth measuring (the most valuable results tell the runtime to do something new)

Each a first-class cell allowed to win:

- **Vertical, data-parallel (SoA) interpretation:** interpret one program over many inputs at once, SIMD
  across inputs, one dispatch amortised over a vector of values. This is the standout idea in any of the
  three forks: it maps directly onto vehje's real per-record evaluation (the same residual run over a
  column of records), so it could dominate exactly the workload the runtime cares about most while being
  nowhere in the current tier plan. Its own axis (scalar vs vertical), potentially the single largest
  result the matrix can produce.
- **Copy-and-patch stencil execution** (the weval / Cranelift lineage): the cheap near-native tier between
  interpreter and full native; answers whether jumping straight from baseline interpreter to full native
  skips a tier that is most of the win for a fraction of the cost.
- **Computed-goto / token-threading in the Zig cdylib:** Rust cannot express label-as-value computed goto;
  Zig can, and the cross-language cdylib isolation already in place drops a Zig dispatch cell into the same
  matrix on the same program bytes. Also closes the "not expressible in Rust" saga from the other side.
- **Trace / superblock dispatch** (dispatch per hot straight-line run) and **alternative residual
  encodings** (register vs stack bytecode vs the SSA value-graph the carrier uses now).

The materialized "strongest interpreter" cell (optimized-flat + slot-allocated + fused +
direct-threaded/native) is the right strong reference cell (its gap to native is the usable tiering
number), but it is not the frame: a beyond-runtime shape like vertical SIMD could beat it, and the matrix
must be able to show that. The oracle envelope is over everything measured.

## Part 6: make it a reusable framework, not per-bench scaffolding

This class of bench ("a composable implementation with a setup-plus-per-op cost model, measured across
program-property and cache-state axes, decomposed against floors, with an adaptive selector validated
against an oracle") deserves first-class harness support (from 1530). Five-plus primitives:

1. **Regression cells:** the bench declares "I am a cost-model cell"; the harness owns the geometric
   k-ladder, the >=10us duration-floor auto-calibration, the least-squares fit, and reports `(S, I, R^2)`.
2. **Floor decomposition as a service:** register the native and per-form null-dispatch floor cells once;
   the harness reports every slope as native + structure + dispatch automatically.
3. **Regime as an execution mode over pure cells:** make the cell a pure function (program bytes ->
   checksum); the harness drives it warm (one program, k evals) or cold (a batch of distinct programs), so
   the two regimes share one implementation and are provably the same code.
4. **Isolated cross-product codegen from a declarative axis spec:** declare the orthogonal
   axis-implementations once as pure pieces; the harness emits the isolated per-cell cdylibs for the
   requested tier, preserving the per-cell codegen isolation that prevents cross-composition contamination
   while removing the hand authoring.
5. **Per-stage sub-timing** (`timed_stage!`, from 1615) as a sixth primitive.
6. **Oracle envelope and selector-regret reporting as harness outputs.**

This turns the maximal matrix from hand-authored cells into declared-axes-in, decision-grade-surface-out,
reusable for any future staged bench.

## The one open decision for op (initially suggested, but superseded and ignored)

**Superseded, retained for the trail.** This section initially framed the beyond-runtime cells as an open
call for op (build now or defer). Op resolved it decisively: build ALL of it, beyond-runtime approaches
first-class and primary, nothing deferred. The reconciliation below (final-like as a labelled strong
reference, oracle envelope over everything) still holds; the "one open decision" framing does not. See the
two final sections.

The forks converged on everything except the endgame frame, and the difference is real:

- **1530's final-like convergence:** the endgame is one buildable optimal interpreter
  (predecoded-slot-allocated-fused-threaded/native); the oracle envelope becomes a buildable runtime and the
  strongest cell is that path.
- **The design-space-explorer posture** (op's own correction, adopted in 1615 and Part 5 here): do not
  privilege any shape; measure every approach on its merits; keep first-class room for beyond-runtime shapes
  that might beat the final-like path.

The recommended reconciliation (this topic's position): keep the naive shipped default at one end, the

## Discipline (carried, non-negotiable)

Every cell runs the identical `generate()` program per (profile, seed), differs only in memory form and
stage strategy, and folds the identical post-pass checksum; the harness cross-validates byte-exact before
trusting any timing, and asserts distinct profiles yield distinct checksums. Serial runs, >=3 per cell,
minimum for throughput and median-with-spread for regression points, no ranking inside the noise floor,
`(S, I, R^2)` reported, the ns-to-cycles-to-IPC sanity line per slope with out-of-range IPC flagged as an
artefact. Committed CSVs and the tracked `.bench_history` trail travel with every bench commit. A threaded
cell that fails to compile on some shape is recorded as toolchain-blocked, not worked around.

## Amendment: mandate, fairness gate, and the build-then-review process (2026-07-22, op-directed)

This amendment is binding and supersedes any softer framing above. Op reviewed the roadmap and set three
further mandates.

### 1. Every proposal is built. The beyond-runtime approaches are the primary, first-class subject.

All proposals in this topic are built, none deferred, none subset. The "approaches beyond the current
runtime" (vertical/SoA SIMD interpretation, copy-and-patch stencils, Zig computed-goto/token-threading,
trace/superblock dispatch, alternative residual encodings, allocation strategies) are the **primary,
first-class subject of the experiment**, not an appendix. The reason the whole apparatus exists is to find
a shape better than what the runtime plans today, so the shapes outside that plan get the most attention,
the most careful implementations, and full standing to win.

The existing theory (the final-like predecoded interpreter: optimized-flat + slot-allocated + fused +
direct-threaded, and native above it) is retained as **the baseline we map as the one we expect to win**.
That is its ONLY special status: it is the labelled expected-winner reference that every other composition
is compared against, so the numbers read as "how does approach X do against the shape we currently believe
is best." It gets **no other special treatment**: it is implemented to the same fidelity bar as everything
else, it is measured on the same cost-model line against the same floors, and if a beyond-runtime approach
beats it, that is the result and it is not explained away. Every composition, expected-winner and
challenger alike, gets a proper, sound, actually-representative implementation and path. No strawmen, no
naive stand-in for a shape a real runtime would ship in a better form (this is the "strongest opponent"
honesty rule applied to every cell, not just the ones we like).

### 2. The fairness gate: every cell double-checked sound and fair, down to the disassembly.

Before any bench is run, every composition is audited for accidental unfair advantage, at every level:

- **Access discipline is uniform.** Every dispatch shape reaches operands and stores results through the
  one shared `access` primitive (unchecked post-validation), so no cell elides a bounds check another
  pays. This is the confound both audits already found in the threaded cells; the same discipline extends
  to const loads, node loads, slot loads, and every future axis (a checked-vs-unchecked slip anywhere is
  the exact class of "obvious and embarrassing in hindsight" bug this gate exists to catch).
- **Setup exclusion is uniform or modelled.** No cell gets a larger free ride by excluding more work from
  the timed region than another. The `S + k*I` line fit is the structural fix (setup is measured, not
  hidden), and until a cell is expressed as a regression cell its excluded setup is documented and equal
  to its peers'.
- **Every dispatch label is confirmed at the ISA level, by disassembly.** switch actually emits a jump
  table; fntable keeps its indirect `blr` and LTO did not devirtualize it back to a branch; threaded
  actually elides the x19-x28 callee-saved spills under `rust_preserve_none_cc` and did not silently fall
  back to the standard ABI; bittree is a real balanced branch tree; perfecthash is a real hash-to-table;
  the Zig computed-goto is a real indirect-goto. A cell whose codegen does not match its label is
  relabelled or fixed, never shipped mislabelled, because a mislabelled cell poisons every comparison it
  is in. Disassembly evidence is recorded per cell.
- **No optimizer leakage.** The program stays opaque (runtime-generated bytes crossing FFI) so no cell
  partial-evaluates the interpreter over the program; cross-variant isolation stays airtight (per-cell
  cdylib, `lto=fat`, `codegen-units=1`, static carrier copy, subprocess dlopen); const-fold, DCE, and CSE
  are explicit stages measured on purpose, never accidental in one cell and not another.
- **Semantic equality is proven.** Every coherent cell folds the identical post-pass checksum on the
  identical program; a divergence fails the bench. Floors (native, null-dispatch) are exempt from the
  cross-check by design and carry their own checksum.
- **Any other asymmetry imaginable is hunted deliberately.** Allocation reuse that helps one form, a seed
  coupling that helps one size, an inlining boundary that helps one shape, a struct padding that changes
  one record's cache behaviour: the audit enumerates and checks these, because the failure mode is a slip
  of mind that silently boosts one composition, obvious only in hindsight.

### 3. Build the machinery fully, commit as we go, but DO NOT run any bench until experts review it.

The machinery (carrier, all cells, generators-turned-harness-features, the fairness audit evidence) is
built to completion and committed incrementally as it lands. It is then handed to an expert panel to review
the BUILT MACHINERY for soundness and fairness before a single timing run. We fix per their findings, and
only then run. No bench numbers are produced before that review. (Git commits proceed normally throughout;
"do not commit" in the earlier phrasing meant do not commit to running the benches, i.e. do not start the
timing runs, not do not git-commit.)

### 4. Everything currently in Python becomes a first-class upstream harness feature.

The `gen_carrier_*.py` generators (emit variant cdylib crates plus `bench.toml` sections from a declarative
spec) are ad-hoc scaffolding. Per the all-upstream mandate, that workflow becomes a first-class feature of
the mockspace bench harness: a declarative axis catalogue in, the isolated per-cell cdylib cross-product
and the bench/CSV wiring out, preserving per-cell codegen isolation while removing the hand-rolled Python.
This is the "isolated cross-product codegen from a declarative axis spec" primitive listed above, made the
actual authoring path so no bench hand-writes a generator again. **Before rebuilding any of this, read the
mockspace bench-harness docs and source to confirm what is already first-class** (a variant/axis/matrix
feature may already exist and simply not have been used); build upstream only what is genuinely missing,
and adopt what exists. The same applies to any other Python currently in the bench tree (normalisation,
findings generation, node-count probing): each becomes a harness capability or is confirmed already
supported, never re-implemented as a one-off script.
