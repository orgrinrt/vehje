## The mandate, restated in full

The mandate has five load-bearing parts, and every one of them is binding.

First, every proposal is built. Not a subset, not a tier-0, not a "v1 then later." The workspace anti-YAGNI
discipline is explicit that the full thing is built immediately and phasing is forbidden, and op directed the
same here in as many words: all of it, every form, every dispatch, every stage, every beyond-runtime approach,
every champion. A proposal that turned out to be a strawman on this IR (one that cannot be made representative)
is the only thing that is not built, and each such case is named with its reason, never quietly dropped.

Second, the approaches beyond the current runtime are the primary, first-class subject. Vertical SIMD,
copy-and-patch machine code, the Zig guaranteed-tail-call runtime, trace and superblock dispatch, alternative
residual encodings: these are not a follow-up step or an op's-call-on-timing afterthought. They are the point.
The existing final-like interpreter is the labelled baseline we expect to win, and it is a comparator for the
others, nothing more. It gets no privileged path, no special-cased optimization, no framing that anchors the
oracle envelope to it. Every composition is measured on its merits against it, and a beyond-runtime shape is
allowed to win.

Third, every composition gets a proper, sound, actually representative implementation and path. Not a
caricature that exists only to be beaten, not a shortcut that measures something other than the technique it
claims. If a cell cannot be made representative, it is not built, and the reason is recorded. A machine-code
cell emits real machine code; a Zig cell runs the real Zig dispatch on identical program bytes; a trace cell
records and runs a real trace with a real side-exit guard.

Fourth, every edge case, every dispatch detail, and the ISA lowering itself are double-checked to be sound and
fair, so that no composition is accidentally boosted over another by something as easy to miss and as
embarrassing in hindsight as a check-versus-no-check asymmetry. The fidelity gate is the concrete form of this:
every dispatch shape reaches operands and stores results through one shared unchecked primitive, so the only
thing the dispatch axis varies is dispatch, and the post-pass checksum is byte-identical to the old rolling
hash so cross-validation values are unchanged. Beyond the source-level gate, each dispatch label is confirmed
by disassembly: a jump table shows its indirect branch, a function-pointer table shows its surviving indirect
call, a tail-threaded handler shows its tail branch with zero callee-saved spills (proving the preserve-none
mechanism did not silently fall back to the standard ABI), and the machine-code and cross-language cells are
confirmed to compute the identical results the interpreters do. The audit is extended to every new dispatch
cell as it lands, not done once and assumed to hold.

Fifth, nothing is run until the machinery is reviewed. The build stays red where the design is not yet fully
realized, the cells are cross-validated by `cargo test` (correctness, not timing), and the whole apparatus is
handed to an expert panel before a single timing run. Their findings are addressed, and only then do the
benches run. Git commits proceed normally throughout; the "commit" in the arc's goal wording means committing
to the bench runs, which is exactly the thing gated on the review.

## What is built to the mandate (verified, cross-validated, fairness-audited)

The carrier composition machinery is complete. Every cell below is cross-validated by `cargo test` (byte-exact
against the switch interpreter or the appropriate oracle, across the six designed program profiles and many
seeds), and every dispatch cell is confirmed at the ISA level in
`mock/research/202607221230_fairness-audit-disassembly.md`.

The dispatch axis over the straight-line IR: switch (jump table), function-pointer table (surviving indirect
call), frequency-ordered if-chain and its ascending sub-axis, balanced bit-tree, preserve-none token threading
in three families (table, direct, flat), register/accumulator caching, and a per-form null-dispatch floor.

The dispatch axis over the control-flow VM (real loops and branches, which a straight-line DAG cannot exercise):
switch, function-pointer table, and preserve-none token threading across basic blocks, where a loop back-edge
is a tail call into an earlier flat index. The three control-flow cells were unified onto the shared unchecked
operand primitive as part of this work, closing the check-versus-no-check confound on the control-flow axis at
the source; the disassembly confirms the eight threaded-CFG handlers carry zero callee-saved spills and no ABI
fallback.

The beyond-runtime cells, the primary subject: vertical/SoA SIMD interpretation (one dispatch over W inputs,
cross-validated per lane); copy-and-patch native aarch64 codegen (a per-node instruction stencil concatenated
into one function run from MAP_JIT memory with the W^X and instruction-cache handling Apple Silicon requires,
byte-exact against the interpreter across every opcode stencil, declining rather than miscompiling above the
immediate-offset window); trace/superblock dispatch (the hot self-loop linearized into a guarded superblock,
cross-validated against the base control-flow interpreter on the full result-and-counts triple so the
superblock provably walks the same path); and the Zig cross-language cell (switch and guaranteed-tail-call
threading on identical wire bytes, the tail shape Rust needs a nightly feature to express, byte-exact against
Rust and confirmed at the ISA level to be true tail threading with no per-node call).

The value-representation axis (static, runtime-tagged, NaN-boxed, cross-validated to agree); the residual
encoding axis (the register/SSA default plus a stack-bytecode encoding); and the working-set stages (constant
folding with common-subexpression elimination and dead-code elimination, superinstruction fusion, liveness slot
allocation, and output-building in three sink-emission strategies), each cross-validated on the program's
live-out values because the node count changes. The program basis is six designed profiles, and the reference
floors are the native ceiling and the null-dispatch floor.

The named cells that are deliberately not built, with their reasons, so the absence is honest and not a gap:
perfect-hash dispatch degenerates to the function-pointer table on the dense contiguous opcode set and needs a
sparse-opcode design decision before it is representative; interned operands cannot win on a value-DAG where
operand tuples do not repeat, so building it would be a strawman (inline-versus-spill operand access is already
the record-layout axis); the multi-guard branchy trace and the machine-code cell above the immediate-offset
window are labelled refinements of cells that are built. Each of these is the same call already made for
perfect-hash: a non-representative cell is worse than a named absence.

## The upstream harness features, built to the "everything upstreamable goes upstream" directive

On the mockspace branch `feat/bench-harness-cost-model-and-matrix`, five features that were either Python
scripts or absent-but-wanted harness capabilities are now first-class, each with tests and the harness suite
green: the cost-model regression fit (`total = S + k*I` with the coefficient of determination, so a variant is
a fixed cost and a marginal cost rather than one opaque number); the declarative axis-matrix and variant-crate
generation that replaces the per-bench Python generators (cartesian axis expansion, per-axis feature union,
variant-crate scaffold, and bench-section emission, with the bench-specific `lib.rs` body staying a template);
the disassembly duplicate-check wired into the pre-run flow as a fairness guard against two variants that
compile to identical code; the reference-floor ratio column wired from the parsed-but-dead normalise mode; and
the auto duration-floor calibration, whose sound home is a `timed_calibrated!` macro in the variant (the timed
region is the variant's, and only the variant can repeat it) rather than the harness batch loop, which is
coupled to scoring.

Two design decisions were taken under op's live steer on the ABI-break blast radius. Per-stage sub-timing is
achieved with no ABI break, via the cost-model's fixed-versus-marginal decomposition and cumulative-through-
stage variants in the matrix whose differences give per-stage cost, because breaking the `FfiBenchCall` ABI
would force an explicit migration across every workspace bench variant, which op flagged as a careful-design
item rather than an easy auto-update. The hardware perf-counter wiring is left as an investigate-and-wire item
because it needs a privileged sysctl to produce any data and the same deep sample-and-report capture plumbing;
it is not rushed into the timing path.
