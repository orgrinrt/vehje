# Topic: the lease and region proof axis

**Date:** 2026-07-20
**Phase:** TOPIC
**Round:** runtime output + lease proof. Second of two topics. The sibling
`202607201315_topic.runtime-output-value-transfer.md` settles how the output value crosses the boundary; this
one settles how the validity of the references inside that value is proven, so the runtime never needs a
garbage collector or a null.

## The question

Fully dynamic languages (the .NET CLR, Lua, JavaScript) all default to a nullable, garbage-collected value
because they have no compile side and therefore cannot know, when a value is produced, how long any reference
into it stays valid. They pay for that uncertainty at runtime, forever, in null checks and collection. vehje
has a compile side, and it already discharges an effect proof in Rust before any lowering, so that the runtime
never checks effects. The question is whether the same can be done for reference validity: prove every
reference's lease statically, discharge it before lowering, and let the runtime inherit proven-valid,
non-null references with no collector and no reference counting.

op's framing: mimic Rust's explicit and inferred lifetimes with a lightweight borrow-analysis in the loop, so
vehje does not inherit the forced-null stance of the dynamic languages. Reconceived not as Rust borrows but as
references carrying leases, statically analysable through vehje's typestate and the Rust machinery on the
compile side.

## What this actually is

This is a third proof axis, sitting parallel to the two vehje already has. Family inclusion proves a program
only uses node families its target supports. Effect inclusion proves a program only performs effects its
target permits. The lease proof proves every reference in a produced value is valid for as long as it is used.
All three are discharged in Rust before lowering, so the runtime inherits proven-safe programs on all three
axes and stays a dumb evaluator.

The right lineage for it is region inference (Tofte-Talpin and MLKit, with Cyclone as the closest prior art
for the infer-or-annotate discipline), not the full Rust borrow checker. Rust's borrow checker does two jobs:
region validity, and aliasing-exclusive-of-mutability. A produced vehje value is immutable once computed, so
only the first job is needed. Dropping the aliasing half is what makes the analysis tractable to fuse into the
existing resolve walk rather than build a separate borrow checker. So the analysis is lifetime reasoning
without borrow exclusivity: references and leases, region-validity only.

The default lease is per-body: a value is valid for the duration of the evaluation body that produced it (a
`Let` body, a `Lambda` body, the top-level program body). When a reference escapes its default region, the
analysis tries to infer the wider lease it needs. If it can prove one, it annotates the reference and moves
on. If it cannot, it is a compile error that forces the author to make the lease explicit, rather than a
silent fall back to a nullable, collected value. That failure-is-an-error stance is the strict-by-design
posture applied to lifetimes.

## Decisions (settled with op, 2026-07-20)

The lease is proven by a pass and certified by the typestate. A value-level region-inference pass computes a
proven lease per reference and region over the IR, which is what handles per-program regions (a value whose
lease depends on the specific program). A `Leased` typestate gate, the mirror of the existing `Checked`
residual gate, makes lowering callable only on a lease-proven IR. Inference is where the regions are computed;
the typestate is where the discharge is certified, exactly as the effect proof is a computed set that the
typestate then certifies. This was chosen over a pure type-level typestate, which cannot express per-program
inferred regions, and over a pure value-level annotation with no type gate, which would make the
proof-before-lowering guarantee a convention rather than something the type system enforces.

The lease analysis is a dedicated, separable module, but it is fused into a single walk with no extra
traversal. Its hooks are invoked from within the existing resolve walk, which already threads the borrowed
scope chain and where a binder's default region is its `Let` or `Lambda` body. The lease logic stays its own
module, testable on its own, but adds no second pass over the IR. The exact fusion point is an implementation
detail; the resolve walk is the natural host because it owns the scope structure.

The residual carries the proof to the runtime as region tags plus emitted region nesting. Each value node or
arena segment carries a region id, and region open and close markers are emitted so the runtime frees a
region's segment at its close, on stack discipline, with no collector and no reference counting. Whole-value
mode from the transfer topic is the single-region degenerate case, and the format can stage in as one flat
region first, with region tags as the general form it grows into. This was chosen over a single flat region
with no per-region frees, and over per-node reference counts, which would reintroduce exactly the dynamic
per-node tracking the static-lease design exists to remove.

Absence is an explicit value form, not a nullable reference. Optionality is a `Maybe` node the consumer
matches on, so every reference is proven non-null by construction. This is notko's fallibility ladder applied
to the runtime value model, consistent with the rest of the stack's refusal of implicit null.

## How it lands on the transfer mechanism

The transfer topic's value-arena, host-lent memory, reserve/commit sink, and whole-subtree chunking all stand;
the lease layer sits on top. The value-arena becomes region-structured. The per-body default lease is exactly
whole-value mode: compute, hand the host the region, the region dies at body end. A value that must outlive the
call is no longer a lifetime hazard the host has to be careful about; it is a value whose longer lease the
compile side proved, so the runtime puts it in a longer-lived region and the retained-value danger dissolves
into a proof rather than a documented convention. The in-process Rust driver's borrow, which the transfer
topic scopes with Rust lifetimes, becomes the outer mirror of an inner lease the compile side already proved.

## Open threads for this round (to settle before the doc changelist)

Several details remain genuinely open and are the topic-phase conversation still to have. The consumer-surface
hook for the explicit lease annotation, the shape a consumer language uses when inference fails and an
explicit lease is forced, parallel to the existing family and effect extension hooks. How a family (the `Raw`
escape) extends the lease analysis over its own payload. The exact wire layout of the region tags and the
open/close nesting markers in the value-arena. Whether the lease proof and the effect proof compose or stay
orthogonal, the current expectation being orthogonal. And the `Maybe` value form itself belongs to the
value-node-kind schema, which is op's sequenced follow-up round, so this topic names it as a decision but does
not fix its encoding.
