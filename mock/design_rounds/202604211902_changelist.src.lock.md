## Purpose

Retrofit every `Vec<T>` return type or trait-method output across
the clause phase + runtime crates into a sink-based signature
(`&mut impl DiagnosticSink<E>` or `&mut impl ByteEmitter`). The
sink traits live in `hilavitkutin-api` (`sink.rs`) and are blanket-
impl'd over the `Push` / `BulkPush` / `Len` primitive operations.

Doc counterpart is `202604211855_changelist.doc.lock.md`, already
landed. Struct fields (`Vec<Scope>`, `HashMap<String, Symbol>`,
`Vec<Maybe<Symbol>>`, `Vec<String>`) remain untouched this round —
their shape is tangled with `Str` interning and ships with #73.3.

### Change S2 — clause-typecheck: Validator trait + 10 impls + registry

`src/validator.rs` — trait change:

```
- fn validate(&self, ctx: &ValidatorCtx) -> Vec<Diagnostic>;
+ fn validate(
+     &self,
+     ctx: &ValidatorCtx,
+     sink: &mut dyn DiagnosticSink<Diagnostic>,
+ );
```

Note the `&mut dyn` rather than `&mut impl`: the trait lives
behind a `&'static dyn Validator` registry, which prohibits
`impl Trait` in method signatures (no monomorphisation at the
dyn boundary). Callers can still pass any concrete type that
implements `DiagnosticSink<Diagnostic>`; the dyn-dispatch cost
sits on the sink call site, not the validator dispatch.

Ten impl sites move in lockstep (same `&mut dyn DiagnosticSink<
Diagnostic>` sig, empty body, push nothing this round):

- `src/strict1.rs` through `src/strict7.rs` (seven files).
- `src/coherence.rs`, `src/orphan_rule.rs`,
  `src/bind_target_shape.rs`.

`src/registry.rs::ValidatorRegistry::run_all` moves from

```
pub fn run_all(ctx: &ValidatorCtx) -> Vec<Diagnostic> { ... }
```

to

```
pub fn run_all(
    ctx: &ValidatorCtx,
    sink: &mut dyn DiagnosticSink<Diagnostic>,
) { ... }
```

The internal `let mut out = Vec::new()` accumulator is removed; the
body iterates `Self::VALIDATORS` and forwards `sink` into each
`v.validate(ctx, sink)` call.

`src/registry.rs::typecheck` — the free fn moved in #73.1 — takes
the same sink and forwards. `src/lib.rs` already re-exports
`typecheck` via `pub use registry::{typecheck, ValidatorRegistry};`;
no additional change.

Tests in `src/registry.rs` under `#[cfg(test)]` adjust to pass a
local `Vec<Diagnostic>` as the sink (works via the existing blanket
`Push` / `Len` / `BulkPush` impls for `Vec` in the standard library
collections — `hilavitkutin-api` provides those blanket impls).

### Change S3 — clause-syntax: parse entry + Parser::parse

`src/parser.rs::Parser::parse` — move from returning
`Outcome<Ast, Vec<SyntaxError>>` to filling a caller-provided
sink. Trait choice: `&mut dyn DiagnosticSink<SyntaxError>` — same
dyn-over-impl reasoning as S2 (parser is called through the
free fn `parse` at the crate root and may flow through
generic-over-sink at one level and dyn below).

Free fn `parse` at the crate root (moved to `src/parser.rs` in
#73.1, re-exported from `src/lib.rs`):

```
pub fn parse(
    tokens: &[Token],
    errors: &mut dyn DiagnosticSink<SyntaxError>,
) -> Outcome<Ast, ()>
```

The existing `lint:allow(bare_collection) tracked: #73` on the
signature disappears. The `Outcome::Err(())` variant keeps the
hard-failure shape; soft errors flow through the sink.
