# Runtime-ABI soundness fixes

A neutral read-only soundness review of the runtime-ABI boundary (the residual wire format and the
value arena the eventual runtime consumes) found one defect in landed code plus several hardening
gaps. The verification core the compile-side DSL builds on was already sealed in round `202607240400`;
this boundary is downstream (a runtime consumes it), so these do not block authoring a language
consumer, but the one real defect is cheap to close now, before any reinterpret-cast code is written
against the wire types. Each finding was confirmed against source before this topic was written.

## The value-arena wire types carry no repr (the one landed defect)

`vehje-runtime-abi/src/value.rs` declares the value-arena node types (`ValueTag`, `ValueList`,
`BlobSpan`, `ValueNode`, `Region`, `RegionId`) with `#[derive(...)]` but no `#[repr]`. The crate's own
design (the value-transport deep dive) states the wire form equals the in-process form and the runtime
reads the arena zero-copy over host-lent memory. Zero-copy reads across the boundary require a stable,
declared layout; Rust's default representation guarantees none and may reorder fields between
compilations. So the types the design treats as the wire form have no wire layout.

Decision: give each value-arena struct `#[repr(C)]` and the `ValueTag` enum an explicit discriminant
repr. The layout is then declared and stable, matching the zero-copy design. The `#[repr(transparent)]`
newtypes already present (`ValueRef` and its sibling) stay as they are.

## The children accessor repeats the arena overflow bug

`ValueArena::children` slices `pool[start .. start + len]` with no bound, the same shape the round
`202607240400` review flagged in `Arena::list`: a malformed `ValueList` overflows the `start + len`
add (panic in debug) or reads past the filled pool. `ValueArena::get` likewise indexes `nodes` and
panics on an out-of-range `ValueRef`.

Decision: clamp `children` to the live pool with a saturating add, exactly as `Arena::list` was fixed,
and add a bounds-checked `try_get` returning `Maybe<ValueNode>` for the untrusted path. `get` stays as
the documented trusted-path accessor (valid only after validation), with its precondition stated.

## Validation typestate (kept as the honest frontier)

`vehje-runtime-driver`'s `Reader::validate` is an intentionally FIXME'd no-op, and there is no
typestate stopping a caller from reading an unvalidated (possibly untrusted, out-of-process) arena
directly through the raw accessors. Building the real validation pass, and a typestate that makes an
unvalidated arena unreadable through the safe path, is a genuine design addition tied to the
out-of-process residual story, which is not yet built. It stays FIXME'd and tracked; the `try_get`
accessor and the stated `get` precondition are the interim, so a caller at least has a non-panicking
option. This round does not fake it green.

## New public surface

`vehje-runtime-abi`: `ValueArena::try_get` (the bounds-checked accessor). The `#[repr(C)]` additions
are attributes on existing documented types, not new surface.

## Flagged for op (wire-spec questions, not decided here)

The exact `ValueTag` discriminant width and whether the wire format is host-native (same architecture
both sides, so `USize` platform-width fields are fine) or a cross-platform serialized form (which would
need fixed-width fields, not `USize`) are wire-specification decisions. This round pins `#[repr(C)]` +
an explicit small discriminant on the host-native reading (matching the "wire form equals in-process
form" design), and flags the cross-platform question for op rather than settling the wire spec
unilaterally.
