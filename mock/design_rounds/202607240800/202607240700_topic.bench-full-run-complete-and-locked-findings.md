# The bench full run is complete, and the findings are locked

The long design round ran an unusually large de-risking, composition-matrix, and boundary-bench effort. The
last outstanding piece, the ABI batched-execute cross-profile full run over the whole 72-family validate
matrix, has now finished: total wall time 29223.7s (about 8.1 hours), 885 cdylib variants compiled and run in
subprocess isolation, every variant cross-validated byte-exact. The prior findings topic anticipated this run
as confirmatory ("the cross-profile full run is confirmatory of these reads"), and it was: no finding flipped,
no new result emerged, the numbers reproduce the reads the design already rests on. The committed trail is
`mock/benches/.bench_history/abi_*.tsv` and the curated `mock/benches/results/` tree (committed in `d3b2038e`).

One representative confirmation, because it is the load-bearing dispatch result: on `abi_zig_entry_wideselect`
the Zig tail-threaded dispatch measures about 1053x the null floor against about 629x for the plain Zig
switch, so tail-threading is about 1.7x slower than a plain switch for vehje's lean op vocabulary, reproducing
the composition matrix's "switch wins for straight-line dispatch, threading only earns its keep across real
control-flow terminators" read. The SoA vertical-SIMD win (2.3x to 4.1x, surviving the C ABI boundary
byte-exact) reproduces likewise, and it is what justifies the batched-column entry.

## What is now locked (bench-backed, final for this design)

These were settled by the arc and are now confirmed complete; the implementation round treats them as fixed:

1. The runtime C ABI exposes one runtime-W batched column entry, W >= 2. No per-W symbol zoo, no
   crossing-amortisation cleverness: the crossing is about 9 ns warm (negligible against any interpret
   payload), and the runtime, not the ABI, owns the SIMD width. The win the batched entry enables is the SoA
   vectorisation the runtime does across a resident column.
2. Interpreter dispatch is a plain switch for straight-line blocks; preserve-none token threading is reserved
   for the CFG terminator transfers where it measurably wins; tail-threading is a measured-and-rejected
   alternative for this op vocabulary.
3. The native tier is a modest 1.0x to 1.5x accelerator over a good interpreter for scalar code, not a 10x
   keystone; the 10x class is reserved for a vectorising JIT on the rare compute-bound consumer. Copy-and-patch
   is an opt-in accelerator whose stencil emitter applies the tier-dependent branch-strategy map.
4. Wire format: operands stay inline (pool indirection is the measured expensive part at 10.7 ns/node versus
   4.4 ns/node inline); the exact inline operand count is an open measure-then-lock decision against a real
   census corpus (the earlier 24-byte-three-operand flip washed out to a null result under the carrier
   re-measure), not a day-one commitment.
5. The comptime kernel, the load verifier, and the e-graph extractor are iterative work-stacks, never
   recursive (recursion is a hard Zig-comptime compiler wall at about 2500 depth).
6. The relational-fixpoint compile substrate is feasible no-alloc and cheap (about 50 ms at 8M nodes,
   whole-column OR beating delta semi-naive for the realistic shallow graphs); the eqsat growth is linear
   (about 5.2x in four rounds, hashcons congruence deduplicating), validating it as dev-time-only behind a
   bounded streaming window; the effect proof is negligible (about 3 ms at 8M via thermometer-encoded bitmask
   join); the incremental scaling layer is decisive (4 ms cold, 0.003 ms warm, 7.7x parallel at 8 threads).
7. The branch-strategy map is tier-dependent (interpretation never eval-all; native branchless-eval-all wins
   for cheap-arm many-way unpredictable branches by 26%), which is the measured content of proof-directed
   strategy selection.
