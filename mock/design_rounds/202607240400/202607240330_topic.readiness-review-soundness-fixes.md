# Readiness-review soundness fixes

The converged twelve-crate ecosystem landed and closed in round `202607240130`. A neutral read-only
readiness review of the whole ecosystem, run against the completion criterion "ready to build a
language consumer on the machinery," found that the criterion is not yet met: the verification core,
which is the framework's stated identity, does not hold as landed. The witness a target consumes to
prove a program was checked is presently forgeable, and the structural hash the incremental layer
trusts collides on distinct programs. Both are correctness gaps in already-shipped code, not frontier
mechanisms left for later, so they are fixed here in a follow-up round on the same branch before the
arc's work is offered as ready.

Each finding below was confirmed against the source before this topic was written. The distinction the
review was asked to draw, a genuine soundness or contract gap versus a mechanism merely not yet
implemented, is preserved: the honest frontier pieces stay marked and deferred, and only the real gaps
are closed.

## The forge (load-bearing)

`vehje-typecheck::mint_checked` is the one sanctioned public path that constructs the `Checked`
witness (`Checked::new` is correctly `pub(crate)`). Its signature takes `Supports`, `Permits`,
`Families`, and `Effects` as free type parameters, none tied to the target `T`, with the bounds
`Supports: ContainsAll<Families>` and `Permits: ContainsAll<Effects>`. Because hilavitkutin-api ships
`impl<S: AccessSet> ContainsAll<Empty> for S` (access.rs:111), a caller writing
`mint_checked::<AnyTarget, _, _, Empty, Empty>` discharges both bounds vacuously and mints a witness
that claims any target accepts any program.

The gap has two halves. Half (a): `Supports`/`Permits` are decoupled from the target's real declared
sets, so a caller can claim a support set the target does not have. This is fixable now. Half (b): the
program's actual `Families`/`Effects` are supplied by the caller rather than derived from the program,
so a caller can claim `Empty` and dodge the check. Half (b) is the already-existing FIXME (the full
soundness that derives the used sets from the program lands with the runtime-bitmask inclusion path);
the review's new contribution is that half (a) was unmarked and is separately closable.

Decision: introduce a `TargetSets` carrier trait in `vehje-ir` naming `type Supports: AccessSet` and
`type Permits: AccessSet`. `vehje-codegen`'s `Target` extends it. `mint_checked` becomes generic over
`T: TargetSets` and derives the two sets from `T`, so the caller can no longer decouple them from the
target. Half (b) stays FIXME'd and now stands alone as the single remaining inclusion hole, clearly
marked rather than hidden inside the free-parameter surface.

## The mint does not require a check (load-bearing)

The DESIGN states that check mints the witness. The implementation split the graded fold (`check`,
which fills the `GradeTable`) from the mint (`check_for` / `mint_checked`), and the mint requires no
evidence that `check` ran. A caller can mint over an arena whose root is a dangling reference; the
integrity error surfaces only later as a panic inside `emit`'s `fold_core`, past the point the witness
claimed the program sound.

Decision: `check` returns a `Graded` witness token on success (a zero-size proof that the graded fold
ran clean over a given arena and root, i.e. no dangling references), and the mint requires it. This
re-unifies the mint with the check the DESIGN describes, kills the unchecked/dangling-ref path, and is
the structural slot into which the half-(b) program-derived inclusion later drops (the token's
completeness grows as `check` grows). At M-level the token proves integrity; the FIXME on it names the
inclusion-derivation it will also carry.

## The structural hash collides on leaf content (correctness)

`vehje-ir::hash_of` is a Merkle word-fold that mixes each node's discriminant with its children's
content-hash words. Its module doc claims equal subtrees hash equal so a cross-artifact cache hit is
sound, and `vehje-fixpoint`'s incremental layer trusts exactly that ("a hit is proven-valid"). But the
fold incorporates no leaf content: `Var(_)` folds nothing, `Lit` folds only the type tag and not the
value, and `Project` and `Raw` drop their key and payload. So `Var(x)` and `Var(y)` collide, `Int(1)`
and `Int(2)` collide, `a.foo` and `a.bar` collide. Distinct programs hash equal, which breaks the
soundness the module's own comment asserts and arms a trap for the first hash-consing or dedup consumer.

Decision: fold the leaf content into the hash. `Var` folds the interned name (`Str::to_bits()`), `Lit`
folds the scalar value (the bool bit, the 64-bit int, the interned string word) alongside the type tag,
`Project` folds the key, `Raw` folds its payload children. Structurally distinct subtrees then hash
distinct, restoring the invariant the incremental proof-preservation argument depends on.

## let rec cannot resolve (correctness)

`Node::Let` carries a `rec: Bool` and the builder exposes it, so a recursive binding is representable.
`vehje-resolve` walks the bound value under the outer scope unconditionally, discarding `rec`, so a
`let rec f = ... f ...` cannot see its own binder and fails to resolve.

Decision: when `rec` is set, push the binder frame before walking the value, so the value sees the
binding; when it is not, keep the current non-recursive scoping. The same rule applies in `resolve`
and `resolve_into`.

## Doc/source mismatch: compile_language

`vehje/DESIGN.md.tmpl` backticks `compile_language` as the per-language orchestration entry, but the
source carries it only as a FIXME comment (the symbol was dropped to avoid a duplicate-fn collision and
its real form is deferred). The design-doc-source-mismatch lint did not catch it because the name
appears in a comment. A backticked name in a DESIGN asserts the symbol exists.

Decision: unbacktick `compile_language` in the DESIGN so the doc honestly reads it as designed but not
yet shipped, matching the BACKLOG-not-DESIGN convention for deferred surface. It returns to backticked
form when the per-language path is implemented.

## Minor hardening

`Arena::list` is not bounded by the child-index pool length, so a malformed `NodeList` could read out
of the pool's live region; bound it. There is no recursion depth cap on the compile-side folds; the
depth is arena-bounded in practice, so this stays a documented FIXME rather than a hard cap this round.
The suite carries no catalogue-red tests despite the frontier FIXMEs; add `#[ignore = "catalogue: ...;
tracked ..."]` reds for the genuine deferred mechanisms (the effect-gating derivation, half (b) of the
inclusion) and green tests for every fix landed here (the hash now distinguishes leaves, let rec
resolves, the mint requires a `Graded` token).

## New public surface introduced

`vehje-ir`: `TargetSets` (the carrier trait), `Graded` (the check-evidence token). Both go into the
relevant DESIGNs so the surface is documented. `vehje-codegen::Target` gains `TargetSets` as a
supertrait. No other public shape changes.
