# Doc changelist: the produced-value crossing contract

**Round:** 202607251109 (topic: `202607251109_topic.produced-values-cross-back.md`)
**Phase:** DOC
**Scope:** two documents. `vehje-runtime-abi/DESIGN.md.tmpl` gains the pinned value-image byte layout and the writer and reader that realise it. `runtime-zig/DESIGN.md.tmpl` is corrected from the superseded Phase 6 stub-and-macro-interpreter description to the residual executor it is.

## `mock/crates/vehje-runtime-abi/DESIGN.md.tmpl`

In the value-arena section, after the existing description of the in-memory format, add the wire layout that makes it a cross-language contract:

- State the problem the layout solves: the `#[repr(C)]` record is a Rust in-memory shape whose widths are the platform's, so a Zig writer and a Rust reader need a pinned byte form, the same reason the residual pinned one.
- Name the layout: a header of fixed little-endian words (magic, version, node count, pool count, region count, blob length, root), then fixed-width value-node records, then the flat child-index pool, then the region table, then the byte blob. Fixed-width records so a reader indexes node `i` in constant time without scanning; the image self-contained and position-independent so the wire form equals the in-process form.
- State the ordering rule and what it buys: depth-first, children-before-parents, so a parent records already-known child indices with no back-patching, and a structural decode over an untrusted image is a single monotone index check (a child index strictly below its parent) rather than a cycle search.
- Name the two halves as shipping surface: `write_value` serialises a `ValueArena` into a caller-provided byte buffer and reports the bytes written, or `Isnt` when the buffer cannot hold the image; `ValueImage` is the reader over an untrusted image, whose accessors bounds-check every index and span against the image so a malformed input is a refusal, never a read past the end.
- State the closure constraint: a closure names an environment inside one run of the runtime, so it has no value-arena representation and cannot be a value the host holds after the call returns. A program whose final value is a closure is refused with a named reason rather than partially written.

Keep the existing region-structure paragraph and the host-lent backing note unchanged; the layout section sits with them, not in place of them.

## `mock/runtime-zig/DESIGN.md.tmpl`

Rewrite the identity, scope, and round-skeleton sections. The document currently describes three stubs that return an error code and a compile-time macro interpreter with a scratch-variable evaluator and a token-stream emitter; that role is superseded (the compile side reduces every build-environment effect away in Rust, and the Zig side executes the residual against the runtime environment).

- Identity: the Zig implementation of the vehje runtime, the executor of a `Checked` residual. It consumes the tier-tagged wire residual across the C ABI, evaluates it, and produces a value. It pulls no `std`, holds no allocator, and works over host-lent memory.
- The tier-0 execution model, marked as shipped: the `Arena` tier is a tree-walk over the serialized node arena, the reference semantics against which the `Bytecode` tier (the CFG-of-blocks linear form) is later measured. Describe the decode (seven-word header, seven-word node records, the flat child pool, the string blob, little-endian) and that binders match by their `Sym` bits, so a `Var` binds to its `Let` by integer equality with no text and no interner on the runtime side.
- The environment model and why it is what it is: a caller-lent bump arena of linked bindings rather than a popping stack, so capturing an environment is recording one index and a closure that outlives its defining scope still reads the bindings it captured. Nothing is freed within a run; exhausting the lent arena is a named refusal.
- The evaluated set, marked shipped: unit, boolean, and integer literals; `Var`; `Let` including the recursive form (the binding is in scope for its own value, which is what makes a recursive closure terminate); `If`; `Lambda` producing a closure that captures lexically; and `Apply`, which applies one argument at a time because multi-parameter lambdas desugar to nested `Lambda`.
- The refusal set, marked shipped: an unbound variable, a non-callable application, a form or literal this tier does not evaluate, an exhausted environment arena, and a corrupt index or record past the image. Each is a named error, never a wrong answer.
- The C ABI surface, marked shipped: `vehje_runtime_new`, `vehje_runtime_free`, `vehje_runtime_execute`, and the `VEHJE_RESULT_*` constants mirroring the Rust discriminants. Keep the existing scalar-`i32`-return rationale (the rejected one-field extern struct and the MSVC hidden-pointer reason) verbatim; it is still correct and still load-bearing.
- What is intended and not shipped, each labelled: returning the produced value across the ABI through a `VehjeSink` in the value-image layout this round pins (the next gate, and today the value is evaluated then discarded); family operations and host calls, which is how arithmetic and host services arrive, since the framework owns no family; strings, sequences, records, and the remaining Core forms; and the `Bytecode` tier.
- Non-scope, corrected: the ABI contract itself (`vehje-runtime-abi`), the compiler-side dispatch and embedding (`vehje-runtime-driver`), and any build-environment semantics, which the effect proof guarantees never reach the residual.
- Sources: cite this round and the wire serialization module rather than the superseded macro and scratch-variable research notes.

## Not in this changelist

No other crate's design changes. The Zig writer, the sink parameter on the execute entry, and the driver embedding are named as intended in the runtime design and land in their own rounds.
