# Src changelist: Perform, and the non-resuming discharge

**Date:** 2026-07-25
**Phase:** IMPL
**Doc CL:** `202607252200_changelist.doc.lock.md`

The mechanism lands whole rather than in halves, which is what the reserved resumption field exists to make
unnecessary. Each pass gains a single arm; building the representation twice is the cost the reservation buys
out of.

Order matters here because the crates are layered: the Core form and the clause region first, then the wire,
then the two passes that gain a scope chain, then the interpreter. Nothing below compiles until the layer above
it has landed, which is the ordinary shape of a change that crosses the whole stack.

## CHANGE: `Clause` and `ClauseList` ARE ADDED to `vehje-ir`

File: `mock/crates/vehje-ir/src/node.rs`
`Clause { op: Sym, resume: Sym, arity: Uint<8, Hot>, body: NodeRef, span: Span }` and
`ClauseList { start: USize, len: USize }`. Every field is authored because none is derivable; `arity` in
particular cannot be recovered by counting `Lambda` nesting, because a body may return a lambda.
Verification: `grep -n "pub struct Clause" mock/crates/vehje-ir/src/node.rs` returns one match.

## CHANGE: `Arena` GAINS the clause region

File: `mock/crates/vehje-ir/src/arena.rs`
FROM `Arena::new(nodes, spans, pool)`
TO `Arena::new(nodes, spans, pool, clauses)`, with a bump cursor and an append that refuses when full, matching
the three regions that already exist. The refusal is `must_use` like the grade region's, so an undersized
region cannot be silently ignored.
Verification: `grep -n "clauses" mock/crates/vehje-ir/src/arena.rs` returns the field, the cursor, and the
appender; every caller of `Arena::new` across the workspace compiles.

## CHANGE: `Node::Handle.clauses` CHANGES FROM `NodeList` TO `ClauseList`

File: `mock/crates/vehje-ir/src/node.rs`
The clause list now slices the clause region rather than the child pool. The `Handle` doc comment loses its
third authored item, per the doc CL: the discharge is the binding-time grade, not clause data.
Verification: `grep -n "clauses: ClauseList" mock/crates/vehje-ir/src/node.rs` returns one match.

## CHANGE: `Node::Perform` IS ADDED as the thirteenth form

File: `mock/crates/vehje-ir/src/node.rs`
`Perform { op: Sym, args: NodeList }`. The doc comment carries the algebra argument and the reason it is not
`Raw`, so the next reader does not re-propose folding them.
Verification: `grep -n "Perform {" mock/crates/vehje-ir/src/node.rs` returns one match.

## CHANGE: the builder GAINS `perform` and `clause`

File: `mock/crates/vehje-ir/src/builder.rs`
`perform(op, args)` beside the existing smart constructors, and `clause(op, resume, arity, body, span)`
appending to the clause region. `handle` takes a `ClauseList`.
Verification: `grep -n "pub fn perform\|pub fn clause" mock/crates/vehje-ir/src/builder.rs` returns both.

## CHANGE: structural hashing COVERS the new form and the clause region

File: `mock/crates/vehje-ir/src/hash.rs`
`Perform` folds its operation's `Sym` bits and its argument list; `Handle` folds its clauses' four words. A form
the hash does not cover would make two structurally different programs hash equal, which is the one thing the
within-stage identity must not do.
Verification: a test asserts two `Perform` nodes differing only in operation hash differently.

## CHANGE: the wire GAINS tag 12, the clause section, and a version bump

Files: `mock/crates/vehje-runtime-abi/src/wire/serialize.rs`, `src/encode.rs`
`Perform` serialises as tag 12 with the operation in word 1 and the argument list in words 2 and 3. The clause
section follows the string blob, four words per clause; the header gains a clause count. `VERSION` bumps.
Verification: `grep -n "NodeTag::Perform => 12" mock/crates/vehje-runtime-abi/src/wire/serialize.rs` returns
one match; a round-trip test covers a handle with one clause.

## CHANGE: `resolve` GAINS the handler scope chain

File: `mock/crates/vehje-resolve/src/lib.rs`
A `Handle` pushes its clause operations on the way in and pops on the way out; a `Perform` resolves its
operation against that chain and records the perform against the handling `Handle` in the existing side-table.
An unresolved operation is a named error rather than a silent pass.
Verification: a test resolves a nested `break` to the inner handler and a second test resolves an operation
that crosses an unrelated handler untouched.

## CHANGE: `check` GAINS the effect scope chain, retiring the subtraction FIXME

File: `mock/crates/vehje-typecheck/src/lib.rs`
A lexically handled `Perform` contributes nothing to the effect mask; only escaping operations populate it. The
FIXME at the `Handle` arm goes away because the question it names no longer arises.
Verification: `! grep -n "subtract the handled ops" mock/crates/vehje-typecheck/src/lib.rs`, and a test asserts
a handled operation is absent from the root's effect mask while an unhandled one is present.

## CHANGE: `check` CONSTRUCTS `ForbiddenEffect` and `UnplaceableLease`

File: `mock/crates/vehje-typecheck/src/lib.rs`
`ForbiddenEffect` for a performed operation with no enclosing clause and no permitting target.
`UnplaceableLease` for the escape check: the `Lambda` promotion puts the body's unhandled operations on the
lambda value's reach, and the `Handle` refuses a result whose reach contains its own handler slot.
Verification: both variants are constructed somewhere in the crate, not merely declared; a test returns a
performing lambda out of its handler and asserts the refusal.

## CHANGE: the interpreter GAINS the carrier, `Perform`, and `Handle`

File: `mock/runtime-zig/src/runtime.zig`
`eval` returns a carrier that propagates rather than jumping. `Perform` evaluates its operands left to right and
returns an unwind carrying the operation and the operands. `Handle` installs its clauses, evaluates its body,
and on an unwind compares the carrier's operation against its clause list, applying the matching clause body in
the handler's own environment rather than the performer's.

Every multi-child site must check the first child's carrier before evaluating the second, or left-to-right
order does not survive the unwind. That is a per-site obligation, so it gets a test per multi-child form rather
than a comment.
Verification: the tests below pass.

## CHANGE: the stale comment naming `Project` as unimplemented IS REMOVED

File: `mock/runtime-zig/src/runtime.zig`
`Project` shipped in round 202607251900 and the comment listing forms that land later still names it.
Verification: `! grep -n "Project, Match, Iter" mock/runtime-zig/src/runtime.zig`.

## The red tests, which are the mechanism's boundary

An operation that escapes inside a returned lambda, refused. A `break` crossing a `continue` handler untouched.
A clause whose body references its resumption, refused, catalogued red until the bounded-multi-shot work lands.
Two labelled loops whose operations do not collide. An unhandled perform refused at compile time rather than at
run time. And the loop iteration bound, asserting the intended unbounded behaviour and left red against the
current exhausted-arena refusal, so the limitation is measured rather than described.

## Not in this round

The resumption's runtime representation. The trampoline and the binding reclamation that make loops usable.
Whether a host-served `Raw` collapses into a `Perform`. Whether the clause region is the region `Match`'s arms
will use.
