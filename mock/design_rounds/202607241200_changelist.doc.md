# Doc changelist: the consumer-facing public API surface

Doc-template edits for round `202607241130`. Documents the consumer-facing surface the `vehje` crate
re-exports so a consumer imports from one crate, and records the end-to-end consumer demonstration. Only the
`vehje` DESIGN changes; the re-exported types are already documented in their home crates.

## vehje/DESIGN.md.tmpl

- Add a "The consumer-facing surface" section stating that `vehje` re-exports the types a consumer needs to
  build against the two contracts, so a grammar plus a family plus a target is written against `vehje` alone
  rather than reaching into `vehje-ir`, `vehje-resolve`, `vehje-typecheck`, and `vehje-codegen` directly. The
  re-exported surface, by role:
  - IR building: `Arena`, `Builder`, `Node`, `NodeRef`, `NodeList`, `Literal`, `Span`, `FamilyId`.
  - The family machinery: `Family`, `Core`, the `AccessSet` set constructors `Cons` and `Empty`, and the
    `Contains` / `ContainsAll` inclusion witnesses.
  - The passes and their side-tables and hooks: `resolve`, `resolve_into`, `resolve_with`,
    `resolve_into_with`, `Resolution`, `FamilyResolve`, `CoreFamilies`, `ResolveError`; `check`, `check_with`,
    `Graded`, `CheckError`, `FamilyCheck`; `GradeTable`, `Grade`, `EffectMask`.
  - The output surface: `TargetSets`, `check_for`, `fold_core`, alongside the already-exported `Target`,
    `Checked`, and `CodegenError`.
- State that an end-to-end consumer demonstration (a minimal family plus target built against `vehje` alone,
  run through resolve, check, mint, and emit) is carried as an integration test, both as proof the framework
  hosts a consumer and as the reference a real consumer follows.
