# Topic: the host drives the runtime and reads the value back

**Date:** 2026-07-25
**Phase:** TOPIC
**Scope:** `vehje-runtime-driver` gains the real embedding: load the runtime artifact, call its entry with a serialized residual and a host sink, and hand back the value image the runtime committed. Also flip the runtime design's produced-value bullet from intended to shipped, now that the Zig side writes one.

Every piece of the path from a program to an answer now exists except the piece that joins them. The compile side lowers, resolves, checks, and emits. The wire form serialises. The Zig runtime decodes that wire form, evaluates it including closures and recursion, marshals the produced value into the pinned value image, and streams it through a reserve-then-commit sink. What no Rust code can do yet is call any of that: `dispatch` is a stub that ignores its argument and returns success, and the crate's own design admits the embedding is owed. This round closes the loop, which is what turns a set of working parts into a runnable system.

The embedding needs a way to reach the artifact's exported symbols. The crate's Cargo file carries a commented-out `libloading` line and its design names dlopen behind a `std` feature, both written before the workspace had its own answer. It does now: `hilavitkutin-linking` is the cross-platform loader primitive, pull-based explicit-symbol resolution over dlopen and LoadLibrary, `no_std` and no allocator, with `Library::load`, a sealed `LibrarySymbol` contract covering `extern "C"` function pointers, and an explicit `close`. Using it instead of a third-party crate is what the use-the-stack rule asks for, and it has a consequence worth stating: the driver does not need `std` to embed the runtime. The `std` role the design claims for this crate is not required by loading, so the claim narrows rather than grows.

The other half is the sink. The runtime writes the value image through the host's `reserve` and `commit` callbacks, so the driver must supply a pair. The host lends the backing up front, which is the property that lets the runtime hold no output memory after the call. The driver's sink hands out one caller-provided buffer and records what was committed, which is the degenerate single-reserve case the transfer contract already allows, and refuses the reservation when the buffer is too small, which the runtime reads as backpressure rather than as a crash.

## Current state

`vehje-runtime-driver` ships `DriverError`, a `dispatch` that ignores its residual and returns `Ok` behind a FIXME, and `Reader`, a genuine bounds-checked validator over an in-memory `ValueArena` (region ranges, blob spans, child spans, and the strictly-below-parent monotone check that the children-first order turns into an acyclicity proof). It depends on `vehje-schedule`, which the canon has settled for dissolution in its own round, and its Cargo file carries the commented `libloading` line. Its design document describes the dlopen embedding and the `std` role as intended.

`mock/runtime-zig` exports `vehje_runtime_new`, `vehje_runtime_free`, and `vehje_runtime_execute(rt, input, len, sink)`, the last of which evaluates the residual, marshals the produced value into a value image, and commits it through the sink. A closure is refused, since it names an environment inside the run. `vehje-runtime-abi` pins the value image layout and ships `write_value` and `ValueImage`.

## Changes proposed

Add a `Runtime` type to the driver: open the artifact by path through `hilavitkutin-linking`, resolve the three exported entries once at open, and expose `execute`, which takes the serialized residual bytes and a caller-lent output buffer, calls the runtime with a sink over that buffer, and returns the number of bytes committed. The resolved symbols live for as long as the loaded library, which the type enforces rather than documents. Closing is explicit and surfaces the platform result, with the drop path as the fallback.

Extend `DriverError` with the failures this makes reachable: the artifact could not be loaded, an expected symbol was missing, and the runtime reported an execution failure. Each names what went wrong rather than collapsing into one code, since a missing symbol and a rejected program are different problems for whoever has to fix them.

Keep the value reading where it already is. The driver's job here ends at the committed bytes; `ValueImage` in `vehje-runtime-abi` is the untrusted reader over them, and `Reader` remains the validator over an in-memory arena. This round adds no second decoder.

Correct the driver's design to match: the loader is the workspace primitive rather than a third-party crate, embedding does not require `std`, and the produced value returns through a host-lent sink. Correct the runtime design's intended-not-shipped list, moving the produced-value crossing to shipped and recording the sink parameter the entry now takes.

## Not in this round

`vehje::run_and_execute`, the orchestration that would thread compile, serialize, execute, and read into one call for a consumer. It belongs above this crate and lands once this embedding exists. The `vehje-schedule` dissolution stays whole in its own round rather than being half-done here by dropping one dependency. Family operations and host calls, which is how arithmetic reaches a program, remain a separate design question.
