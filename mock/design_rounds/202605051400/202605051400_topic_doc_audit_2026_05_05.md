# Doc audit consolidation round (vehje)

This round consolidates the workspace-wide documentation audit findings for vehje into a single doc-only round. Two audits ran on 2026-05-05: a per-crate sub-agent audit covering `mock/crates/*/{README,DESIGN,BACKLOG,DEEPDIVE_*}.md.tmpl` and `mock/runtime-zig/` across 11 crates plus the runtime-zig directory, and a self-audit of the entrypoint surfaces. The findings cluster into six categories:

1. **`## Sources` block leakage in every per-crate DESIGN.md.tmpl.** Every section at the bottom of each DESIGN tmpl lists changelist filenames (`mock/design_rounds/<id>_changelist.doc.md`) at Tier 1.
2. **Round-shorthand vocabulary in DESIGN body prose.** Pervasive `Round-skeleton scope` / `Phase N skeleton round` / `R1-R4` references in body prose. These render Tier 1 and refer to internal round taxonomy.
3. **Banned bullet form `- \`Type\`. description` and `- **Label**. description`** across "Scope" and "Module-layout" sections in multiple DESIGN tmpls. Per `writing-style.md`, label-plus-period bullets (and the close-cousin label-plus-colon) are the cheat-sheet form to convert to glossary tables or prose.
4. **SHAME.md.tmpl files leak task IDs at Tier 1.** Names like `mockspace task` / `mockspace lint` plus `#131` / `#134` / `#147` / `#166` / `#207` task IDs render to public surfaces. SHAME files are workspace-internal but appear to render. Verify rendering target; if Tier-1-rendered, strip task IDs and `mockspace` mentions.
5. **Two sibling-private `stellar-heritage` repo mentions** in `vehje` and `vehje-codegen` BACKLOG.md.tmpl, plus the entrypoint audit's findings of `stellar-heritage/tools/clause/` references in `mock/DESIGN.md.tmpl`.
6. **Doc-vs-source claim mismatch in vehje-schedule.** The DESIGN.md.tmpl claims types `PassDag` / `PassRegistry` / `Scheduler` / `Artifact` exist; source has none of them. Likely a doc that was written ahead of source and source has not caught up. Substantive: needs determination of which side is canonical.

The audit's "## Suggested topic-file scope" proposed splitting into four scoped topics (Topic A Tier-1 leakage sweep, Topic B bullet-form remediation, Topic C vehje-schedule doc-vs-source repair, Topic D minor tail). This round consolidates them into one doc CL per the same rationale used in arvo + hilavitkutin parallel rounds (overlap, cheaper lock).

This round is doc-only. The src CL referenced in section "## Following src CL (mentioned, not written)" is left for a separate round.

## Decisions

### Decision 1: Scope shape

**Single doc CL covering all six categories** plus the entrypoint audit findings. Same rationale as arvo + hilavitkutin parallels.

### Decision 2: `## Sources` blocks → Tier 2 history

Same as arvo Decision 2 + hilavitkutin parallel: every `## Sources` block at the bottom of every per-crate DESIGN.md.tmpl moves to a sibling `mock/research/<crate>-history.md` Tier 2 file. The DESIGN.md.tmpl gets a one-line generic pointer at its bottom. Audit cites this in 14 of 15 DESIGN files; doc CL enumerates each.

### Decision 3: Round-shorthand vocabulary

Each `Round-skeleton scope`, `Phase N skeleton round`, `R1-R4` in body prose gets rewritten to the design rationale itself. Where the prose says "Round-skeleton scope: this crate ships the validator framework," replace with "This crate ships the validator framework. Subsequent passes (parser, typechecker, codegen) build on it." The phase-by-phase narrative belongs in Tier 2 history; the Tier 1 surface describes what the crate does, not its planned-implementation sequence.

### Decision 4: Bullet-form remediation

Convert label-plus-period bullets (`- \`Type\`. description`) to one of three canonical forms per writing-style:

- **Glossary table** (two-column `Name | Purpose`) when the listing has 3+ rows of parallel content.
- **Long-form prose paragraph** when the listing has 1-2 rows or when the description is multi-sentence.
- **Long-form bullets with real content** (multi-sentence per bullet, no leading-label-plus-period shape) when an enumeration genuinely needs bullets.

The audit cites the affected files; the doc CL enumerates the conversion choice per file.

### Decision 5: SHAME.md.tmpl

Verify rendering target via `cargo mock`:

- If SHAME files render to a Tier 1 surface, strip every `mockspace task` / `mockspace lint` mention and every `#NN` task id, replacing with the underlying issue framed in consumer terms.
- If SHAME files do not render to Tier 1 (workspace-internal only), no fix needed; their content is Tier 2 by the documentation-writing rule's surface taxonomy.

The audit flags this as a verification step rather than a hard fix; the doc CL includes the verification.

### Decision 6: stellar-heritage references

Three sites:

- `mock/DESIGN.md.tmpl` lines 10-13: rewrite the seed paragraph to drop `stellar-heritage` and frame the python reference implementation reference generically ("the python reference implementation, in a separate repo").
- `mock/DESIGN.md.tmpl` lines 59-62: drop the three `stellar-heritage` references in the "future extraction" lists; replace with `vehje-jomini` (the planned future companion crate) or drop the reference entirely.
- `vehje/BACKLOG.md.tmpl` and `vehje-codegen/BACKLOG.md.tmpl`: per-audit-citations, drop or generic-frame.

### Decision 7: vehje-schedule doc-vs-source

The DESIGN.md.tmpl claims `PassDag` / `PassRegistry` / `Scheduler` / `Artifact` types. Source has none. Two valid resolutions:

- **Doc is correct, source needs to add.** The DESIGN was written as a target-state doc; source has not caught up. The doc CL keeps the DESIGN content as-is (no doc-side edit) and the src CL ships the missing types.
- **Source is correct, doc is stale.** The DESIGN was written before a re-shape that removed the named types in favour of different shapes. The doc CL rewrites the DESIGN to match current source.

Determine which by reading vehje-schedule's source state. If source is empty (skeleton crate), the first reading applies (doc-CL leaves DESIGN, src-CL adds types). If source has different types, the second reading applies (doc-CL fixes the DESIGN). The doc CL records the verification result.

### Decision 8: `clause` references

The python reference implementation may legitimately keep the `clause` directory name in its source repo. Where `clause` appears as a stale Rust-port reference in vehje docs (post-rename to `vehje`), update to `vehje`. Where `clause` legitimately refers to the python reference impl directory, keep the reference but disambiguate context ("the python reference implementation, named `clause` in its source location").

### Decision 9: `saalis` reference in PRINCIPLES.md

The entrypoint audit found `saalis` named in `docs/PRINCIPLES.md` line 88 (rendered output). Source `mock/PRINCIPLES.md.tmpl` likely has the same. Replace with generic phrasing: where it currently reads `saalis's <X-trait-list>`, replace with `the established <X-trait-list>` or drop the cross-reference entirely.

### Decision 10: Title flow

`# vehje. Architecture Design` → `# Vehje: Architecture Design`. Mechanical edit on `mock/DESIGN.md.tmpl` line 1.

### Decision 11: WORKFLOW.md.tmpl rendering fate

Same as arvo + hilavitkutin parallels. Verify and act per the result.

### Decision 12: Auto-gen header workspace finding

Same as arvo + hilavitkutin parallels. Recorded; not addressed in this round.
