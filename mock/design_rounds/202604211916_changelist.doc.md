# Doc Changelist: clause binary CLI skeleton

**Date:** 2026-04-21

**Source topics:**

## Purpose

The `clause` binary DESIGN is a placeholder pointing at a set of
subcommands (`check`, `build`, `compile`, `new`) that never had
a design body. This round replaces it with the real CLI shape
the source CL will ship in lockstep, and opens a BACKLOG file
for the deferred subcommands.

Both files land this round. No other clause crate doc changes.

## Deliverables this round

### Change D1 — rewrite `clause/DESIGN.md.tmpl`

Replace the current 23-line provisional shape with the real
round-one shape: five subcommands (`lex`, `parse`, `check`,
`build`, `run`), with only `lex` carrying content this round.

The new DESIGN names the five subcommands, describes the `lex`
output format, lists the seven direct dependencies, and
explicitly carves the pass-DAG integration out as a BACKLOG
item. The "Provisional shape" section disappears.

### Change D2 — create `clause/BACKLOG.md.tmpl`

First BACKLOG file for the binary crate. Entries:

- `clause parse` — real AST pretty-printer once the parser
  productions land. Depends on `clause-syntax` ast printer.
- `clause check` — real typecheck + diagnostic print once the
  validators walk. Depends on `clause-typecheck` validator
  bodies.
- `clause build` — target dispatch. Depends on
  `clause-codegen` target implementations.
- `clause run` — compile + runtime invoke. Depends on runtime
  implementation and interpreter loading.
- Pass DAG wiring via `clause-schedule` — replaces the
  hard-coded phase chain once the pass-DAG exists.
- `Clause.toml` workspace manifest parsing — multi-file
  module graph, edition selection, target list.
- Argument parser library swap — replace the hand-rolled
  `args.rs` with `argh` or similar once CLI growth warrants
  it.
- Shebang / script-mode entry — `clause` as a `#!`-invoked
  interpreter for `.clause` scripts (separate from `run`).

## Deliberately NOT changed

- `mock/crates/clause/README.md.tmpl` — 9-line summary already
  reads correctly: "clause — top-level binary; orchestrates
  the compiler phases". Adding subcommand detail here would
  duplicate the DESIGN.
- No other crate docs. Dependencies added in the source CL do
  not surface any doc that isn't already described in the
  relevant crate's DESIGN.
