## Affected files

### clause-runtime-abi (R2 handle PhantomData, R3 SAFETY-GATE comments)

- `mock/crates/clause-runtime-abi/src/handle.rs` —
  - Replace `pub struct ClauseRuntime { _private: [u8; 0] }`
    with:
    ```rust
    use core::marker::{PhantomData, PhantomPinned};

    #[repr(C)]
    pub struct ClauseRuntime {
        _opaque: [u8; 0],
        _marker: PhantomData<(*mut u8, PhantomPinned)>,
    }
    ```
  - Expand the doc comment above the struct to declare the
    "foreign-owned opaque handle" invariant and explain why the
    `PhantomData` marker denies `Send`, `Sync`, `Unpin`.
  - Option chosen: `PhantomData<(*mut u8, PhantomPinned)>` —
    the raw-pointer component denies `Send`/`Sync`, the
    `PhantomPinned` component denies `Unpin`. Alternative
    (manual `impl !Send / !Sync / !Unpin` via negative impls)
    rejected because negative impls are unstable.
  - No consumer change: the handle is never constructed on the
    Rust side in skeleton-round bodies, and the fields stay
    private.

- `mock/crates/clause-runtime-abi/src/exports.rs` —
  - Above `clause_runtime_new`, insert a `// SAFETY-GATE:` comment
    block declaring the catch_unwind + null-input-guard
    obligations tracked in BACKLOG.
  - Above `clause_runtime_free`, same SAFETY-GATE block. (No
    null-input guard mention — `free` is documented as accepting
    null safely and has no buffer parameters.)
  - Above `clause_runtime_execute`, same SAFETY-GATE block plus
    an explicit line calling out the `(input, len)` null-input
    guard (null pointer with `len > 0` must surface as
    `ClauseResult::InvalidInput`, not a segfault).
  - Option chosen: inline `//` comments above each function, not
    module-level doc. Rationale: the gates are per-function
    invariants (each export has its own body that must pass
    them); module-level doc would drift from the call site.

### runtime-zig (R1 ABI unification + R5 stale filename)

- `mock/runtime-zig/src/runtime.zig` —
  - Remove `pub const ClauseResult = extern struct { code: i32 };`.
  - Add four named `pub const` integer constants:
    ```zig
    pub const CLAUSE_RESULT_OK: i32 = 0;
    pub const CLAUSE_RESULT_ERR: i32 = -1;
    pub const CLAUSE_RESULT_NULL_HANDLE: i32 = -2;
    pub const CLAUSE_RESULT_INVALID_INPUT: i32 = -3;
    ```
  - Change `clause_runtime_execute` return type from
    `ClauseResult` to `i32`, return `CLAUSE_RESULT_ERR` directly.
  - Update the module-level `//!` header: the text that says
    "we mirror the layout via a one-field `extern struct { code:
    i32 }`" becomes "we return the layout as a plain `i32` to
    preserve scalar-in-register calling convention symmetry with
    the Rust `#[repr(i32)] enum` on every target (MSVC Windows
    x64 would lower a one-field extern struct via hidden-pointer
    sret, breaking the match)".
  - Option chosen: scalar `i32` return + named constants. The
    alternative of flipping Rust to
    `#[repr(transparent)] struct ClauseResult(i32)` was
    considered and rejected in the doc CL (loses enum
    exhaustiveness).

  The `PhantomData` marker on `ClauseRuntime` does not affect
  any existing call site because the handle is never
  constructed on the Rust side in skeleton-round bodies.

## Rollback path

- All changes are additive (doc comments, commented `Cargo.toml`
  line, `PhantomData` field) or substitutive (`extern struct`
  → scalar `i32` on the Zig side only). Reverting the SRC
  commit undoes every change cleanly.
- If the R1 Zig change is somehow wrong on a target we don't
  CI, the rollback is symmetric: restore the `extern struct`
  wrapper and the `ClauseResult` type alias.
