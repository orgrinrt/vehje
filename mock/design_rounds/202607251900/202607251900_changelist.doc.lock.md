# Doc changelist: Project evaluation over records

**Date:** 2026-07-25
**Phase:** DOC
**Topic:** `202607251900_topic.project-evaluation-over-records.md`

One document changes: the runtime's, which is where the evaluated set and the refusal set are stated.

## `mock/runtime-zig/DESIGN.md.tmpl`

**Section: `## The evaluated set`.** Add `Project`. State the mechanics briefly: the base is the first child
word and the key a blob span in the two words after it, matching a string literal's shape, and the lookup walks
the record's alternating key and value children comparing the key bytes.

**Section: `## The evaluated set`, a paragraph on the strategy boundary.** State that the runtime implements
the dynamic lookup, and that this is the floor the measured accelerations are measured against rather than a
placeholder for them. Give the numbers (`project-field-access`: 0.54 ns compile-resolved offset, 0.61 ns
monomorphic inline cache, 1.27 ns hashed, 1.57 ns scanned) and then the reason none of them can land here yet:
each needs the record's shape known at the access site, which is a compile-side fact the emitter does not yet
produce. Name the polymorphic-site hazard the cell found, that an inline cache is the worst option there and
must detect polymorphism and disable itself rather than thrash, so that whoever builds the acceleration later
does not have to rediscover it.

**Section: `## The refusal set`.** Add projecting from a non-record and projecting an absent field, as two
distinct names rather than one.

**Section: `## Intended, not shipped`.** Remove `Project` from the remaining-Core-forms entry, leaving `Match`,
`Iter`, `Interp`, and `Handle`. Add the shape-resolution work as its own entry, owed by the compile side: a
record shape the emitter can name, which is what unlocks the fixed offset and the inline cache.

## Not in this round

Sequence indexing by a computed value, which is the dynamic-projection fork the census left open. The pattern
representation, `Handle`, `Match`, and `Iter`.
