# Topic: migrate to the mockspace launcher

**Date:** 2026-07-31
**Phase:** TOPIC
**Scope:** replace the build.rs self-bootstrap with the launcher-managed harness; rename the imported lint pack; drop the lint sections the pack no longer registers.

## Where this comes from

Mockspace retired the build-script bootstrap on its `dev` line. The old model had
every crate in `mock/` carry a `build.rs` that called
`mockspace::bootstrap::bootstrap_from_buildscript()`, which wrote
`.cargo/config.toml` (the `cargo mock` alias) and generated the proxy binary and
git hooks under `target/`. That model coupled harness installation to compiling
the consumer's own crates, meant `target/` deletion silently uninstalled the
gate, and pinned the engine through workspace `[build-dependencies]` entries in
eleven Cargo.toml files.

The replacement is the standalone launcher: `cargo-mock` (and its `mock` alias)
installed once on the machine, resolving the engine per repo from a
`mockspace_branch` pin in `mock/mockspace.toml`, caching built engines per
version, and planting durable delegate-hooks in the git config home. The engine
tombstones `bootstrap_from_buildscript()` outright: a repo still carrying the
build.rs bootstrap gets a refusal with migration steps instead of a silent
re-install, so staying on the old shape is not an option once the workspace
dependency refs advance.

## What the migration is

Three mechanical strands, all confined to harness plumbing, none touching crate
source or design docs:

First, the bootstrap teardown. Delete every `mock/crates/*/build.rs` whose only
content is the bootstrap call, remove the matching `[build-dependencies]`
`mockspace.workspace = true` entry from each crate's `Cargo.toml`, and remove
the mockspace git ref from `mock/Cargo.toml`'s `[workspace.dependencies]`.
Delete `.cargo/config.toml`, whose only content is the generated `cargo mock`
alias the launcher replaces.

Second, the engine pin. `mock/mockspace.toml` gains
`mockspace_branch = "dev"` so the launcher resolves the engine from the
mockspace `dev` line rather than the legacy Cargo.lock fallback.

Third, the pack rename. The shared lint pack renamed to
`mockspace-extra-lints` when it moved to the split lint-trait ABI; the
`[lint-crates]` entry updates to the new name against the pack repo's `dev`
branch. With the new pack in place, the engine's builtin set no longer registers
`no-bare-vec`, `no-box`, or `no-float` as standalone lints (they were subsumed:
`no_alloc` covers the first two, `no_bare_numeric` covers the third), so their
`[lints.*]` override sections name lints that no longer exist and are deleted.
The `no-bare-result` and `no-bare-string` sections stay: those lints relocated
into the pack under the same names, so the sections keep configuring them. This
is a section removal for lints that vanished upstream, not a severity change to
any live lint; the subsuming lints keep their severities untouched.

## The gate blessing this commit carries

An engine fix (mockspace PR #11) repaired inherited hook environment
(`GIT_DIR` and friends) that had been making the commit-gate lints run blind
under hooks. With the gate now actually seeing, this repo's pre-existing debt
blocks any source-touching commit in the affected crates: 902 errors,
dominated by `arvo-types-only` bare primitives in `vehje-syntax` and siblings,
the known bare-primitive history the language-completeness census already
maps.

None of that red is this migration's; it predates the change and is untouched
by it. Op blessed a per-instance `--no-verify` for this migration commit
(2026-07-31, in-session). Clearing the red belongs to the vehje ready-build
arc, and once this merges the gates enforce for real on every subsequent
source commit in those crates. This round deliberately stays at TOPIC (no
changelists): the source window could not be opened honestly while the lint
state fails, and the blessing covers the commit instead.
