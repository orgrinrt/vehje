# Doc Changelist: clause-schedule as WorkUnit home (M0.2 / #131)

**Date:** 2026-04-21
**Phase:** DOC
**Scope:** `clause-schedule` documentation templates — full rewrite
under the substrate principle.

**Source topics:**
- 202604212200_topic.clause-schedule-wu-home.md

## Purpose

Replace the pre-substrate `PassDag` / `PassRegistry` /
`Scheduler` / `Artifact` framing in `clause-schedule`'s shipping
contract with the substrate-principle framing. The crate hosts
clause-specific `WorkUnit` declarations against hilavitkutin's
shipped contract; it does not build its own scheduler. Ship a
new `BACKLOG.md.tmpl` listing the follow-up WUs this skeleton
does not yet declare, and a new `SHAME.md.tmpl` capturing the
`ClauseCtx` provider-impl skeleton gap.

Three doc-template files in total — one full rewrite + two new
files. Per the rule that `README.md.tmpl` stays terse (3-10
lines), the existing `README.md.tmpl` gets a one-paragraph
content update. Nothing else in the workspace doc surface
changes.

## Deliverables this round

### Change D1 — `clause-schedule/README.md.tmpl`: substrate framing

Keep the file 3-10 lines. The current skeleton content predates
the audit. Replace with:

```
# clause-schedule

Home for clause-specific `WorkUnit` declarations against
hilavitkutin-api's shipped contract. Hosts the `LexWU`, `ParseWU`,
`ResolveWU`, `TypecheckWU`, `CodegenWU` type skeletons plus the
`CLAUSE_PIPELINE` tuple the scheduler builder consumes.

clause-schedule does not build its own scheduler. Hilavitkutin
is the scheduler; clause-schedule is the WorkUnit home.
```

### Change D2 — `clause-schedule/DESIGN.md.tmpl`: full rewrite

Full-file replacement. New content has these sections:

- Opening prose: what the crate is under the substrate
  principle. Explicit negation: this crate does not define a
  PassDag, does not register passes, does not schedule. It
  declares clause-side WU types.
- Scope list: `LexWU`, `ParseWU`, `ResolveWU`, `TypecheckWU`,
  `CodegenWU` — five ZST WU structs each implementing
  `WorkUnit<Always>` from hilavitkutin-api.
- Column-value ZSTs: `SourceFile`, `TokenStream`, `AstArena`,
  `ResolvedBundle`, `TypedProgram`. Each satisfies
  `ColumnValue` (`Copy + 'static`). Skeleton bodies; follow-up
  rounds populate them.
- AccessSet tuple aliases: `LexRead`, `LexWrite`, `ParseRead`,
  `ParseWrite`, etc. One pair per WU.
- `ClauseCtx` ZST implementing the seven `HasX` accessor
  traits. Skeleton impls panic with `core::hint::unreachable_unchecked`
  or similar sentinel — wait, that's unsafe. Safer: panic with
  a clear message. Documented in SHAME.md.
- `CLAUSE_PIPELINE` const: 5-tuple of the WU ZSTs in DAG order.
- Dependencies: hilavitkutin-api, notko, arvo, clause-ir,
  clause-lex, clause-syntax, clause-resolve, clause-typecheck,
  clause-codegen. No arvo-graph / arvo-bitmask direct dep —
  those belong to the engine.
- Non-scope: actual execution, TranspileWU, MacroExpansionWU,
  analyzer WUs, interpreter WU, the real `ClauseCtx` provider
  impls.
- Sources: the topic file, the SUB-H0 audit memo, the parity
  plan M0.2 section.

### Change D4 — `clause-schedule/SHAME.md.tmpl`: new file

Three known-gap sections, each over 50 words, keyed by the
type the gap attaches to:

- `## ClauseCtx` — the provider impls panic because the
  scheduler composition is upstream-skeleton. Any accidental
  execution of a WU body in skeleton mode therefore triggers
  a panic rather than undefined behaviour; the skeleton is
  internally consistent because nothing composes or invokes
  the WUs yet. Tracked to the hilavitkutin engine's
  scheduler-composition gap.
- `## DiagSinkMarker` — placeholder resource for the
  structured diagnostic registry landing in #168. Real
  routing resolves there; this round holds a marker ZST so
  every WU's Read tuple has a consistent shape.
- `## SourceFile` (representative) — column-value ZSTs are
  opaque markers. Real content lands as each phase's
  follow-up round populates the type. Tracked to #136 (lexer
  feature-complete), #137 / #138 / #139 (parser), #140 (resolve
  module resolver), #148 (storage catalog).
