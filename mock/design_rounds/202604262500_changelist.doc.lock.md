## Purpose

Finalise the validator-framework Rust shape inside clause-typecheck.
Blocks clause-typecheck's impl round (Task #37). Supersedes the
Python-era Protocol-based validator registry with a tagged-union
+ compile-time-dispatch approach that matches the arvo /
hilavitkutin / clause no-dyn discipline.

## Decisions

### 1. Validator = trait + const-registered list.

```rust
pub trait Validator: Sized + Send + Sync + 'static {
    /// Canonical name used in diagnostics + suppression filters.
    const NAME: &'static str;

    /// Categorises the validator. Drives default severity + scope.
    const CATEGORY: Category;

    /// AST node kinds this validator inspects. Used by the
    /// schedule crate to route nodes to validators efficiently.
    fn accepts(&self, kind: AstNodeKind) -> bool;

    /// Check a single resolved node. Accumulates diagnostics in
    /// the sink.
    fn check(
        &self,
        node: &TypedNode,
        ctx: &ValidatorCtx<'_>,
        sink: &mut DiagnosticSink,
    );
}
```

### 2. `Category` enum.

```rust
pub enum Category {
    /// STRICT lints from the Python era: no-shadow, unused,
    /// assign-to-immut, int-overflow, use-after-move,
    /// ambiguous-imports, clippy-batch.
    Strict,

    /// Type-system invariants that must hold. Errors.
    Type,

    /// Style / naming / ergonomics. Warnings by default.
    Style,

    /// Performance advice. Info-level.
    Performance,

    /// Consumer-defined (plugin).
    Custom,
}
```

### 3. Validator registry.

Const-sized `[Option<&'static dyn Validator>; MAX_VALIDATORS]`.
Same `&'static dyn` sanctioned exception as R3's TargetRegistry.
Justification: limited to the registry iteration surface,
static-lifetime, const-sized.

```rust
pub struct ValidatorRegistry {
    validators: [Option<&'static dyn Validator>; MAX_VALIDATORS],
    count: usize,
}
```

### 4. Core vs plugin validators.

Core validators (ship in clause-typecheck):
- STRICT1 `no-shadow` — variable shadowing detection.
- STRICT2 `unused` — dead binding detection.
- STRICT3 `assign-to-immut` — immutable binding reassignment.
- STRICT4 `int-overflow` — compile-time-detectable integer
  overflow in const eval + literal contexts.
- STRICT5 `use-after-move` — move-semantics invariant check.
- STRICT6 `ambiguous-imports` — use-tree ambiguity detection
  (coordinates with clause-resolve).
- STRICT7 `clippy-batch` — a curated batch of style / bug-prone
  patterns (named after Python's clippy inspiration).

Plus type-invariant core:
- `coherence` — trait-impl overlap detection.
- `orphan-rule` — impl ownership invariant.
- `bind-target-shape` — target-language bind-type sanity.

Plugin validators: any consumer crate implements `Validator` and
registers via `ValidatorRegistry::register`. No compile-time or
runtime registry magic — registration is explicit in the
consumer's build script / main.

### 5. Suppression.

Three tiers:

1. **Per-item**: `#[allow(validator_name)]` / `#[deny(...)]` /
   `#[warn(...)]` attributes on the AST node. Standard Rust-like.
2. **Per-crate**: `[lints]` section in Clause.toml. Maps validator
   names to severity overrides.
3. **Per-workspace**: `[workspace.lints]` — fallback.

Priority: item-level > crate-level > workspace-level > category
default.

### 6. Diagnostic output.

Validators emit via `DiagnosticSink`. Each emission carries:
- The validator's NAME.
- The offending span.
- The message (rendered via a plain format string — no
  i18n this round; BACKLOG for future localisation).
- Optional related spans (for "defined here" pointers).

### 7. Severity routing.

`Category` provides default severity:
- Strict → Error
- Type → Error
- Style → Warning
- Performance → Info
- Custom → trait-provided via `default_severity()`

Overridden by per-item / per-crate / per-workspace suppression.

### 8. Scheduling.

`clause-schedule` consumes the ValidatorRegistry. For each
AST node, it walks validators where `accepts(kind)` returns true.
Sequential per-node, but per-node validator invocations are
parallelisable (future optimisation — BACKLOG).

## Per-crate doc changes

### `mock/crates/clause-typecheck/DESIGN.md.tmpl`

- Replace "Deferred to R4" section with the finalised validator
  framework shape.
- Expand module layout: `validator.rs` (trait + Category),
  `registry.rs` (ValidatorRegistry), `ctx.rs` (ValidatorCtx),
  `suppression.rs` (attribute parsing + crate config lookup),
  `severity.rs` (Category → Severity mapping), `builtin/*` (STRICT
  1-7 + coherence + orphan-rule + bind-target-shape).

### `mock/crates/clause-typecheck/BACKLOG.md.tmpl` (new)

- Per-node parallel validator execution (post-core optimisation).
- Localisation for diagnostic messages.
- Cross-crate validator dependencies (validator A queries validator
  B's outputs). Deferred until a consumer drives the need.
- Validator-specific config (e.g. STRICT4 accepts a list of
  integer types to audit — currently hardcoded to all).
- Suppression granularity beyond per-item (e.g. `#[allow(name,
  reason = "...")]` with required reason strings above a
  threshold). Already in Python; port once core lands.
