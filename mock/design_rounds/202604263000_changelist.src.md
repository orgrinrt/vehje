### clause-lex (new src)

1. `src/cursor.rs` — `Cursor<'a>` over a `&'a [u8]` with UTF-8
   peek. Methods: `peek() -> Option<char>`, `peek_byte() -> Option<u8>`,
   `bump() -> Option<char>`, `bump_byte() -> Option<u8>`,
   `pos() -> ByteOffset`.

2. `src/trivia.rs` — `Trivia { kind: TriviaKind, span: Span }`.
   `TriviaKind { Whitespace, LineComment, BlockComment }`.
   `TriviaSet` — const-sized array of leading Trivia + trailing
   Trivia (up to 8 each; excess coalesced).

3. `src/token.rs` — `Token { kind: TokenKind, span: Span, trivia:
   TriviaSet }`.

4. `src/keyword.rs` — `KEYWORDS: &[(&str, TokenKind)]` table +
   `lookup_keyword(&str) -> Option<TokenKind>`.

5. `src/lexer.rs` — `Lexer<'a>` with drive loop:
   - `next()` returns `Option<Token>`.
   - Consumes trivia (whitespace + comments), then tokenises one
     "real" token, then consumes trailing trivia up to the next
     newline.
   - Emits Eof at end.

6. `src/tokenizers.rs` — per-kind tokenisers:
   - `read_ident_or_keyword`.
   - `read_int_literal` (decimal only this round).
   - `read_operator_or_punct` — matches the longest-possible
     operator / punctuation.
   - `read_line_comment`, `read_block_comment` (non-nested).

7. `src/stream.rs` — `TokenStream<'a>` wrapping `Lexer<'a>` with
   `peek` + single-token lookahead.

8. `src/lib.rs` — `#![no_std]`, module decls, re-exports.

## Impl-time decisions (pre-committed)

1. **TokenKind exhaustive this round** even for deferred
   tokenisers. Keeps downstream consumers stable as we add
   tokenisers without AstNodeKind changes.
2. **TriviaSet is const-sized** (8 leading + 8 trailing) — excess
   trivia coalesces. No alloc.
3. **Non-nested block comments** this round — nested blocks are
   tracked in BACKLOG. Simple `{ depth }` extension later.
4. **Whitespace + comments emit as trivia, not as tokens** —
   attached to the next real token. Round-trip-safe for future
   formatter.
5. **`Lexer::next() -> Option<Token>`** returns None at EOF, but
   also emits a final `TokenKind::Eof` token so consumers can
   treat EOF as a token. Both conventions supported.
6. **Span uses byte offsets, not char offsets** — matches LSP's
   byte-based protocol; char-offset conversion is a downstream
   renderer concern.
7. **`Unknown` TokenKind** for anything the lexer can't classify
   — diagnostic emitted alongside.
