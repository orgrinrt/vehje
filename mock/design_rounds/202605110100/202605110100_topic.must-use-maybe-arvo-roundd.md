# Topic: adopt notko Maybe must_use + arvo Round D facade reshape

## Scope

Library-side mechanical adoption of two upstream changes:

1. **notko Maybe gained `#[must_use]`** (notko #15, FusedIterator + must_use round). Discarded `Maybe<T>` return values now error under `#![deny(unused_must_use)]`. Vehje's strict crate roots deny `unused_must_use`, so every `c.bump_byte()` discard site (and friends) needs explicit `let _ = ...`.

2. **arvo Round D facade reshape** (arvo #260-#268). The `arvo::newtype` module retired; `Bool`, `USize`, etc. moved to the top-level facade re-exports (`pub use arvo_storage::{Bool, USize, ...}` from `arvo::lib`). Vehje's `vehje-resolve` was the only consumer importing `arvo::newtype::Bool`; the migration is one-character-change-per-import.

## Decisions

1. **`let _ = c.bump_byte();`** for every `bump_byte()` discard. The
   semantic doesn't change: lexer-internal advance idiom never needed
   the returned byte. The explicit discard makes the must-use
   contract honest.

2. **`use arvo::Bool` (top-level)** replaces `use arvo::newtype::Bool`.
   Top-level matches the rest of the workspace (hilavitkutin /
   notko-using consumers already import `arvo::USize` via the
   top-level facade). The `arvo::newtype` path was an internal-module
   re-export that arvo retired.

3. **No must-use silence via attribute.** The deny-lint at the crate
   root is intentional (compiler discipline per CLAUDE.md). The fix
   is the explicit discard at the call site, not a lint relaxation.

4. **Library-only scope.** Tests fail under deeper arvo Round D rot
   (E0658 const-context Bits refit, test-fixture API drift). Deferring
   keeps this round mechanical and reviewable; the test rehab is its
   own focused round.
