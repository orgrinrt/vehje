# Topic: the runtime output value-transfer model

**Date:** 2026-07-20
**Phase:** TOPIC
**Round:** runtime output + lease proof. First of two topics (this one, the transfer mechanism; the sibling
`202607201316_topic.lease-proof-axis.md` adds the lease/region proof that governs ref validity in the output).
**Source study:** `mock/research/202607201227_runtime-value-transfer-study/` (five-runtime study + synthesis).

## The question

The runtime interprets a residual and produces an output value. That value can be huge and deeply nested:
full-program outputs, records within records within records, arbitrarily large trees. The value has to cross
to the host, either in-process over the runtime's C ABI (shared address space) or from the standalone
`vehje-runtime` exe writing a pipe or file (disjoint address spaces). Two naive shapes were rejected earlier:
a single encoded value written into one caller buffer (unbounded size, no room to grow the design), and a
retained runtime-side handle the host reads through accessor calls (unspecified lifetime, and a per-field
round-trip cost). The question this topic settles is what shape replaces them.

## What the study found

Five runtimes were studied independently for exactly this boundary: the .NET CLR, Lua and LuaJIT, V8 and
Deno, WebAssembly core plus its Component Model and Canonical ABI, and the zero-copy format family (Cap'n
Proto, FlatBuffers, Arrow, rkyv, the CPython buffer protocol, JNI). The full reasoning and per-runtime
citations live in the study directory; `synthesis.md` there is the consolidated argument. The five converge,
and the shape they converge on is the shape vehje's residual already is.

The value graph crosses as one flat, self-describing, index-referenced buffer, not as a host object graph
materialized field by field and not as per-field accessor calls. Its internal links are relative (indices or
offsets), never absolute pointers, so the same bytes are the zero-copy in-process representation and the
verbatim wire form written down a pipe. Scalars skip the buffer and cross by value; bulk byte runs cross as a
shared region, never re-serialized. Bounded residency for enormous outputs is a matter of streaming with
backpressure, never a bigger buffer. Bytes that crossed a process boundary are untrusted and get a
bounds-checked validation pass before they are walked. The moving-garbage-collector machinery that every
dynamic runtime carries (V8 handles, Lua's stack-by-index, JNI critical regions, .NET pinning) does not
transfer, because vehje's arena never relocates, and that absence is the single biggest simplification vehje
gets for free.

## Decisions (settled with op, 2026-07-20)

The output is a value-arena: fixed-width value-node records, a flat child-index pool, and a self-contained
byte blob, with relative index links, the same structural family as the residual `wire.rs` format, reused for
produced values instead of IR. It is a closed, versioned record layout with no vtables, because vehje owns
both the producer and the reader and has no cross-version schema-evolution problem to solve. It is
tier-orthogonal: a future bytecode or native tier emits the same value-arena a tier-0 interpreter does.

The backing memory is host-lent up front. In whole-value mode the host provides the region and the runtime
writes the arena into it, holding no output memory after `_execute` returns. This is not merely preferred; the
no-alloc discipline forces it, because the runtime cannot own or grow an output heap, and it makes the lease
trivial since the host owns the bytes throughout. This was chosen over a runtime-scratch region handed back
with a release call.

The transfer contract is a two-function sink: `reserve(hint)` lends the runtime a writable window and blocks
under backpressure, `commit(n)` declares how many bytes of value-arena were written. It is one protocol for
both boundaries. In-process the sink is a `#[repr(C)]` struct of two function pointers plus an opaque
userdata, which is an FFI wire shape at the C ABI boundary, not a `dyn` object. Out-of-process the sink is the
exe's stdout pipe, where the operating system pipe buffer is the backpressure. This unifies what were two
separate open questions (the in-process result contract and the exe's input/output shape) into one sink. The
runtime serializes the value depth-first, children before parents, so a parent records already-known child
indices with no back-patching. Whole-value mode is the degenerate case of the same protocol where the window
is large enough to need one `reserve`.

For outputs that exceed a residency budget, streaming chunks at whole-subtree boundaries. Each chunk is a
self-contained mini value-arena that walks and validates on its own, and a parent refers to an
already-emitted child by a (chunk, index) pair, so nothing dangles across chunks and a chunk can be dropped
once its parent has consumed it. This was chosen over a flat record-window that would force the reader to
retain earlier windows to resolve links.

The untrusted path (the subprocess reader, or any host reading bytes that crossed a process boundary) runs a
bounds-checked traversal, proving every child index and blob offset is in range and the graph is
depth-bounded, before or while walking. The in-process path, where the runtime produced the bytes in the same
address space, may skip it.

## Named deliverables

The value-arena format specification and its encoder live in `vehje-runtime-abi`, mirroring the residual's
`wire.rs` and `encode.rs`. The `VehjeSink` reserve/commit contract and the stdout-pipe sink for the exe live
there too. A safe reader over the value-arena, the analogue of rkyv's archived types or a Cap'n Proto reader,
lives in `vehje-runtime-driver`, lifetime-scoped to the borrow. The bounds-checked validation pass sits over
the value-arena for the untrusted path.

## Open threads for this round (to settle before the doc changelist)

The exact value-node-kind schema (what value forms exist in the arena) is deliberately out of scope here; op
sequenced it as a separate follow-up round, and this topic designs the container and transport generically
over a tagged record, the way the residual node format is already generic. The interaction with the lease
proof axis (region tags in the arena format, and how the sink transports region-tagged bytes) is settled in
the sibling lease topic, not here. What remains genuinely open for the transfer mechanism itself: whether the
whole-value region is sized by the host up front with streaming as the overflow path (the current lean) or
ever benefits from a runtime-scratch variant, which is bench-decidable if it becomes contentious.
