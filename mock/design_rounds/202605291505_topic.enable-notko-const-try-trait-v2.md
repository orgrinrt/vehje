**Scope:** enable notko's `const` and `try_trait_v2` features in the vehje workspace, alongside the nightly-2026-05-28 toolchain pin already on this branch.
**Source:** workspace decision to align consumers with the stack's notko feature set (`const` + `try_trait_v2`) and to enable notko's `try_trait_v2` so its `?`-on-`Maybe`/`Outcome`/`Just` impls compile in consumer builds; notko PR #23 + arvo #69 + hilavitkutin #95 (all merged) landed the try_trait_v2 core-bound adaptation upstream.

vehje has no `core::ops::Try` impls of its own, so the recent core `Try::Residual: Residual<Self::Output>` bound change did not break vehje directly; its earlier build failure was transitive through arvo, now fixed on arvo dev. With fixed arvo + notko pulled, the full vehje workspace (lib + all test targets) compiles clean on `nightly-2026-05-28`.

vehje currently takes notko with `default-features = false` and no features, so it gets neither `const` (notko's default-on const-trait machinery) nor `try_trait_v2`. The rest of the stack (arvo, hilavitkutin) uses `["const", "try_trait_v2"]`.

## Decision

Set the vehje notko dep to `features = ["const", "try_trait_v2"]` in `mock/Cargo.toml`. `const` aligns vehje with the stack's const-trait fallibility surface (ConstTry / ConstFromResidual / Slot const methods). `try_trait_v2` transitively enables notko's `try_trait_v2_residual` rustc gate, so notko's fixed `Try` + `Residual` impls compile inside vehje's build. Pull the merged notko + arvo dev tips into the lockfile.

## Consequences

- Cargo.toml is a SRC-phase (gated) change in mockspace, so it lands via the src CL.
- The `rust-toolchain.toml` pin to `nightly-2026-05-28` is already committed on this branch (not gated); the PR bundles both.
- No source-type changes; this round is build-config only.
