## Purpose

Ship the codegen crate scaffolding for Clause: the
`CodegenTarget` trait, the `TargetRegistry` with the R3-sanctioned
`&'static dyn CodegenTarget` exception, two built-in target ZST
stubs (`NativeTarget` + `JominiTarget`), a `CodegenCtx` carrier,
`CodegenArtifact` + `ArtifactKind` payload types, a `CodegenError`
enum, and a top-level `emit` entry that forwards to the registry.

This is the skeleton pattern: each target's `emit` body returns
an `Ok(CodegenArtifact { kind: Binary, bytes: Vec::new(),
diagnostics: Vec::new() })` (not `todo!()`, so the registry does
not panic in tests). Every concrete backend — real LLVM/cranelift
lowering for `NativeTarget`, Clausewitz bytecode for
`JominiTarget` (in the future `clause-jomini` sibling repo) —
lands as its own follow-up round on top of this stable harness.

Without this round, clause-codegen is a nuked stub; with it,
downstream phases (the `clause` binary driver, future
`clause-jomini` extension) have a concrete target surface to
route work through, and each deferred backend ships in isolation.

## Scope adjustment vs R3

R3 finalised a richer trait shape (associated consts `NAME` /
`VERSION`, `accepts(kind)` node routing, `stages()` pipeline
entry, `compile(unit, ctx) -> Result<CodegenOutput, Diagnostic>`
with full `CodegenOutput { bytes, manifest, references }` payload,
`render_diagnostic(err) -> Diagnostic` error rendering). This
skeleton round lands a narrower instance-method trait that still
satisfies the R3 invariants at the registry surface:

- `name(&self) -> &'static str` — the NAME access point.
- `emit(&self, &CodegenCtx) -> Result<CodegenArtifact, CodegenError>`
  — the emission entry.

`Stage`, `accepts`, `VERSION`, `ManifestFragment`, `SymbolRef`,
`TargetError` rendering, and cross-target reference resolution
are deferred to follow-up rounds that land real target backends.
The instance-method form works in a `&dyn CodegenTarget` registry
directly; associated-const variants require `const-in-trait` or
an object-safe shim and can be retrofitted without touching
consumers once the registry walks real backends.

This mirrors exactly the R4 → clause-typecheck skeleton pattern
(202604263700): one round to establish the stable harness, one
follow-up round per deferred feature.

## Deliverables this round

### clause-codegen — trait + registry

- `CodegenTarget` trait (`src/target.rs`):
  ```rust
  pub trait CodegenTarget: Sync {
      fn name(&self) -> &'static str;
      fn emit(&self, ctx: &CodegenCtx) -> Result<CodegenArtifact, CodegenError>;
  }
  ```
- `CodegenCtx<'a>` carrier (`src/ctx.rs`) — holds
  `resolved: &'a Resolved` only this round. Future fields
  (diagnostic sink, artefact cache, workspace info, per-target
  config) are BACKLOG.
- `TargetRegistry` (`src/registry.rs`) — hosts
  `pub const TARGETS: &[&'static dyn CodegenTarget] = &[...]` with
  two entries plus `lookup(name) -> Option<&'static dyn CodegenTarget>`
  and `emit_for(name, ctx) -> Result<CodegenArtifact, CodegenError>`.

### clause-codegen — two target stubs

Each is a ZST struct with `CodegenTarget` implemented; body
returns the empty `CodegenArtifact` (`kind: Binary`, `bytes:
Vec::new()`, `diagnostics: Vec::new()`).

- `src/native.rs` — `NativeTarget` — name `"native"`. Placeholder
  for future Rust/LLVM or cranelift backend.
- `src/jomini.rs` — `JominiTarget` — name `"jomini"`. Placeholder
  for the future `clause-jomini` sibling repo extension that
  emits Clausewitz engine script for Paradox games.

### clause-codegen — payload + error types

- `src/artifact.rs` — `CodegenArtifact { kind: ArtifactKind,
  bytes: Vec<u8>, diagnostics: Vec<Diagnostic> }` plus
  `ArtifactKind { Binary, Object, Assembly, SourceFile, Config }`.
  `CodegenArtifact::empty(kind)` constructor returning zero-byte
  payload.
- `src/error.rs` — `CodegenError { TargetNotFound { name },
  UnsupportedFeature { feature }, LoweringFailed { message },
  NotImplemented }`. Each variant carries a `&'static str` where
  a string is needed (host-side is fine, but static avoids
  allocation churn for this thin error surface).

### clause-codegen — entry point

- `emit(resolved: &Resolved, target_name: &str) ->
  Result<CodegenArtifact, CodegenError>` in `src/lib.rs`. Builds
  a `CodegenCtx`, forwards to `TargetRegistry::emit_for`.

### Tests (`clause-codegen/tests/`)

- `tests/target_trait.rs` — 4 tests:

  - `jomini_name_matches` — `JominiTarget.name() == "jomini"`.
  - `native_emit_empty_artifact` — empty resolved → `Ok` with
    empty bytes + empty diagnostics.
  - `jomini_emit_empty_artifact` — same for `JominiTarget`.
- `tests/registry.rs` — 5 tests:
  - `registry_has_two` — `TARGETS.len() == 2`.

  - `registry_lookup_missing` — `lookup("bogus")` is `None`.
  - `registry_emit_for_missing` — `emit_for("bogus", ctx)`

## Deferred (BACKLOG, one follow-up round per entry)

### Deferred target implementations (each a follow-up round)
- NativeTarget — Rust/LLVM codegen via inkwell or cranelift.
- JominiTarget — Clausewitz engine bytecode (used by
  clause-jomini when it exists).
- Possible future targets: WebAssembly, Python bytecode, Lua.

### Deferred framework features
- IR lowering (Resolved → internal IR → target-specific lowering).
- Optimisation passes between IR and codegen.
- Target-specific diagnostics (per-target error recovery).
- Per-target config — `Clause.toml` `[codegen.target_name]`
  subsection.
- Incremental codegen (cache artifacts by IR hash).
- R3-shape retrofit — associated `NAME` / `VERSION` consts,
  `accepts(kind)` routing, `stages()` entry, `CodegenOutput`
  with `manifest` + `references`. Lands once real backend bodies
  surface the need.

### Non-blocking follow-ups
- Extension loading — dynamic targets via dlopen / DLL (for
  `clause-jomini` as a runtime plugin).
- Cross-compilation target triples.
- Debug info emission.
- Stage reordering via topological sort (carried from R3 BACKLOG).
- Target-provided lints (carried from R3 BACKLOG).
- SymbolRef cross-target resolution (carried from R3 BACKLOG).
- Multi-target parallel codegen (carried from R3 BACKLOG).
