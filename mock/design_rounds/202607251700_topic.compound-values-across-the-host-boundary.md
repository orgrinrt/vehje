# Topic: compound values across the host boundary

**Date:** 2026-07-25
**Phase:** TOPIC
**Scope:** `vehje-runtime-abi` (the operand contract), `runtime-zig` (the value model and the marshalling), `vehje-runtime-driver` (the mirrored host surface).
**Oracle:** the canon (`mock/research/canon/`), the completeness census (`mock/research/202607251530_language-completeness-census.md`), and the measured cells named below.

A family operation can currently receive a scalar or a string and return the same. That is the single widest
constraint in the framework right now, and the census located why: content-as-values makes construction a
family concern, so the Core has no record-building form by design, which means a record, a sequence, a tuple,
or an enum variant cannot be produced by any program until a handler can return one. `Project` is not blocked
on `Project`; it is blocked on there being records to project from. Every compound entry in the census's
mapping table resolves with this one extension.

This round settles how a compound crosses the host boundary, and what the runtime holds it in.

## The decision: a compound crosses as a value image, and there is no second format

The value image already exists, is already the format a produced value crosses back in, and its tag vocabulary
already names `Seq`, `Record`, and `Outcome` alongside the scalars. So the compound operand needs no new
encoding: it crosses as a value image whose root is the subtree being passed.

This falls out of a decision already taken rather than being a new one. When the operand record was widened
for strings it was given a `bytes` pointer plus a length in `payload`, with the note that one record serves
both a scalar and a string so the common case does not grow. A compound uses that identical convention: the
tag says compound, `bytes` points at a value image, `payload` is its byte length. **The ABI record does not
change shape at all.** The same holds in the return direction: a handler writes a value image into the session
scratch it was already lent for returning strings, and reports it the same way.

The property this preserves is the one the canon states for the scalar tags, that one vocabulary describes a
value wherever it appears. A second marshalling format for the host boundary would have been a second thing to
keep in sync with the wire, a second thing to validate, and a second place for the two to drift. The value
image is already an untrusted-input decoder with every index and span bounds-checked and acyclicity proven by
one monotone check, because children emit before parents. Reusing it means a compound arriving from a handler
is validated by the same code that validates a value crossing back to the host, rather than by a second
decoder written to the same spec and trusted to agree.

## What the runtime has to grow

The Zig runtime's `Value` is a union of unit, boolean, integer, string, and closure. It needs a compound case,
and a compound case needs somewhere to live, because unlike a string literal a produced record is not a slice
into the residual.

That is a runtime value arena, and it is caller-lent in the same shape as the environment arena the closure
work already introduced: the host lends the space, the runtime bump-allocates within it, and the runtime owns
none of it when the call returns. A record is a node in that arena with its fields in a child pool, which is
the same shape the value image describes, so materialising a returned image is a walk rather than a
translation.

## What the measurements decide about its shape

Three cells constrain this and are the reason the round is worth doing once rather than twice.

**Operands go inline, not through a pool indirection.** `value-arena-throughput` measured a pool-indirected
walk at 10.7 ns per node against 4.4 ns for inline operands, and attributed the difference to the indirection
itself rather than to transport. The arena's node record carries its operands inline.

**Values stay raw bytes. No interning, no deduplication.** Both of the optimisation mandate's interning
candidates were measured and refused for this exact domain. `string-interning` found interning a constructed
string 2.2x to 3.1x slower across three regimes, including the regime built specifically to remove the bias
that flattered the do-nothing strategy. `dedup-vs-reuse` found record deduplication 9x to 19x slower than
reuse and 6x to 7x slower than doing nothing. So the arena stores values plainly and the round adds no hash
table to the runtime.

**Reuse is the optimisation that goes in, and it excludes the other two.** In-place update when the emitter
proves a value unique is confirmed by two independent cells, at 2.7x to 2.9x over copy-on-write in the
mostly-unique regime and never losing. The exclusion is structural and is the reason the two cannot both be
defaults: a deduplication table holds a reference to every value it contains, so **the table is itself a
referrer**, and interning a value permanently forfeits reuse on it while still charging the hash at
construction. Measured, the combination is worse than doing neither.

The round does not build the reuse analysis; that needs the emit-time uniqueness verdict, whose derivation
from the lease masks is still only intended. What the round must do is leave room for it: the arena's update
path is written so that a per-site uniqueness bit selects in-place against copy, with copy as the behaviour
until the bit exists. That is the safe direction of the switch. A residual emitted with reuse bits and run by
a runtime ignoring them is coherent, since ignoring the bit means copying, which is always safe; the reverse
is not, since a runtime asked to reuse without a verdict has nothing to read.

## Boundaries this round holds

`Project` evaluation is deliberately not in this round even though it becomes possible with it. The field
access strategy is already settled by measurement (a compile-resolved offset at 0.54 ns where the shape is
static, a monomorphic inline cache at 0.61 ns otherwise, against 1.27 ns hashed and 1.57 ns scanned), so it is
a well-specified follow-on rather than an open question, and keeping it separate keeps this round's claim
about the boundary auditable on its own.

The pattern representation and `Handle`'s clauses stay deferred; both are named in the census with their own
rounds owed, and neither is a prerequisite here.

A closure remains unrepresentable as a value image and continues to be refused by name. It names an
environment inside the run, so it has no arena-independent form, and the refusal is the honest answer rather
than a gap.

## What lands

The operand contract gains a compound form on both sides of the ABI without changing the record's shape. The
Zig runtime gains a caller-lent value arena and a compound `Value` case, marshals a compound operand out as a
value image, and materialises a returned one back in through the existing validating decoder. The driver
mirrors the host surface. Named refusals cover an undersized arena and a malformed returned image, so a
handler that returns something the runtime cannot accept is distinguishable from one that failed.
