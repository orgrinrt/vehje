# Doc changelist: runtime-ABI soundness fixes

Doc-template edits for round `202607240530` (source topic
`202607240530_topic.runtime-abi-soundness-fixes.md`). Documents the wire record layout the value-arena
review found undocumented, states that the value-node records carry a declared `#[repr(C)]` layout, and
refreshes two stale SHAME no-std entries.

## vehje-runtime-abi/DEEPDIVE_VALUE_TRANSPORT.md.tmpl

- State that the value-node records (`ValueNode` and the `ValueList`, `BlobSpan`, `Region`, `ValueTag`
  it composes) carry an explicit `#[repr(C)]` layout (and an explicit small discriminant on `ValueTag`),
  so the "wire form equals the in-process form" claim has a declared, stable layout the runtime can read
  zero-copy. The exact discriminant width and the host-native-versus-cross-platform question are flagged
  open (see the topic).
- Name the input-record wire layout at `BatchColumn.records` as an explicitly-open wire-spec item: the
  batched column entry passes W records, and the deep dive currently describes the descriptor but not the
  per-record byte layout the host writes and the runtime reads. State that the per-record layout is an
  undecided wire-spec detail (flagged for op alongside the discriminant-width and host-native-versus
  cross-platform questions), so a consumer knows it is owed rather than silently absent. The layout is not
  invented here.

## vehje-runtime-abi/DESIGN.md.tmpl

- Note `ValueArena::try_get` alongside `get`: `try_get` is the bounds-checked accessor returning
  `Maybe<ValueNode>` for the untrusted path; `get` is the trusted-path accessor, valid only after
  validation, and its precondition is stated in source.

## vehje-runtime-abi/SHAME.md.tmpl and vehje-runtime-driver/SHAME.md.tmpl

- Refresh the no-std entries that drifted from current source, so the known-gaps record matches what the
  crates actually do today.
