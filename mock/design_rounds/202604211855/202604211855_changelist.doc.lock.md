# Doc Changelist: clause collections sweep

**Date:** 2026-04-21
**Phase:** DOC
**Scope:** `clause-syntax`, `clause-typecheck`, `clause-runtime-driver`,
`clause-codegen` — doc templates only.

**Source topics:**
- 202604211855_topic.collections-sweep.md

## Purpose

Update the shipping-contract templates for the four clause crates
whose public return-type or trait-method signatures shift from
`Vec<T>` to `&mut impl DiagnosticSink<E>` / `&mut impl ByteEmitter`.
The `clause-resolve` struct-field drift (`Vec<Scope>`,
`HashMap<String, Symbol>`, `Vec<Maybe<Symbol>>`, `Vec<String>`)
stays untouched this round — those ride with the #73.3 primitives
sweep because their shape is tangled with `Str` interning.

## Deliverables this round

### Change D1 — `clause-syntax/DESIGN.md.tmpl`: parse signature

Line 28 updates:

```
- `parse(tokens: &[Token]) -> Outcome<Ast, Vec<SyntaxError>>` —
+ `parse(
+     tokens: &[Token],
+     errors: &mut impl DiagnosticSink<SyntaxError>,
+ ) -> Outcome<Ast, ()>` —
```

Prose below the signature stays. The "future multi-error
recovery" narrative now fits inside the sink, which is what the
R4 BACKLOG promised.

### Change D2 — `clause-typecheck/DESIGN.md.tmpl`: validator trait + run_all

Line 68 — trait method:

```
- fn validate(&self, ctx: &ValidatorCtx) -> Vec<Diagnostic>;
+ fn validate(
+     &self,
+     ctx: &ValidatorCtx,
+     sink: &mut impl DiagnosticSink<Diagnostic>,
+ );
```

Line 88 — `ValidatorRegistry::run_all`:

```
- pub fn run_all(ctx: &ValidatorCtx) -> Vec<Diagnostic> { /* ... */ }
+ pub fn run_all(
+     ctx: &ValidatorCtx,
+     sink: &mut impl DiagnosticSink<Diagnostic>,
+ ) { /* ... */ }
```

The surrounding narrative that refers to "empty diagnostic vec"
as the round-one output updates to "sink left empty".

### Change D3 — `clause-typecheck/BACKLOG.md.tmpl`: R4 retrofit note

Line 42 — the BACKLOG note that describes the current narrower
skeleton shape against the R4 richer shape:

```
- trait (`name(&self)`, `validate(&self, ctx) -> Vec<Diagnostic>`)
+ trait (`name(&self)`, `validate(&self, ctx, sink)`)
```

The `&'static dyn`-registry-iteration commentary continues to
apply — the trait remains object-safe.

### Change D4 — `clause-runtime-driver/DESIGN.md.tmpl`: execute signature

Line 25:

```
- `execute(&self, &[u8]) -> Outcome<Vec<u8>, DriverError>`
+ `execute(&self, input: &[u8], output: &mut impl ByteEmitter) -> Outcome<(), DriverError>`
```

No other narrative changes. Callers allocate the byte sink;
DlopenHandle (BACKLOG) will forward through the sink.

### Change D5 — `clause-codegen/DESIGN.md.tmpl`: emit + CodegenArtifact

Two lines change.

Line 48 — the richer R4 `compile` method:

```
- ) -> Outcome<CodegenOutput, Diagnostic>;
+ ) -> Outcome<CodegenOutput, Diagnostic>;
```

Actually unchanged — `CodegenOutput` is an R4 BACKLOG shape that
already assumes richer contract; only the skeleton shape moves.

Line 65 — skeleton `CodegenTarget::emit`:

```
- fn emit(&self, ctx: &CodegenCtx) -> Outcome<CodegenArtifact, CodegenError>;
+ fn emit(
+     &self,
+     ctx: &CodegenCtx,
+     bytes: &mut impl ByteEmitter,
+     diagnostics: &mut impl DiagnosticSink<Diagnostic>,
+ ) -> Outcome<CodegenArtifact, CodegenError>;
```

Line 91 — the `CodegenArtifact` payload description:

```
- `CodegenArtifact { kind, bytes, diagnostics }` is the skeleton
- payload. R3's fuller `CodegenOutput { bytes, manifest,
- references }` is BACKLOG.
+ `CodegenArtifact { kind }` carries only the artifact tag this
+ round; bytes and diagnostics flow through caller-provided sinks
+ (`ByteEmitter` / `DiagnosticSink`). R3's fuller
+ `CodegenOutput { bytes, manifest, references }` is BACKLOG.
```
