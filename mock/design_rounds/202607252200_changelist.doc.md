Five documents describe the surfaces this round changes: the Core's forms and arena, the two passes that gain a

## `mock/crates/vehje-ir/DESIGN.md.tmpl`

**The Core forms.** Add `Perform { op, args }` as a thirteenth form. State the reason in the register the
twelfth was admitted in: `Handle` is an eliminator and nothing built a term it could eliminate, which is an
incompleteness in the algebra rather than a census gap, since the free model is generated by the operation
symbols and the handler is the homomorphism out of it.

State why it is not `Raw`: arithmetic lowers to `Raw`, and an effect on `1 + 2` is a grade the handler
discipline would then have to subtract everywhere. The rejection is on typing, not ergonomics, and saying so
keeps a future reader from re-proposing it as an ergonomic simplification.

State that the operation identity is a freshly minted `Sym` rather than a dense id, and what that buys:
labelled `break` and labelled `continue` fall out with no additional mechanism, and an unlabelled `break` binds
to the innermost enclosing handler because that is the first frame whose clause list matches.

**The arena.** Add the clause region as a fourth caller-lent region beside nodes, spans, and pool. Give the
clause record its five fields and say why each is authored rather than derived, particularly that `arity` is
not recoverable by counting lambda nesting because a body may return a lambda. Name the cost honestly: the host
sizes and lends one more buffer.

State the two rejected placements with their costs, because both look cheaper than they are. The child pool
holds node references, so an operation identity in it is a pun. A non-evaluating node variant would make four
term-walking passes each acquire a skip rule.

**The `Handle` doc comment's third item is wrong and gets corrected here.** It says a clause carries an
operation, a body, and the discharge. The discharge is which stage provides the handler, which is the
binding-time coordinate the grade already owns, so it is derived, not authored. Two things are authored.

## `mock/crates/vehje-resolve/DESIGN.md.tmpl`

Add the handler scope chain: a `Handle` pushes its clause operations, a `Perform` resolves its operation
against that chain, and the resolution side-table records the perform against the handling `Handle`. State that
resolution is lexical and what that means, namely that no evidence vector is threaded through calls, and that
static binding is the safe choice as well as the cheap one because it stops a caller's operation being caught
by a callee's handler.

## `mock/crates/vehje-typecheck/DESIGN.md.tmpl`

**The effect scope chain.** State that a lexically handled `Perform` contributes nothing to the effect mask in
the first place, so the mask is only ever populated by operations that genuinely escape. Say why this
formulation rather than subtracting a mask at the `Handle`: subtraction is unsound when two operations share a
slot, and this avoids the question. This retires the standing subtraction FIXME.

**The escape rule, as an axis interaction.** `Perform` is not a value, so a direct escape is impossible by
construction; the residual case is a lambda whose body performs, returned out of the `Handle` and called
later. State the rule in two halves: a promotion at `Lambda`, where the body's unhandled operations become the
lambda value's reach of the corresponding handler slots, which is the latent effect on the arrow; and a check
at `Handle`, where the result's reach must not contain the handler's slot.

Say what this is, because it is the most consequential sentence in the round: **the first genuine
effect-and-lease interaction rule in the system**, which is what the canon says the graded spine owes before
the word theorem is earned. Label it `intended`, not proven.

**Two error variants become real.** `ForbiddenEffect` and `UnplaceableLease` are both declared and never
constructed today. Say which obligation constructs each.

**The slot collision.** State that it over-approximates reach, so it costs a false refusal and never a false
acceptance, which is why the mechanism can land before the mask widens and why widening is an accuracy fix
rather than a soundness one.

## `mock/runtime-zig/DESIGN.md.tmpl`

**The evaluated set** gains `Perform` and `Handle`, `intended` until the src CL lands.

**The carrier.** State that `eval` returns a carrier rather than a bare value, that the carrier propagates
rather than jumping, and why that is a correctness constraint rather than a preference: a future `finally` or
resource-release clause must run code at each frame the unwind passes, which a propagated carrier can do and a
direct jump cannot. State that the choice between a value-or-unwind union and a sentinel plus an out-parameter
is a hot-path question to be benched rather than asserted, and that the propagation property is what is not
negotiable either way.

**What an exit costs.** No allocation; integer compares bounded by handler nesting depth; nothing copied,
because a string is a slice into the residual blob or the session scratch, a compound is an index into the lent
value arena, and the environment arena never pops so every binding a captured value names is still live after
the unwind. State the inversion plainly: the never-pop discipline that reads as a cost is what makes the unwind
free.

**The loop bound, stated as a limitation rather than omitted.** The loop encodings are correct denotationally
and unusable operationally: the environment arena bumps and never pops against 1024 lent slots, so a loop body
with `k` bindings terminates with an exhausted-arena refusal after roughly `1024 / (k + 1)` iterations; and a
closure body is evaluated by native recursion that is not in tail position, so a self-recursive loop grows the
native stack. Name both fixes as owed (a trampoline, and reclaiming an iteration's bindings, which needs the
escape the reach mask computes) and say plainly that this round delivers early exit, not unbounded iteration.

**The refusal set** gains the unhandled perform and the clause that references its resumption.
