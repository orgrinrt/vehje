# Src changelist: compound values across the host boundary

**Date:** 2026-07-25
**Phase:** IMPL
**Doc CL:** `202607251700_changelist.doc.lock.md`
**Topic:** `202607251700_topic.compound-values-across-the-host-boundary.md`

The doc CL locked three claims: the operand record serves a third shape without changing its own, a compound
crosses as a value image in both directions so the boundary has one decoder, and a compound lives in a
caller-lent value arena whose record carries operands inline, stores values plainly, and leaves room for a
uniqueness bit it does not yet have. This changelist executes them.

The lending pattern already in the file is the one to follow: `evalImage` takes the environment arena as a
caller-lent `[]Binding` slice and the export provisions it from a fixed buffer. The value arena is lent the
same way, so the round adds no new lifetime shape.

## CHANGE: `value_image.zig` GAINS a tree writer beside `writeScalar`

File: `mock/runtime-zig/src/value_image.zig`
Today the module writes one scalar image (`writeScalar`, `scalarLen`, `intPayload`). A compound needs a writer
that emits a whole subtree: nodes children-before-parents so a parent records indices it already knows, then
the pool, the region table, and the blob, matching the pinned layout exactly.

Add `writeTree(out: []u8, arena: *const ValueArena, root: u32) WriteError!usize`, refusing a too-small buffer
without a partial write, as `writeScalar` already does.
Verification: `grep -n "pub fn writeTree" mock/runtime-zig/src/value_image.zig` returns one match, and a Zig
test round-trips a two-field record through `writeTree` and back.

## CHANGE: `value_image.zig` GAINS a reader for an untrusted image

File: `mock/runtime-zig/src/value_image.zig`
Materialising what a handler returned needs a reader, and it is reading untrusted bytes. Every index and span
is bounds-checked against the image, and acyclicity is the one monotone check the children-before-parents
emission order buys: a child index must be strictly below its parent's.

Add `Reader` with `parse(bytes) ReadError!Reader`, `nodeCount`, `root`, `node(i)`, `child(list, k)`, `blob(n)`,
and `validate()`. `ReadError` names its own failures rather than collapsing them.
Verification: `grep -n "pub const Reader" mock/runtime-zig/src/value_image.zig` returns one match; tests cover
a truncated header, an out-of-range child index, and a parent-before-child ordering violation, each rejected by
name rather than read past the end.

## CHANGE: `runtime.zig` GAINS `ValueArena` and `ValueNode`

File: `mock/runtime-zig/src/runtime.zig`
The arena is caller-lent and bump-allocated, never freed within a run, mirroring `Env`. Its node record carries
its operands inline rather than through a pool indirection, which is the measured shape (10.7 ns per node
pool-indirected against 4.4 ns inline).

Add `pub const ValueNode` (tag, inline operands, a child span, a blob span) and `const ValueArena` with
`slots: []ValueNode`, `pool: []u32`, `len`, and an `alloc` that returns `EvalError.ValueArenaFull` when the
lent space is exhausted.
Verification: `grep -n "const ValueArena" mock/runtime-zig/src/runtime.zig` returns one match; a test proves an
undersized arena refuses by name rather than overrunning.

## CHANGE: `Value` GAINS a compound case

File: `mock/runtime-zig/src/runtime.zig:70`
FROM `union(enum) { unit, boolean, int, str, closure }`
TO the same plus `compound: u32`, an index into the value arena.
Verification: `grep -n "compound: u32" mock/runtime-zig/src/runtime.zig` returns one match.

## CHANGE: `EvalError` GAINS `ValueArenaFull` and `BadImage`

File: `mock/runtime-zig/src/runtime.zig:81`
A returned image the reader rejects has to stay distinguishable from a handler reporting failure, which is the
property the doc CL locked. `BadImage` is that distinction.
Verification: `grep -n "ValueArenaFull\|BadImage" mock/runtime-zig/src/runtime.zig` returns both.

## CHANGE: `toOperand` GAINS the compound shape

File: `mock/runtime-zig/src/runtime.zig:156`
FROM a pure function of `Value`
TO one that also takes the arena and the session, because writing a compound out means writing an image into
the session scratch. A compound operand reports the image pointer in `bytes` and its byte length in `payload`,
which is the string convention generalised, so `VehjeOperand` does not change shape.
Verification: `grep -n "fn toOperand" mock/runtime-zig/src/runtime.zig` shows the widened signature; a test
asserts a record operand's `tag` is the value image's record tag and that its bytes parse as an image.

## CHANGE: `fromOperand` GAINS materialisation of a returned image

File: `mock/runtime-zig/src/runtime.zig:167`
A compound tag means `bytes` is a value image of `payload` length. Parse it with `Reader`, validate it, then
walk it into the value arena, returning `Value{ .compound = root }`. A rejected image is `BadImage`; an arena
too small is `ValueArenaFull`.
Verification: a test has a host return a two-field record and asserts the program's value is that record;
another has the host return a deliberately malformed image and asserts `BadImage`.

## CHANGE: `evalImage` and `vehje_runtime_execute` THREAD the value arena

File: `mock/runtime-zig/src/runtime.zig:377`, and the export below it
`evalImage` gains the lent `[]ValueNode` and `[]u32` beside the existing `[]Binding`, and the export provisions
them from fixed buffers exactly as it already provisions `slots`. The C ABI entry signature does not change,
so the driver's `ExecuteFn` type is untouched.
Verification: `cargo test -p vehje-runtime-driver` still compiles against the unchanged entry types.

## CHANGE: the produced-value crossing HANDLES a compound root

File: `mock/runtime-zig/src/runtime.zig`, the sink marshalling path
A program whose value is a record must cross back as a whole image rather than a scalar one, which is what
`writeTree` is for. The closure refusal stays exactly as written.
Verification: a Zig test runs a program whose value is a record and asserts the committed bytes parse and
validate as an image whose root is a record.

## CHANGE: `Operand` in the driver DOCUMENTS the compound shape

File: `mock/crates/vehje-runtime-driver/src/runtime.rs:39`
The `#[repr(C)]` record is already correct for a compound, since a compound uses the string convention. The
change is its doc comment, which currently says the tag covers unit, boolean, integer, or string. It must name
the compound shape too, or the type lies about its own contract.
Verification: `grep -n "compound" mock/crates/vehje-runtime-driver/src/runtime.rs` returns a match in the
`Operand` doc comment.

## CHANGE: a driver test PROVES a compound round-trips

File: `mock/crates/vehje-runtime-driver/src/runtime/tests.rs`
An end-to-end test in the existing `#[ignore]` style: a Rust host services a family operation by returning a
two-field record, the Zig runtime materialises it, and the driver reads it back with `ValueImage`, asserting
the root is a record with the two expected fields.
Verification: `cargo test -p vehje-runtime-driver --features dynamic -- --ignored` passes with the artifact
built.

## Not in this round

`Project` evaluation, the pattern representation, `Handle`'s clauses, and the reuse analysis itself. The update
path is shaped so a uniqueness bit can select in-place against copy, and copy is the behaviour until that bit
exists; nothing in this round produces the bit.
