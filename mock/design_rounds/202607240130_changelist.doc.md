# Doc changelist: the converged design and the twelve-crate taxonomy

**Date:** 2026-07-24
**Phase:** DOC
**Round:** runtime output + lease proof
**Oracle:** `202607240100_topic.consolidated-design-and-taxonomy.md` (the closing design statement) plus the
full-arc bench findings `202607240015`. Every doc edit below realises that statement.

This changelist rewrites the full documentation set from the pre-round shape (eleven forms, the
`Pure`/`Reads`/`Writes` effect lattice, the program-centric tier-tagged residual, native-as-a-tier, the two-sides
framing) to the converged design (the two-artifact model, twelve Core forms, the graded proof spine, the effect
and binding-time split, reachability leases, the value-arena and batched-column ABI, the incremental scaling
mechanism, and D1 through D7). It also lays down the doc templates for the four new framework crates and the
`vehje-typecheck` to `vehje-check` rename, so the source phase implements against a complete doc set.

The tiering discipline (per the workspace documentation rule) governs every file: the rendered public surfaces
(the root README, each crate's rendered docs, rustdoc) carry no workspace-internal vocabulary (no mockspace, no
design-round references, no cross-repo paths); the `DESIGN`, `BACKLOG`, `SHAME`, and `DEEPDIVE` templates are
contributor-facing and may reference the design internals. DESIGN documents describe the shipping contract
(backticked types the source phase makes real); BACKLOG holds the designed-but-deferred pieces (unbackticked);
SHAME holds known gaps.

## Root documents

Rewrite the top-level architecture design to the converged shape. Sections: the identity (framework, type system
as the verification layer, certified generation, serving a consumer spectrum); the two-artifact model (dev-time
Rust language compiler emitting validated data plus structural proofs, shipped Zig composed runtime specialised by
comptime, Rust emits data not Zig source); the compile pipeline (parse, resolve, check, lower, discharge, emit)

inclusion-not-coverage, the output spectrum); the incremental scaling mechanism (D6) and the framework-scope rule
(D7, core plus mechanism only); the twelve-crate taxonomy with the dependency layering; and the foundations reused
(arvo, notko, hilavitkutin). Retire the "two sides / tier-tagged residual / build-env-reduced-away" framing.

## New crates (create README, DESIGN, BACKLOG, SHAME; the source phase creates the crate dirs and source)

### `vehje-fixpoint` (new)

README and DESIGN: the generic, `vehje-ir`-free, no-alloc semi-naive relational-fixpoint engine with congruence,
over caller-provided columnar storage (the hilavitkutin-api contracts as vocabulary, arvo graph and bitmask as

mechanism and its bench evidence, the compile-stage-brain role. DEEPDIVE_INCREMENTAL_SCALING: the D6 mechanism, the
content-addressed keying, the host-owns-policy boundary.

### `vehje-lower` (new)

README and DESIGN: the lowering stage, the cheap runtime subset (const-fold, CSE by hash-consing, bounded single

### `vehje-runtime-gen` (new)

README and DESIGN: runtime generation, the validated-data package (family table, effect masks, lease-rule schema,
