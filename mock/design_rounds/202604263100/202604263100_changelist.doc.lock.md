## Purpose

Ship the parser crate scaffolding for Clause: the type surface,
the parser driver loop, and a minimal `parse` entry point that
handles the two trivial programs (empty input, single literal).
This is the saalis-style skeleton pattern — land the harness,
defer every grammar production to follow-up micro-rounds.

Without this round, clause-syntax is an empty crate; with it,
downstream phases (clause-resolve, clause-typecheck, clause-codegen)
have a concrete `Ast` + `NodeId` arena to key work off, and each
deferred production (binary expressions, blocks, items, patterns,
…) ships as an isolated round on top of a stable harness.

## Deliverables this round

### clause-syntax — type surface

- `Ast` — root container with a flat arena of `AstNode`s and a
  root `NodeId`. Lookups via `NodeId` index. Arena push returns
  `NodeId`.
- `AstNode { kind: AstNodeKind, span: Span, children: [NodeId; N] }`
  — kind and span pulled from `clause-ir`; children are arena
  indices. Const-sized child array this round (arvo-style, no
  alloc); a single literal node has zero children. Larger nodes
  (blocks, calls, structs) extend this in their own rounds.
- `NodeId` re-exported from `clause-ir`.

### clause-syntax — parser driver

- `Parser<'a>` — holds `&'a [Token]` plus cursor state (current
  index, one-token lookahead) and an `Ast` under construction.
- `Parser::new(tokens: &'a [Token]) -> Self`.
- `Parser::parse(self) -> Result<Ast, SyntaxError>` — drives the
  minimal grammar this round implements.
- Peek / bump helpers for the follow-up rounds to consume.

### clause-syntax — errors

- `SyntaxError { span: Span, kind: SyntaxErrorKind, message:
  &'static str }` — `Copy`. Message is `&'static str` so the
  whole error is alloc-free, matching `clause-ir::Diagnostic`.
- `SyntaxErrorKind { UnexpectedToken, UnexpectedEof,
  InvalidLiteral }` — exhaustive for the shapes this round's
  parse paths actually produce; further kinds added per round.
- `From<SyntaxError> for Diagnostic` — converts to the shared
  diagnostic surface so the compiler driver can merge syntax
  errors into its diagnostic pipeline without re-keying.

### clause-syntax — entry point

- `parse(tokens: &[Token]) -> Result<Ast, SyntaxError>` —
  top-level function. This round handles:
  - Empty slice OR slice of `[Eof]` → `Ok(Ast::empty())`.
  - Slice of `[IntLit, Eof]` → `Ok(Ast)` with one `Expr` node
    whose kind is `AstNodeKind::Expr` and span covers the lit.
  - Anything else → `Err(SyntaxError { kind: UnexpectedToken,
    … })`.

Everything else (identifiers, operators, statements, items,
blocks, …) is `UnexpectedToken` for now — follow-up rounds flip
the switch production-by-production.

### Tests (`clause-syntax/tests/`)

- `empty_input.rs` — parses `[]` and `[Eof]`, verifies `Ast` is
  empty.
- `single_literal.rs` — parses `[IntLit, Eof]`, verifies the
  AST has exactly one node, kind `Expr`, span matches.
- `unexpected_token.rs` — parses `[Plus, Eof]` (and a couple
  more), verifies `SyntaxErrorKind::UnexpectedToken`.
- `ast_types.rs` — `AstNode` construction, `Ast::push` returns
  monotonic `NodeId`s, `Ast::get` round-trips, `NodeId` is
  `Copy + Eq`.

Target 8–12 tests total across those files.

## Deferred (BACKLOG, one follow-up micro-round per entry)

- Primary expressions: identifier path. (Literal path landed.)
- Binary expressions (precedence climbing).
- Unary expressions (prefix `-`, `!`, `&`, `*`).
- Call expressions + argument lists.
- Block expressions.
- Let / assignment statements.
- If / match expressions.
- Function definitions + parameter lists.
- Type annotations.
- Struct / enum definitions.
- Module / import declarations.
- Pattern syntax.
- Error recovery (synchronise on `;`, `}`, top-level keywords).
- Incremental reparse for IDE workflows.

Each of these is a self-contained round: add the grammar
production, add a test file, land it. The skeleton harness does
not change.
