# Doc honesty: label shipped-vs-intended state per the second-direction audit

**Date:** 2026-07-24
**Phase:** TOPIC.
**Source:** the second-direction audit `mock/research/202607241700_second-direction-audit.md` (Stephen Dolan, fresh-eyes doc-claim-vs-source walk, not a FIXME walk), which the canon Section 11 flagged as owed.

The canon's contract is docs = design (trusted), source = untrusted (a catching-up approximation), so a DESIGN doc stating the intended design ahead of the source is correct and expected. The audit did not find that contract violated in spirit. It found a narrower, real problem: several DESIGN and DEEPDIVE docs state a designed-but-unbuilt mechanism in the present tense with no state label, so a reader on a first pass takes it as shipped. The canon itself already uses an assurance-verb discipline (proven / demonstrated / measured / intended) and a "State:" label convention for exactly this (its own `vehje-runtime-gen` Manifest bullet self-corrects), but several docs predate or missed that convention, and one paragraph this consolidation round added (the `vehje-lower` recursive-macro terminator) states an entirely unbuilt mechanism in the present tense with no hedge. This round makes those docs honest without changing a single design claim's substance: it re-tenses to "intended / designed to" or adds a "State:" label, matching the canon's own preamble ("Intended means design not yet realised").

This is a doc-only round. No source changes. It does not build the missing mechanisms; it labels them, which also produces the explicit owed-worklist the implementation rounds work through (each implementation round removes a "State:" label by building the thing).

## The overclaims to label (from the audit gap map)

Each gets a "State:" label or a re-tensing to the intended mood. The design claim is unchanged; only its shipped-vs-intended status is made explicit.

- **`vehje-lower/DESIGN.md.tmpl`** (audit items 7, 8). The `MacroExpand` bullet ("its effect is discharged here, so the residual carries no unexpanded macro") and the whole "Recursive macros are supported" paragraph (the three-layer terminator, the default-255 depth cap, static cyclicity detection) describe unbuilt machinery: `MacroExpand::apply` is a no-op, no depth-cap constant exists, `vehje-signature::Operation` has no productivity-condition field, and no cyclicity sketch exists. Re-tense to the intended mood and add a State label naming these as owed (the fold_core catamorphism, the productivity-condition field, the cyclicity sketch). This corrects a present-tense overclaim added in the canon consolidation round itself.
- **`vehje-schedule/DESIGN.md.tmpl`** (audit items 15, 16, open question 1). The doc describes a working DAG scheduler (registration, read/write sets, `arvo-bitmask` adjacency, `arvo-graph::topo_sort`, cycle diagnostics); the source is three near-empty stub types (`Pass` is `pub trait Pass: Debug {}`, `PassDag` a unit struct, `Schedule::build` returns success unconditionally). Do NOT flesh the stubs to match: the crate's own DESIGN hedges that it "folds into the orchestrator if family passes turn out to be handler instances of the compile-stage effect discipline," and the canon's handler discipline (macros and family passes are compile-stage-effect operations the compile stage handles) is direct evidence that dissolution is live, not remote. So mark the crate's DESIGN as describing a contingent, possibly-dissolving mechanism whose stubs are intentionally unbuilt pending the unification question, with a State label. Building a full scheduler that may be deleted is the non-reversible call; labeling is the reversible one. The unification question (does the scheduler dissolve into the handler discipline) is a design call to resolve before any build here, flagged for op or a design round, not settled by fleshing the stub.
- **`vehje-codegen/DESIGN.md.tmpl`** (audit item 13). The "Module layout" section names `target.rs` / `check.rs` / `fold.rs` / `compose.rs` / `error.rs`; only `lib.rs` exists, and `compose.rs`'s described compile-time target composition is unwritten with no FIXME. Re-frame the module layout as the intended layout (not a present-tense file list), and add a State label that target composition is owed (tracked as the distribution-composition item below).
- **`vehje/src/lib.rs` module doc** (audit item 14). "...the distribution-composition entry point that links a set of targets at compile time" states a present-tense mechanism that does not exist and carries no FIXME. This is a source doc-comment (so it belongs to the src side); label it in the src CL of a later round or add a FIXME. For this doc round, note it in the owed-worklist; the DESIGN-doc side (`vehje/DESIGN.md.tmpl`) gets the State label.
- **`vehje-fixpoint/DESIGN.md.tmpl`** and its crate doc comment (audit items 10, 11). The DESIGN describes `Engine::evaluate` dispatching between whole-column and semi-naive-delta strategies; the source ships whole-column only and its own FIXME (`engine.rs`) names the exact DESIGN sentence it falls short of. Re-tense the dual-strategy sentence to the intended mood with a State label (whole-column ships, the delta strategy is owed). The crate-level doc comment calling the crate "semi-naive" is a source doc-comment for a later src CL, noted in the worklist. Also add the bench-provenance note: the 8M/16M/50ms figure comes from a standalone Zig prototype (`reach.zig`), not from a harness run against the Rust `Engine`; state that scope so a reader does not read it as a measurement of the shipped crate.
- **Canon Section 4** (audit item 9). The relational-fixpoint conviction states present-tense that the engine "serves lease inference and load verification" with no State label, unlike its sibling convictions. The canon topic is closed and frozen (cannot edit), so this is not corrected in place; instead the `vehje-fixpoint/DESIGN.md.tmpl` label above carries the honest state (the engine is built but has zero consumers today; wiring it to lease inference is owed), and a future canon-supersession note records the lapse. The engine-has-no-consumers fact is the load-bearing correction.
- **`vehje-typecheck/DEEPDIVE_GRADED_SPINE.md.tmpl`** (audit item 19). "the check pass can ship the concrete grade computation now... the shippable core is the grade enums, the bitmask joins, and the inclusion checks" reads as the whole judgment shipping; in source, `effect` and `lease` are computed but `binding` and `assurance` are hard-coded constants. Add a per-axis State label: two of the four grade coordinates are computed, two are constants (owed).
- **`vehje-typecheck/DEEPDIVE_GRADED_SPINE.md.tmpl`** (audit item 20). "The differential test ships (as the runtime-generation differential harness)" overclaims: `DifferentialCheck` is a one-field contract type and its own FIXME says the runner is owed. Re-tense to the intended mood with a State label (the contract type ships, the harness runner is owed).
- **`vehje-runtime-driver/DESIGN.md.tmpl` / module doc** (audit item 22). The crate's identity ("the one framework crate with a `std` role, for the dlopen of the runtime artifact") states a present-tense mechanism entirely future (dispatch ignores its argument, libloading is commented out, `std` is an empty feature). Add a State label that the dlopen/std role is designed and owed; the module-doc-comment side is a later src CL.
- **`vehje-runtime-gen/DESIGN.md.tmpl` Manifest bullet** (audit item 4). Minor: the first clause ("a content-addressed byte-image hash of each slice and of the whole package") reads as shipped, and the same bullet self-corrects three sentences later that the interim is a whole-package byte hash only. Tighten the first clause so the "of each slice" part carries its owed status inline rather than only in the later sentence.
