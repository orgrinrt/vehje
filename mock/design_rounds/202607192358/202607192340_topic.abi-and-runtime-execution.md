**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** What crosses the compiler/runtime boundary, in what representation, how the Zig runtime executes it,
and where the compile-time / runtime evaluation line falls. The last contract topic of the round.
**Continues:** the contract-spine topics (identity, input, output/exhaustiveness/effect, crate surface,

## The boundary, restated

The compiler is Rust; the runtime is Zig; they meet at a C ABI defined and validated in Rust (canon posture,
`.claude/CLAUDE.md`). The compiler reduces a program to a `Checked` residual whose effect set is proven
included in the runtime's `Permits` (no `BuildEnv`-parametrized effect survives, per the output-side effect
model). The residual is what crosses. The runtime executes it against the runtime environment. The compiler is
the only thing that ever touches build state; the runtime is the only thing that ever touches live runtime
inputs and outputs.

## What crosses: a tier-tagged residual, not one fixed representation

Op's decision (2026-07-19): the residual crosses as a **flat serialized IR arena** as the baseline, but the
representation is **tiered**, with the door held open for a faster form and, ideally, native code. The ABI
does not hardcode one representation; it carries a tier-tagged artifact plus the runtime-environment interface,
and the runtime dispatches on the tier. The three tiers, lowest to highest:

1. **IR arena (baseline, always available, the reference semantics).** The residual is the `vehje-ir` arena
   serialized as-is: one contiguous buffer of `u32`-indexed `#[repr(C)]` nodes, the `EntityList`/`ListPool`
   side-tables for variable-arity children, a string-arena blob, and a root node id. The Zig runtime walks the
   same node layout it was handed. Nothing is lowered; the residual *is* the wire form. This tier defines the
   reference execution semantics every higher tier must match, and it is the tier the first working version
   ships.
2. **Optimized bytecode (faster interpretation).** The residual lowered to a linear stack or register bytecode
   the Zig runtime runs on a small VM. Smaller wire size, better decode locality, a faster inner loop than
   tree-walking the arena. This tier is an optimization, authored after the baseline works; it is not on the
   first-working-version path, but the ABI reserves its tier tag now so adopting it later is additive.
3. **Native code (the ideal endgame).** The residual compiled to native machine code for the host, through an
   LLVM or cranelift backend (this is the "native target" consumer, realized as the top execution tier). At
   this tier the Zig runtime's role collapses to **environment plumbing**: it sets up the runtime environment,
   marshals inputs and outputs, exposes the host-call surface the residual is allowed to touch, and calls into
   the native code. This is the same shape as a Rust binary, where the language runtime is thin plumbing around
   LLVM-emitted code rather than an interpreter. Zig is the C-ABI-fluent, no-`std` host that stitches the
   native residual to its environment.

The tier is an **optimization axis orthogonal to correctness**. The effect proof (`residual.effects ⊆
Permits`, no `BuildEnv`) is discharged in Rust *before* lowering to any tier, so choosing a tier changes only
execution speed, never semantics or the safety contract. A residual is the same proven-safe object whether it
crosses as an arena, as bytecode, or as native code; lowering to a higher tier is a faithful re-encoding of an
already-checked artifact. This is why the baseline can ship first and the higher tiers slot in behind the same
ABI without reopening the contract.

### Why arena-first, not bytecode-first

The IR arena is already the residual's in-memory form: `vehje-ir` stores `u32`-indexed nodes plus `EntityList`
side-tables in an arena. Serializing it is a memcpy of that arena plus the string blob, and deserializing on
the Zig side is pointing at the same `#[repr(C)]` layout. There is no second IR to design, version, or prove
the effect contract against, and no lowering step to be a source of a determinism bug. Bytecode and native are
genuine wins for execution speed, but each adds a lowering surface that must be shown to preserve the reference
semantics the arena tier defines. Getting the arena tier correct first gives every higher tier a reference to
validate against.

## The compile-time / runtime evaluation split (derived, not chosen)

The split is fully determined by the effect axis; it is not an independent decision. Everything parametrized
over `BuildEnv` is the compiler's; everything parametrized over `RuntimeEnv` is the runtime's.

The **compiler (Rust)** always performs, before emitting any residual: lex and parse (via the consumer's
grammar), lower to IR, resolve and check over the shared Core plus families, and **reduce every
`BuildEnv`-parametrized effect away**. That reduction is where constant evaluation, macro expansion, registry
and manifest queries, `self`-context reads, and build-resource reads happen. Const-eval and macro expansion
are compile-time regardless of anything else, because they are `BuildEnv` reductions by nature: a macro
expands against build state, a const folds at build time. The output is the `Checked` residual, provably free
of any `BuildEnv` effect.

The **runtime (Zig)** only ever executes the residual against the runtime environment: it reads
`RuntimeEnv` inputs, writes `RuntimeEnv` outputs, and performs whatever runtime-tier host calls the residual's
effect set permits. It never implements build-env semantics, holds no registry, and cannot reach `self` or
build resources, because the effect proof guarantees no such construct is present in what it receives. The
runtime is small by construction: its whole job is the runtime-env side of the effect axis.

## Runtime crate shape

Three pieces, following the crate surface already settled:

`vehje-runtime-abi` (Rust) defines the tier-tagged C ABI and the residual serialization. It owns the
`#[repr(C)]` node layout shared with Zig, the arena/string-blob/root-id wire struct, the tier tag enum, and the
runtime-environment interface descriptor (the permitted host-call surface a residual may touch). It ships the
tier-0 serialization first; the tier-1 and tier-2 encoders are added behind the same tier tag when those tiers
are built. Per its lint scope it is the ABI surface only: no syscalls inside it, they belong above or below.

`vehje-runtime-driver` (Rust) is the compiler-side dispatch over the ABI: it takes a `Checked` residual,
serializes it at the chosen tier, hands it to the runtime, and embeds or links the Zig runtime artifact.

The **Zig runtime** itself is a separate build artifact (Zig source compiled to a static library the driver
links, pulling no `std` and no Rust runtime, per canon). It provides, in tier order: the tier-0 arena
interpreter first (the first-working-version execution engine), then the tier-1 bytecode VM, then the tier-2
native-code environment plumbing. All three present the same runtime-environment contract to the residual;
they differ only in how they execute it. The first working version needs only the tier-0 interpreter; the
higher tiers are optimization work that lands behind the already-stable ABI.
