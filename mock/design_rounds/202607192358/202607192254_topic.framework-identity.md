# Topic: vehje is the framework, not a language

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** The identity of vehje itself, settled before the extension-point contract can be shaped. Continues
the round opened by `202607190650_topic.extension-point-contract.md`.
**Reference:** `mock/research/202607190650_mockspace-procedural-docs-arc/` (imported, reference only).

## The reframing

The prior canon, in `mock/DESIGN.md.tmpl` and the agent instructions, opens by calling vehje "a
general-purpose scripting language for game modding and embeddable runtimes". Op corrected this
(2026-07-19): vehje is not that language. Vehje is **the framework for embedded, multi-input, multi-output
IR**. The rich general-purpose scripting language that the old canon conflated with vehje itself, the one
carrying traits, impls, generics, coherence, the orphan rule, events and manifests, is a **first-party
consumer of vehje, name to be decided later**, on equal footing with `vehje-jomini`, `vehje-w3`,
`vehje-ts4`, `vehje-lua` and the rest.

This resolves the tension the extension-point topic left open. That topic worried that a shared core sized at
nine forms was far too few because "vehje's language has traits, impls, generics, coherence". Under the
reframing that worry dissolves: those constructs are not the framework's, they belong to one consumer's
family. The framework core stays small; consumer richness lives in consumer families that extend it.

## What this settles

**vehje is a framework.** Its surface is a shared IR representation, the machinery to lower into it and fold
out of it, an embeddable runtime, and the two contracts by which a grammar plugs into the input side and a
target plugs into the output side. It is not a language and ships no first-party surface syntax as part of
the core.

**The general-purpose language is a consumer, named later.** The traits/generics/coherence language is one
grammar among the consumer census, authored against the same contract as every other grammar. Its name is
deferred; until then it is "the first-party general-purpose language".

**Core shape: open families, with typestate carrying the exhaustiveness.** There is a small shared Core (the
evaluation/expression forms every grammar lowers into, in the low tens, matching Racket ~15 and Jsonnet ~15),
but the family set as a whole is **open**, not a closed universe. A family is a type. Each consumer
contributes its own families (Core is one, a Doc family is another, the first-party language contributes its
trait/generic/coherence families, jomini contributes routing families). New families are new traits, added
without touching existing passes.

The guarantee is **inclusion, not coverage**: a program carries a type-level set of the families it uses, a
target declares a type-level set of families it supports, and emission is bounded on the target's set
containing all of the program's. Openness therefore costs nothing, because inclusion does not need a closed
universe. This is stronger than closed-enum coverage: a target legitimately declares a smaller set, and a
program using something outside it is refused with the construct named, never silently degraded (Pandoc's
failure mode). The single typed escape hatch (Scribble's `convertible?` negotiation form) is the one open
point where a value offers the representations it can be and the target takes what it understands.

The mechanism is the `AccessSet` typestate already shipped in `hilavitkutin-api/src/access.rs` (sealed
`AccessSet` over `Empty`/`Cons<H, T>`, `Contains<S>`, `ContainsAll<L>`, `Concat`), reused with vehje family
marker types as members. Two-stage, discipline compile-time throughout: statically known terms discharge
`ContainsAll` at compile time; runtime-parsed programs compute a family bitmask checked against the target's
const bitmask in one bitwise op, gated so `emit` accepts only a `Checked<T>` that only the check produces.
This corrects `07_toolbox.md`/`06_prior_art.md`, which recommended a closed core and called the check "a pass
to write, not free"; that priced the framework cost in C++/Scheme terms (MLIR TableGen, nanopass ~4600
lines), and in Rust the trait system is the ODS: a family is a trait, its dependencies are supertraits, so
that cost does not transfer. The authoritative sketch is `08_decisions.md` §2. The full output-side spine is
in `202607192310_topic.output-side-contract.md`.

## Consumer census, restated under the reframing

Ten known consumers of the framework, differing in kind, not degree:

1. **The first-party general-purpose language** (name TBD): traits, impls, generics, coherence, the orphan
   rule, events, manifests. The rich one the old canon mistook for vehje itself.
2. **`vehje-jomini`**: Clausewitz script across five Paradox titles. Text emission with routing metadata.
3. **`vehje-w3`**: Witcher 3 script.
4. **`vehje-ts4`**: Sims 4.
5. **`vehje-lua`**: generic Lua; a program with its own control flow survives into the output.
6. **The native target**: LLVM or cranelift lowering to machine code.
7. **polka** (polka-dots): a procedural-dotfiles language, config and content mixed with logic.
8. **ikiuni's first-party scripting language**: engine-embedded, evaluated inside a game loop. Makes the
   embeddable runtime load-bearing rather than optional.
9. **viola's first-party lint authoring language**: lints compiled against viola's plugin surface.
10. **mockspace's procedural-documents language**: registry-queried documents reduced to markdown, terminal,
    html. The consumer that prompted the arc, not the one that shapes it.

## Still open (next topics in this round)

framework's own crate surface, given the current crates are shaped like a single language's compiler
