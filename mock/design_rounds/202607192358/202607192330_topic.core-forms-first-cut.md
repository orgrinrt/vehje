## What Core is, and what it is not

Core is the shared evaluation substrate every grammar lowers into: general evaluation primitives, closed, in
the low tens, matching Racket (~15 expression forms) and Jsonnet (~15 after total desugaring). A consumer uses
the subset it needs; a docs DSL touches few forms, the first-party language touches most. The line against a
family form is sharp: a Core form is a general evaluation primitive (apply, if, iterate); a family form is a
language-specific construct (a trait declaration, a Clausewitz route, a coherence obligation). Surface
conveniences (`::` chaining, `where`, method-call form, object comprehensions) desugar totally into Core and
the Core never learns they existed (Jsonnet's discipline).

Environment access is not new Core forms. A `self`-context read is a `Project` into a context binding; a
registry query is an `Apply`/`Project` into a provided binding. What marks them build-time versus runtime is
the effect axis, not a dedicated form. So the Core stays about evaluation shape; effects carry the staging.

## Core forms (first cut, 11)

1. **`Lit`**, a literal value. Two-tier value domain (05_correction_and_aim): fixed scalars and enums inline
   via arvo primitives; variable text and arrays as an `(offset, len)` handle into the generation-time byte
   arena, itself `Copy`. One form; the payload distinguishes.
2. **`Var`**, a reference to a binding. A name pre-resolution, a resolved binder handle post-resolution.
3. **`Let`**, bind name(s) to value(s) in a scope for a body, with a recursive flag (Racket splits
   `let-values`/`letrec-values`; one form plus a flag is the no-alloc-friendlier shape).
4. **`Lambda`**, abstraction: parameters plus body. Fragments, closures, functions all lower here.
5. **`Apply`**, application: callee plus arguments. Method calls, `::` chaining, `where`, object
   comprehensions all desugar to `Apply` (and `Project`).
6. **`Project`**, field/member/index access: base plus key. `t::id`, `foo.bar`, `arr[i]` lower here.
7. **`If`**, conditional: cond, then, else. The staging-preserved emitted form of a two-arm branch (both arms
   survive into residual code) is `If` under an emit policy.
8. **`Match`**, pattern match: scrutinee plus arms (pattern to body). Destructuring patterns do not desugar to
   `If` cleanly, so `Match` stays a Core form rather than sugar. Consumers without matching (Clausewitz, docs)
   simply never use it.
9. **`Iter`**, iteration producing a monoidal accumulation of values or content. Content must be a monoid
   (Typst `#for`, Scribble list accumulation) or a loop over markup degrades to string concatenation. Earns
   itself where per-row output is prose or a chosen shape rather than a filtered table projection.
10. **`Interp`**, interpolation of a value into text or content (`{t::id}` inside a literal). Kept a distinct
    form rather than desugared to `Apply(concat, ...)` because the staging rule attaches to it: an
    interpolation hole inside otherwise-emitted code is generation-time by what a hole means (decision 1's
    safe local inversion). The staging semantics need the form to be nameable.
11. **`Raw`**, the one typed escape hatch (Scribble's `convertible?` negotiation): a value offers the
    representations it can be, the target takes what it understands, the mismatch is visible. The single open
    point in an otherwise closed Core.

### Flagged choices inside the cut

- **No `Seq` form.** Carmack's finding: stream concatenation satisfies the content monoid without `Seq` being
  a semantic form, so a sequence of values is `Iter` accumulation or nested `Apply(concat)`, not a Core node.
  Kept out unless a consumer need surfaces that concatenation cannot serve.
- **`Match` as Core, not family.** Borderline (only some consumers match), but destructuring is general
  evaluation and does not desugar away cleanly, so it earns a Core slot rather than being re-invented per
  matching language.
- **`Interp` as a form, not sugar.** The staging rule is the reason; if staging did not attach to it, it would
  desugar to `Apply(concat)`.

## Doc family constructors (first cut, a family not Core)

The document algebra is a **family**, used only by document-emitting consumers (mockspace-docs, and any future
doc target), not part of Core. Pandoc's shape at roughly 14 block and 19 inline constructors, twenty years in
production, is the size guide. Block: `Para`, `Heading`, `CodeBlock`, `BlockQuote`, `BulletList`,
`OrderedList`, `DefinitionList`, `Table`, `Div`, `ThematicBreak`, `RawBlock`. Inline: `Str`, `Emph`, `Strong`,
`Code`, `Link`, `Image`, `Span`, `Math`, `SoftBreak`, `HardBreak`, `RawInline`. Attributes uniform on every
node (Djot's improvement over Pandoc's per-constructor decision). Content is a monoid so `Iter` over markup
composes. This list is deferred detail; it lands when the first doc consumer is designed, and it is a family,
so it does not gate Core.

## Effect lattice (ratified: parametrized, not enumerated)

`Pure`, `Reads<E>`, `Writes<E>`, where `E` ranges over an open environment axis (`BuildEnv`, `RuntimeEnv`, and
any later env kind). `Pure` is the empty effect set. This is op's directed shape (2026-07-19), replacing the
flat four-member first cut (`ReadsBuildEnv` / `ReadsRuntimeEnv` / `WritesRuntimeEnv`). Computed from what a
form references, decidably. LMS's fixed-width effect summary is still the runtime shape: a concrete `Reads<E>`
/ `Writes<E>` at a fixed `E` is a distinct `'static` marker, so an effect set is a small `Cons`-list of them,
and the runtime's permitted set lowers to a bitflag, not a heap structure.

Parametrizing subsumes the `WritesBuildEnv` question this file first flagged as an open omission. There is no
fifth member to reserve or defer: `Writes<BuildEnv>` already exists in the type space, expressible the moment a
consumer needs build-time registry mutation, at no cost to the lattice. A new environment kind is likewise a
new marker type, not a widening.

The Rust-to-Zig residual contract restates as a set inclusion, identical in shape to the family check: the
runtime declares a `Permits` effect set of runtime-tier effects (containing no `BuildEnv`-parametrized member),
and the residual's effect set must be included in it. Every `Reads<BuildEnv>` / `Writes<BuildEnv>` is proven
reduced away before emission. The full statement is in `202607192310_topic.output-side-contract.md`.

## Why these sizes are right

Every shipped many-in/many-out system froze a small core and left it frozen (07_toolbox's table: Racket 15,
Jsonnet 15, Pandoc 14+19, WebAssembly 4 types). Eleven Core forms plus a separate ~25-constructor Doc family
plus a two-verb parametrized effect vocabulary (`Reads<E>` / `Writes<E>` over a handful of env kinds) sits
squarely in that band, on separate axes (evaluation model, document structure, effect summary) exactly as the
survey says a system needing all three must count them. The effect axis is the smallest of the three by count
precisely because parametrization does the widening that a flat lattice would spend members on.
