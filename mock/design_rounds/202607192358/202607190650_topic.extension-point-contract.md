# Topic: the extension-point contract

**Date:** 2026-07-19
**Phase:** TOPIC
**Scope:** How a grammar plugs in on the input side and a target plugs in on the output side, over a shared
representation. The round `mock/DESIGN.md.tmpl` names as owed and never held.
**Reference:** `mock/research/202607190650_mockspace-procedural-docs-arc/`, imported. Read its README first;
its numbers are measured against a different workload and its framing inverted vehje with one consumer.

## Why this round exists

`mock/DESIGN.md.tmpl` states the extension pattern and then defers its contract:

> Game-specific targets land as separate repos that extend Vehje: `vehje-jomini`, `vehje-w3`, `vehje-ts4`,
> `vehje-lua`. **The extension point contract is TBD (one of the first session's design rounds).**

That round never happened. Reading `mock/design_rounds/`, every round after the rename to vehje is
maintenance: a doc audit, review fixes, a `must-use` sweep, two test rehabs, a codegen doc fix, and a
build-config change. Meanwhile the shipped code has moved ahead of the design: `vehje-codegen` ships a
`CodegenTarget` trait and a `TargetRegistry`, with `NativeTarget` and `JominiTarget` as stubs, so the
implementation already promises an extension point whose contract is unwritten.

The agent instructions carry the standing consequence: do not inline game-specific vocabulary, types, or
codegen into this repo, because it makes the core extraction harder later. Every day without the contract is
a day that instruction is enforced by discipline alone.

## Current state, verified

Counts and quotes below are from the working tree at this round's date, with the command that produced each.

**The IR has no expression vocabulary.** `vehje-ir/src/nodes.rs` declares `AstNodeKind` with nine variants:
`File, Item, Fn, Let, Expr, Pat, Type, Block, Unknown`. `Expr` is a single variant, so an expression is
currently an undifferentiated category, and `Unknown` is a placeholder.
(`sed -n '/pub enum AstNodeKind/,/^}/p' vehje-ir/src/nodes.rs | grep -cE "^\s{4}[A-Z]"` gives 9.)

**The lexer is not generic over its token kind.** `vehje-lex/src/lexer.rs:45` declares `pub struct
Lexer<'a>`, with the token vocabulary fixed in `vehje-ir/src/tokens.rs`. A second input grammar cannot
reuse it as written.

**The output extension point exists in code, not in design.** `vehje-codegen` declares `pub trait
CodegenTarget: Sync` with a `name()` discriminator and an emit method that walks `ctx.resolved()` and
pushes bytes plus diagnostics. `JominiTarget` and `NativeTarget` are declared. `mock/DESIGN.md.tmpl` says
only that codegen is target-agnostic.

**`vehje-lex`, `vehje-ir` and `vehje-syntax` are `no_std` and no-alloc**, per the generated lint rules.

## What the contract must serve: the full consumer census, stated loudly

Op's correction (2026-07-19): the extension pattern was never only the game targets. The known consumer
set spans the whole workspace, and the design has under-stated it from the start. Canonically, vehje's
extension-point contract serves:

1. **`vehje-jomini`.** Clausewitz script across five Paradox titles (Stellaris, CK3, HOI4, Vic3, EU4).
   Text emission with routing metadata, manifest management, save-compatibility machinery.
2. **`vehje-w3`.** Witcher 3 script target.
3. **`vehje-ts4`.** Sims 4 target.
4. **`vehje-lua`.** Generic Lua emission: a program with its own control flow survives into the output.
5. **The native target.** LLVM or cranelift lowering to machine code, named in the shipped backlog.
6. **polka** (polka-dots). A procedural-dotfiles language: config and content mixed with logic. Related in
   spirit to the mockspace use case, a different take entirely.
7. **ikiuni's first-party scripting and authoring language.** Engine-embedded, evaluated inside a game
   loop. This consumer alone makes the embeddable runtime load-bearing rather than optional.
8. **viola's first-party lint authoring language.** Lints authored in vehje, compiled against viola's
   plugin surface.
9. **mockspace's procedural-documents language.** Registry-queried documents; generation-time reduction to
   markdown, terminal and html. The consumer that prompted this round, not the one that shapes it.

Nine families, and they differ in kind, not degree. Game-script transpilation, generic language emission,
native compilation, procedural configuration, engine-embedded runtime scripting, lint authoring, and
document generation. Some targets preserve control flow, some reduce it away entirely; some evaluate at
build time, one evaluates every frame. Any contract that fits most of these and strains on the rest is the
wrong contract, and any representation shaped by one consumer's corpus is wrong by construction.

## Decisions recorded (op, 2026-07-19)

**The Zig runtime gets built now, and consumers embed it.** Not deferred until a game target needs it. The
current 67-line stub goes on the critical path deliberately: mockspace embedding it over the C ABI is the
first proof of embeddability, and the ikiuni consumer requires it regardless. This executes the canon's
two-language strategy rather than revisiting it.

**The Python prototype carries little weight.** Op's call, direct: it is stale Clause-era work and is not
an oracle for vehje. It stays as greppable history and informs nothing structurally. Canon corrections owed
when this round reaches DOC phase: `mock/DESIGN.md.tmpl` still names it "a parity oracle", the
`mock/agent/` templates still carry "Python prototype is oracle" in the generated banner, and the stated
path (`~/Dev/stellar-heritage/tools/vehje/`) does not exist (the code sits at `tools/clause/`).

**The imported arc is consolidated by carrying the whole shape and gauging what survives.** The
target-agnostic mechanisms are presumed to survive (inclusion-not-coverage checking, polymorphic embedding
for target-decided staging, total renderers per declared family, structural hashing as identity, explicit
frame stack with a branch quota, borrowed scope chain), with their citations and prior art travelling with
them. Everything sized, counted or justified against mockspace's corpus is presumed to fall and must be
re-derived against the nine consumers. The gauging happens topic by topic in this round, not wholesale.

**The feature-declaration model needs alternatives designed before a choice.** One bit per feature is
outgrown by every shipped system surveyed; dependency-carrying capabilities (SPIR-V) and partial-support
state (MDN) are the known extensions, but neither was designed against a spread as wide as these nine
consumers. Alternatives get designed in this round and chosen between, not defaulted.

## The questions this round has to settle

**What the shared representation is.** vehje today has a token vocabulary and a nine-category node enum. A
contract needs a representation both a grammar and a target can be written against. Whether that is an
expression core, a lowering ladder of several representations, or something else is open. Two derivation
sources are now disqualified: the imported arc's answer was sized against mockspace's corpus (which lacks
the constructs being designed), and the Python prototype is Clause-era history carrying little weight (op,
2026-07-19). The representation is derived from what the nine consumers demand, informed by prior art.

**What a grammar plugin supplies and what it may assume.** Extension repos are described as shipping
"grammar, bind targets, codegen", which spans both ends. What a grammar is obliged to produce, and what it
may rely on the core providing, is the input half of the contract.

**What a target declares and what it is obliged to handle.** The imported arc's strongest surviving
mechanism is inclusion rather than coverage: a target declares the feature set it supports, and a program
using something outside it is refused rather than degraded. Whether that is right for vehje, and what the
declaration looks like, is the output half.

**Where evaluation happens: decided.** The Zig runtime gets built now and consumers embed it (op,
2026-07-19; recorded above). What remains open within that decision is the C ABI's shape, what the compiler
still evaluates itself (const evaluation and macro expansion happen at compile time regardless), and what
the runtime owes an embedder about determinism and allocation.

**Whether staging is a property of the target.** The same source reduced for one target and preserved as
emitted code for another, with the choice belonging to the target rather than to a source annotation. Phase
four of the imported arc identifies this as polymorphic embedding (Hofer, Ostermann, Rendel and Moors,
GPCE 2008), so it is an established mechanism with a name rather than an invention.

## Deliberately not in this round

The Clause seed at `mock/design_rounds/202604191301/` is the ancestor project's design and is not vehje
canon. It is a Stellaris mod DSL whose non-goals explicitly reject a general-purpose language. Vehje's own
design opens by declaring one. The rename round states that historical artefacts are not retroactively
rewritten, so the seed stays as history and does not govern here. The Python prototype at
`~/Dev/stellar-heritage/tools/clause/` is the same category: Clause-era history, little weight, not an
oracle (op, 2026-07-19).

Crate-split changes. `mock/DESIGN.md.tmpl` marks the split provisional; this round may imply changes, but the
split is settled separately once the contract exists.
