# Topic: Project evaluation over records

**Date:** 2026-07-25
**Phase:** TOPIC
**Scope:** `runtime-zig` (the evaluation of one Core form).
**Oracle:** the completeness census, the closed compound-values round (`202607251700`), and `mock/benches/project-field-access/`.

Records became runtime values in the previous round, so `Project` is implementable. The census put it directly
behind the compound escape for exactly this reason: `Project` was never blocked on itself, it was blocked on
there being records to project from.

This is a small round and most of its design is already settled, which is worth saying plainly rather than
padding. The one thing it does have to get right is the boundary between what the runtime does and what the
compile side will later do, because the measurements make that boundary sharp and getting it wrong would build
the wrong thing well.

## What lands

`Project` carries a base and a static key. On the wire the encoder fills the node's words in order, so the base
is the first child word and the key is a blob span in the two words after it, which is the same shape a string
literal already uses. Evaluation is therefore: evaluate the base, require a record, find the field, return its
value.

Finding the field means walking the record's children, which alternate a key string with its value, and
comparing the key bytes. That pairing was settled last round: the value-node record has no key slot, and
widening every node to carry one so that records could name their fields would have made every value pay for a
property only one kind uses.

Two named refusals, because a wrong answer here would be silent. Projecting from something that is not a record
is one, and projecting a field the record does not have is the other. They are different mistakes for whoever
has to fix them, so they do not collapse into one code.

## What the measurements decide, and what they do not

`project-field-access` settled the strategy fork: a compile-resolved fixed offset costs 0.54 ns where the record
shape is statically known, a monomorphic inline cache 0.61 ns where it is not, a hashed lookup 1.27 ns, and a
linear scan 1.57 ns. It also found the hazard that matters more than the ranking: at a polymorphic site the
inline cache is the *worst* option, because the shape guard misses almost every access and pays a failed guard
plus a refill on top of the fallback, so it has to detect polymorphism and disable itself rather than thrash.

The boundary that follows is the load-bearing part of this round. **Every one of those accelerations needs
something the runtime does not have: knowledge of the record's shape at the access site.** A fixed offset needs
the shape known statically, which is a compile-side fact. An inline cache needs a shape id to guard on, which is
a representation the emitter has to assign. Neither exists yet.

So what the runtime builds now is the dynamic path, and the dynamic path is not a placeholder for the fast one.
It is the fallback every one of the fast strategies falls back *to*, and it has to exist and be correct whatever
the compile side later learns. Building the scan now is building the real thing; the accelerations attach above
it later, when the emitter can say something about the shape.

Stating that boundary is what keeps this from being either of the two mistakes available here: shipping a scan
and calling the measured strategy done, or refusing to ship a scan because a faster shape was measured and
treating the correct dynamic path as a stopgap. It is neither. It is the floor the measured strategies are
measured against.

## Boundaries

The shape-resolution work is not in this round and is not owed by it: it belongs with the compile side, and it
wants the record's shape to be a thing the emitter can name. The pattern representation, `Handle`, `Match`, and
`Iter` all stay where the census put them.

Sequences are values now, but indexing one by a computed value is the dynamic-projection fork the census
raised, and it stays open. `Project` here is field access by a static key, which is what the form carries.
