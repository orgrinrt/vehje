## Affected files

### clause-ir (new `DiagPhase`, extended `Diagnostic`)

- `mock/crates/clause-ir/src/diagnostic.rs` —
  - Add `DiagPhase` enum (`Lex`, `Syntax`, `Resolve`, `Typecheck`,
    `Codegen`, `Runtime`), `#[repr(u8)]`, derives
    `Copy, Clone, Debug, PartialEq, Eq, Hash`.
  - Add `phase: DiagPhase` field to `Diagnostic`; first field in
    declaration order so struct-literal construction reads
    naturally.
  - Update `Diagnostic::new` signature:
    `pub const fn new(phase: DiagPhase, severity: Severity, span: Span, message: &'static str) -> Self`.
  - Update `Diagnostic::error`:
    `pub const fn error(phase: DiagPhase, span: Span, message: &'static str) -> Self`.
  - `Diagnostic` stays `Copy` (`DiagPhase` is `Copy`).

- `mock/crates/clause-ir/src/lib.rs` —
  - Re-export `DiagPhase` from `diagnostic` module.

- `mock/crates/clause-ir/tests/diagnostic.rs` —
  - Update `diagnostic_new_preserves_fields` to pass
    `DiagPhase::Syntax`; assert `phase` preserved.
  - Update `diagnostic_error_helper_sets_severity` to pass a
    phase; assert `phase` preserved.
  - Update `diagnostic_with_related_labels` struct literal to
    include `phase`.
  - Add `diag_phase_variants_distinct` — each `DiagPhase`
    variant compares unequal to every other (6 variants → 15
    pairs or just assert discriminants).

### clause-lex (fan-out: pass `DiagPhase::Lex` at diagnostic construction)

- `mock/crates/clause-lex/src/lexer.rs` —

### clause-syntax (Change 1 fan-out + Change 2 signature + Change 3 newtype)

- `mock/crates/clause-syntax/src/error.rs` —
  - Update `use clause_ir::{…}` import to add `DiagPhase`.
  - Update `From<SyntaxError> for Diagnostic` to pass
    `DiagPhase::Syntax` as first arg to `Diagnostic::new`.

- `mock/crates/clause-syntax/src/lib.rs` —
  - Change `parse` signature from
    `pub fn parse(tokens: &[Token]) -> Result<Ast, SyntaxError>`
    to
    `pub fn parse(tokens: &[Token]) -> Result<Ast, Vec<SyntaxError>>`.
  - Wrap single-error path from `Parser::parse()` into a
    one-element `Vec`:
    `Parser::new(tokens).parse().map_err(|e| vec![e])`.
  - Add `// lint:allow(bare_collection)` suppression with ≥21-word
    justification on the return type.
  - Doc comment on `parse` updated to mention the vec return +
    multi-error future.

- `mock/crates/clause-syntax/src/parser.rs` —
  - Add `pub struct TokenCursor(pub u32);` with
    `#[repr(transparent)]`, derives `Copy, Clone, Eq, PartialEq,
    Ord, PartialOrd, Hash, Debug, Default`.
  - Add `impl TokenCursor` block: `new`, `as_usize`, `advance`
    const helpers.
  - Change `Parser::cursor: u32` to `Parser::cursor: TokenCursor`.
  - Update `new`: `cursor: TokenCursor::new(0)`.
  - Update `peek` to call `self.cursor.as_usize()`.
  - Update `peek_at` to `self.cursor.as_usize() + offset`.
  - Update `bump` to use `as_usize()` + `advance()`.
  - `Parser::parse` internals unchanged (uses peek/bump only).

- `mock/crates/clause-syntax/tests/empty_input.rs` — no change
  (Ok path only).

- `mock/crates/clause-syntax/tests/single_literal.rs` — no
  change (Ok path only).

- `mock/crates/clause-syntax/tests/unexpected_token.rs` —
  - Three `expect_err("…")` calls now yield `Vec<SyntaxError>`.
  - Index `[0]` to reach `kind` for the assertion. Pattern:
    ```rust
    let errs = parse(&tokens).expect_err("leading + fails");
    assert_eq!(errs[0].kind, SyntaxErrorKind::UnexpectedToken);
    ```

### clause-typecheck (no source change this round)

- No `From<X> for Diagnostic` impl exists today (the skeleton's
  validators return empty `Vec<Diagnostic>` directly, never
  constructing a `Diagnostic` in-crate). No update required.
  When a validator body first emits a `Diagnostic`, that round
  passes `DiagPhase::Typecheck`.

### clause-codegen (no source change this round)

- No `From<X> for Diagnostic` impl exists today (skeleton
  `emit` returns `Err(CodegenError)`, not `Diagnostic`; the
  two built-in stub targets produce empty artifacts on success).
  When a target body first emits a `Diagnostic`, that round
  passes `DiagPhase::Codegen`.

### clause-runtime-abi / clause-runtime-driver / clause-runtime-tests

- No change. The runtime-side `ClauseDiagnostic` is a distinct
  `#[repr(C)]` FFI type on the other side of the ABI boundary,
  not a clause-ir `Diagnostic`. Its own round will align field
  naming at the conversion-layer round (already BACKLOG).
