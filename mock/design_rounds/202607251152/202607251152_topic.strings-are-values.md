# Topic: strings are values

**Date:** 2026-07-25
**Phase:** TOPIC
**Scope:** the runtime evaluates string literals, passes strings to family handlers, and takes strings back from them. The runtime handle gains the per-session scratch that makes the last of those possible.

The runtime's value set is unit, boolean, and integer. That is enough to prove the machinery and not enough to write anything. The consumer-shape study reached the same conclusion from the other direction: with scalars only, a handler cannot receive a string, which blocks the entire string half of any standard library, and that single limit binds harder than any missing Core form.

Strings are the right first compound because the residual already carries them. The wire format ends in a self-contained byte blob, and a string literal is encoded as an offset and a length into it, precisely so the image needs no external table. So a string value costs nothing to produce: it is a slice of bytes the runtime already holds. No copy, no arena, no allocation, which is what lets the first compound land without first building a value heap.

Taking a string *back* from a handler is the part that needs somewhere to put it. A handler that concatenates or formats produces bytes that exist nowhere yet, and the runtime allocates nothing. The answer is the one the design already anticipated: per-session state, lent by the host at the point the design already has for it. `vehje_runtime_new` exists to make a runtime handle and currently returns null because there was nothing for a handle to hold. There is now: the handle owns a caller-lent scratch region, and a returned string is copied into it. The handle's lifetime is the session, which is exactly the lifetime a returned string needs.

That makes a string value uniform regardless of where its bytes live. A literal's bytes point into the residual image; a handler's result points into the session scratch; both outlive the evaluation, and neither is distinguishable to the code that reads them. The value is a byte slice, and where it came from is not part of what it is.

## Current state

`Value` is a Zig union of unit, boolean, integer, and closure. `LIT_STR` is decoded far enough to be recognised and then refused with `Unsupported`, with a note that it awaits the value arena. The residual's blob section is never read: `Image` computes the node and pool bases and stops there.

A family operand is `VehjeScalar`, a tag and a payload word, which covers the three scalar kinds and nothing else. The family-dispatch round named compound operands as the extension point and deferred them. `vehje_runtime_new` returns null and `vehje_runtime_free` does nothing, and the runtime design lists per-session arena state as intended.

`value_image.zig` writes a one-node image for a scalar. Its `writeScalar` already copies a payload into the image blob, so the shape a string needs on the way out is present; only the caller and the tag differ.

## Changes proposed

Add a string to the runtime's value set as a byte slice, and read the residual's blob so a `Lit(Str)` evaluates to the slice its offset and length name. Bounds-check the span against the blob, since the image is untrusted, and refuse a span reaching past it the way every other out-of-range read is refused.

Give the operand record a bytes pointer alongside its tag and payload. For a scalar the pointer is null and the payload is the value; for a string the pointer is the bytes and the payload is their length. That keeps one record for both rather than a second parallel form, and it keeps the common case unchanged in size and cost. Rename the record to name what it now is: an operand, not a scalar.

Let a handler return a string the same way it receives one, by writing a pointer and a length into the out-slot. The runtime copies those bytes into the session scratch, so the value stays valid after the handler returns and the host keeps no obligation once the call ends. Scratch exhaustion is a named refusal, like every other lent bound here.

Make the runtime handle real. `vehje_runtime_new` takes the scratch region the host lends and returns a handle over it; `vehje_runtime_execute` takes that handle and uses its scratch; `vehje_runtime_free` releases nothing, because the memory was never the runtime's. A null handle is accepted and means no scratch, under which a handler returning a string is a named refusal rather than a crash.

Marshal a string value into the value image with the `Str` tag and its bytes in the blob, which the writer already supports.

## Not in this round

Sequences and records, which do need a value arena rather than a byte scratch, since their elements are values rather than bytes. `Project` evaluation, which reads a field of a record and therefore waits on records existing. The Core's pattern representation and `Match` evaluation, which the consumer study established is an undecided design owed its own round. String operations themselves, which belong to a consumer's family and not to the framework.
