## Canon gate outcome

**Aligned, for this dispatch.** The assigned work is an audit of the shipped state against the canon, which is exactly what the gate exists to feed; it builds on no drifted premise. Checked against: both catalogues in full, the canon topic and ratification record in full, the standing calls, and the three live ratifications. The shipped state itself contains canon conflicts (Section "Where the shipped tree sits") and one genuine internal tension in the ratified canon that part of the path ordering depends on; that call is handed back in the final section rather than resolved here, per the gate.

## Verdict in one line

The artifact decomposition is drawn in the right places and mostly honoured, but the one seam the whole design exists for, Rust-extracted specialisation data flowing into the shared runtime, connects nothing to nothing: the extractor ignores its input (`vehje-runtime-gen/src/lib.rs:108`), the runtime reads no package (zero `comptime`, zero manifest reads in `mock/runtime-zig/src/`), the language's semantics live in a throwaway-classified sketch, and until that seam carries data the tree is two well-shaped halves of a framework plus a monolith that works.

## What the canon actually calls for

Three artifacts, one wire boundary, one specialisation boundary. Each with its input and output types.

**A. The Rust compile-side artifact** (dev time, "never sees an end-user script, never ships", `positive:45`). Under `live:1` and `live:3` its jobs are exactly four:

1. **Definition surface.** What a program is (`vehje-ir`: the twelve-plus-one Core forms, families, grades, the caller-lent `Arena`/`Builder`) and what a language is (`vehje-signature`: "the graded algebraic signature a language descends from... Data only", `vehje-signature/src/lib.rs:1-11`; one signature, three projections, `positive:31`). Input: a consumer's language definition. Output: typestate plus validated data.
2. **Specialisation extraction** (`live:3`: "The rust should extract the specialisations"). `Signature -> Package{FamilyTable, Analyzers, LoweringRules, WireLayout, Stencils} + Manifest` (`vehje-runtime-gen/src/lib.rs:29-40,104-124`), "the data the runtime's comptime specialisation reads: data, not runtime source" (`:58-59`), never Zig source (`positive:29`, the LMS kill at `negative:37`).
3. **Interop definition** (`live:1`). The contracts under which N inputs and M outputs meet at the shared IR: the `Grammar` input contract (`vehje/src/lib.rs:48-58`), the `Target` output contract with `Supports`/`Permits` inclusion (`vehje-codegen`, `vehje-typecheck/src/lib.rs:150-176`), the `Checked` witness mintable only through a clean check (`vehje-typecheck/src/lib.rs:80,158`). "Inclusion, not coverage... refused with the offending construct named" (`positive:45`).
4. **The Bundler-grade per-script path and the ABI.** Frontier A places a per-script Rust role on the lattice in words: "and at Bundler (the Rust side inlining a known constant)" (`positive:21`); Section 3 names two per-script compile-stage operations (`positive:45`). So orchestration and reduction of build-time-known programs (resolve, const-fold/CSE/DCE/ANF, emit of the tier-tagged residual byte image through `vehje-runtime-abi`, dispatch through `vehje-runtime-driver`) is licensed dev-time Rust work. Where the per-script *analyses* are implemented is the one genuinely ambiguous point; see the final section.

**B. The shipped Zig runtime artifact.** `live:2` licenses "a very generic, not-specified shared runtime" whose one legitimacy condition is that "it does not expect any kind of language, and will work with anything". Above that generic core sits the specialisation the canon mandates: "one hand-authored engine comptime-specialised to the Rust-emitted data" (`positive:45`), with the exact specialisation mechanism resolved by the lead designer on 2026-07-26 as an implementation detail settled by bench (`mock/design_rounds/202607260500_topic...md:101-106`). It contains the HostLoader compile stage ("load-time compilation, not profile-guided JIT, lives at HostLoader", `positive:21`). It is computationally self-sufficient: "Host should only basically configure the runtime and give it the allocations, nothing more" (`calls:29-31`); arithmetic is never host-supplied (`calls:27-48`). Input: the tier-tagged residual, host config, host-lent allocations. Output: values across the C ABI through the reserve/commit sink. No heap, no collector, no null, on this side too (`positive:45`).

**C. The first-party Clause consumer, a distinct artifact.** "The first-party Clause runtime is a different artifact from the framework, and it ships its own computation" (`calls:44-48`). It comprises a grammar, a family whose operation semantics reach the runtime as data, targets, and a standard library written in Clause exercising the full `CLAUSE_EBNF.md` grammar; the stdlib is both deliverable and acceptance test (`calls:1-3`, "How these interact": "a standard library, written in Clause, exercising the full grammar, running on a runtime that computes without host help"). The framework owns no family (`calls:44`, `positive:45`).

The two boundaries between them: the **C ABI / wire boundary** (residual and value images, defined and validated in Rust, spoken by Zig) and the **specialisation boundary** (the Rust-extracted package plus manifest, consumed at the runtime's build). The first exists and carries data today. The second exists on one side only.

## Where the shipped tree sits against that

1. **The specialisation seam is a producer with no consumer, and it is the framework's centre.** `vehje-runtime-gen::generate` takes `_signature: &Signature` and never reads it (`vehje-runtime-gen/src/lib.rs:108`); `Signature::Operation` carries `FamilyId`, `EffectMask`, `LeaseRule` and nothing that says what an operation computes (`vehje-signature/src/lib.rs:24-33`); `grep -c comptime mock/runtime-zig/src/runtime.zig` returns 0 and nothing in `runtime-zig/` reads a `Package`, a `Manifest`, or a family table. Against `positive:21` (LanguageAuthor stage, "the first Futamura projection as a build step"), `positive:45` ("comptime-specialised to the Rust-emitted data"), and `live:3`. The canon already catalogues the gap honestly (`negative:90`), and the live round `202607260500` exists to close it; I confirm that round is pointed at the single highest-leverage missing piece in the tree. Cost so far: the language's `+` exists only as test-host callbacks, and every day the sketch grows, more semantics accrete on the wrong side of an unbuilt seam.

2. **Arithmetic and value construction are host-serviced, the exact shape standing call 2 corrected.** `runtime.zig:410-433` dispatches `TAG_RAW` to `host.call`, refusing `NoHost` at `:414`; the only implementations of Clause addition in the runtime tree are test hosts (`runtime_family_test.zig:43-76`, `:267`). Against `calls:27-48` verbatim ("It should *NOT* have to give the simple things like fucking arithmetics"). The generic engine routing opaque family ops to whoever declared them is legitimate framework machinery under `live:2` (the framework owns no family); what is missing is the artifact that ships Clause's own computation, which is finding 1's seam plus artifact C. The round's own red test ("`1 + 2` with a null host returns 3", `202607260500_topic...md:128-130`) is the right catalogued red and is correctly still red.

3. **The shared runtime core passes the language-agnosticism test, so `live:2` licenses it.** I tested the condition rather than accepting it: `runtime.zig`'s entire vocabulary is the thirteen Core tags (`:53-65`), four literal kinds (`:68-71`), opaque `u32` family ids handed to the host ("The runtime does not know what the family means", `:411-413`), and the generic value tags `unit/boolean/int/str/seq/record/outcome` (`value_arena.zig:103-134`). No language is named anywhere in `runtime-zig/src/` (the `clause` grep hits are handler clauses). The generic core is on the right side of its boundary. Its defects are items 6 and 7.

4. **`vehje-schedule` is dissolved by ratified call and present on disk.** PE1 (`op-ratification-answers.md:243`, op verbatim) dissolves it; `negative:88` states in the present tense "The crate is deleted... the unused dep dropped". Both clauses are false in the tree: the crate exists (`mock/crates/vehje-schedule/src/lib.rs`, 74 lines, `Pass` an empty trait at `:27`, `PassDag` a unit struct at `:45`), it is a workspace member (`mock/Cargo.toml:11`), and `vehje-runtime-driver/Cargo.toml:11` still declares the unused dep. The continuation state tracks the deletion as owed work, so this is executed-nothing rather than unnoticed drift, but the effect is the same: the governing catalogue now misstates shipped state, which is precisely the Part H species ("surface existence standing in for mandate satisfaction") inverted into surface persistence standing in for an executed kill. Delete it; it is an afternoon.

5. **The driver's dispatch entry is an unconditional-success stub on the artifact seam.** `pub fn dispatch(_residual) -> Outcome<(), DriverError> { Outcome::Ok(()) }` (`vehje-runtime-driver/src/lib.rs:50-52`). It carries a FIXME, which is the honest marking discipline, but it is the same species PE1 condemned in `Schedule::build()` ("returns success unconditionally", `negative:88`): a green-reading answer at the exact boundary whose job is refusal. The real crossing exists beside it (`runtime/e2e.rs` drives the built Zig artifact behind the `dynamic` feature), so the stub is not load-bearing; it should either drive that path or return a named not-implemented error rather than `Ok`.

6. **The C ABI entry provisions its own memory instead of taking the host's.** `vehje_runtime_execute` fixes `slots: [1024]Binding`, `vslots: [1024]`, `vpool: [2048]`, `vblob: [8192]`, `buf: [16384]` internally (`runtime.zig:529-542`). Against `calls:29-31` ("give it the allocations, nothing more") and `positive:45` ("host-owned memory via caller-lent arenas and host-lent budgets"). The module doc says "caller-lent" (`:13-17`) and inside Zig it is, but the lending stops one frame short of the ABI: the C caller cannot size or lend the environment or value arenas, and the runtime has made the count-and-size decision for the host, the exact move XVII7 forbids for allocation spaces (`op-ratification-answers.md:77-79`). Only the session scratch (`vehje_runtime_new`) is genuinely host-lent. This is a boundary bug, not a hygiene nit: the resource discipline is the ABI's content.

7. **The runtime evaluator recurses on IR depth, the bug class the canon closed twice.** `eval` is "Structural recursion over the finite arena" (`runtime.zig:276-278`); the sketch's evaluator likewise (its README admits loops are stack-bounded, task #49). Against the bench-promoted rule "defunctionalization... promoted by the bench from the principled route to the only route" (`positive:61`; canon topic §7 "Recursion is a hard compiler wall; the kernels are iterative") and PE3's mandate that fixed the same defect in Rust (`op-ratification-answers.md:248-249`). A deep-skewed residual overflows the embedder's stack in exactly the embedded contexts the framework courts. PE3b's defunctionalisation round must cover the Zig side too, not just `infer`/`structurally_equal`.

8. **`vehje-fixpoint` exists once, hand-authored, in Rust, with zero in-tree callers.** 591 lines (`lib.rs`/`engine.rs`/`incr.rs`/`congruence.rs`), `grep -rln vehje_fixpoint mock/crates/*/src/` returns nothing; `negative:90` already records "no in-tree callers". The ratified canon's shape for this mechanism is "build our own no-alloc relational-engine generator emitting into both loci" (canon topic §8, `202607241545:193`): one definition, generated projections into both artifacts. What ships is neither the generator nor either projection: it is a hand implementation on one side, and the corrective FIXME at `vehje-typecheck/src/lib.rs:194-196` plans to route inference deeper into it before the locus question (final section) is settled. Do not wire more clients into this crate until that call is made; a caller-less crate is cheap to reshape and a five-client crate is not.

9. **The de-facto Clause implementation lives in the audit-trail tier.** `mock/research/sketches/202607260900_clause-in-zig/` is 5646 lines, 158 passing tests (verified: `zig test eval.zig`, 158/158), a lexer, parser, HM inference with traits, supertraits, associated types, row polymorphism, monomorphisation, enums, effects-as-discharge loops, macros-as-staged-functions, and an 89-line stdlib in Clause. By workspace convention a sketch is throwaway feasibility probing. This one is carrying the language's actual development, commit by commit (the last fifteen commits on this branch are all sketch commits). Two things follow. First, the good: it respects the wire boundary (it emits the exact residual layout `runtime.zig` decodes, no private IR) and its README states its own limits honestly. Second, the hazard: it contains a **second evaluator and a second checker**, parallel to `runtime.zig`'s, and parallel near-copies of one semantics are how ecosystems fork; the round `202607260500` src CL is named as the promotion path for the evaluator semantics, and it must land before the two definitions drift further. The sketch is licensed; letting it remain the only working implementation for long is not a licensed steady state under any reading of the artifact split.

10. **The single biggest measured lever is absent from the shipped ABI.** The canon's one ABI-shaping result is "one runtime-W batched-column entry taking W at least 2" (`positive:35`, measured ~4.8x). The shipped ABI has exactly one entry shape, single-program `vehje_runtime_execute` (`runtime.zig:521`). Measured on the carrier prototype, tagged as such by the assurance ladder; the shipped crate carries none of it. An ABI is the interface that outlives every mechanism (the ratification's own owed-work note, `op-ratification-answers.md:264`); shipping its first consumers against an entry set that lacks the known-needed shape is how the missing entry becomes unaddable.

11. **Two op-ordered benches do not exist.** PE2 ordered the CR1 continuation-representation fork benched "NOW" (`op-ratification-answers.md:245-246`, 2026-07-24); no bench in `mock/benches/` compares segmented capture-and-reinstate against compile-time CPS/defunctionalisation (grep across all findings returns nothing; `multishot-scaling` measures only SK2's enumeration overhead, one candidate's trivial half, dated 07-21). The N-buffer arena bench (XVII7, named owed at `negative:82`) likewise does not exist (`arena-locality` is an unrelated locality sweep). Meanwhile the four-way-projection sketch (`202607260800`, findings: **WORKS**, byte-identical agreement of one operation definition across Rust const, Zig comptime, and two runtime sites) is genuinely established and is the right kind of evidence for the semantics-as-data fork. Established by measurement: everything in `positive:35`/canon §7, on the prototypes it names. Assumed, still: the CR1 representation, the arena count, the record inline count (named measure-then-lock), and every "the specialised runtime computes what the reference does" claim (the differential-check runner is owed, `vehje-runtime-gen/src/lib.rs:89-91`).

12. **Small generated-surface drift.** `.claude/rules/lint-forbidden-vehje-lex.md` and `-vehje-syntax.md` govern crates that do not exist in `mock/crates/`. Regenerate or retire; a rule for a phantom crate teaches a future agent the crate is expected.

## What is missing from the complete set, in dependency order

The ordering principle is the canon's own: the deep unblocking piece first, and the specialisation seam is upstream of everything that makes vehje a framework rather than two demos.

1. **The semantics-as-data representation, bench-decided** (live round `202607260500`; the four-way sketch has demonstrated one candidate admissible; the design-space exploration and bench plan are dispatched; two independent canon-grounded agreements owed on the winner). Everything below item 3 consumes its output type.
2. **`Signature::Operation` gains semantics; `generate` reads the signature; the `FamilyId` granularity fix.** The one-`ARITH`-id bundling (pure ops, host services, and constructors under one id) defeats "refused with the offending construct named" (`positive:45`) because `Permits` cannot distinguish inside a family; the extraction schema must carry per-operation identity. Per-slice manifest hashes land here too (`vehje-runtime-gen/src/lib.rs:77-81` FIXME).
3. **The LanguageAuthor specialisation stage on the runtime side**: the runtime's build consumes the package, family operations discharge in-runtime, the manifest is verified at load, and the `1 + 2`-with-null-host red test flips green. This is the moment artifact C's computation exists and standing call 2 is satisfied.
4. **Independent of 1-3, and startable today:** execute PE1 (delete `vehje-schedule`, drop the dep); PE3b defunctionalisation covering `infer`, `structurally_equal`, **and the Zig `eval`**; host-lent env/value regions through the C ABI entry (finding 6); the driver `dispatch` stub made honest (finding 5); binding-grade and check-to-signature wiring (`positive:27,31`, canon §11).
5. **ANF threaded into `run` (FIXME `vehje/src/lib.rs:68`), then the CFG-of-blocks lowering** (producer for the dead `Block`/`Function`/`BlockTable` surface, `vehje-runtime-abi/src/wire/residual.rs:121` FIXME; downstream of ANF per canon §11), then the runtime's Bytecode-tier interpreter (its prototypes already exist in `mock/benches/cfg-interp-throughput/`). This is also what removes the sketch's loop-depth ceiling properly.
6. **The batched-column runtime-W ABI entry** (finding 10) and the ABI versioning/refusal-of-newer-residual policy, owed before any external consumer (`op-ratification-answers.md:264`).
7. **The two owed bench forks run in the harness**: CR1 representation (decides the `Handle` clause encoding) and N-buffer arenas (decides `NodeRef` branding). Both were ordered; neither blocks 1-6; both block their downstream encodings.
8. **Artifact C promoted out of the sketch tier**: the Clause grammar and family as a real consumer (locus per the final section), its semantics flowing through the item-2 schema, the resolve pass and token-stream macros the sketch names as unbuilt, and the stdlib in Clause exercising the full `CLAUSE_EBNF.md` grammar. That stdlib running on a host-free runtime is the composed acceptance test for calls 1, 2, and 3, and per PE5 it arrives when the framework is genuinely ready, not as a fork-resolver.

## Unlicensed mechanisms found

Stated plainly, with the reasoning that produced each named where it is on the record.

- **`vehje-schedule` on disk after a ratified dissolution** (finding 4). The ratified call is two days old and unexecuted while fifteen sketch commits landed. Executing a kill is cheaper than any one of those commits; leaving a dissolved crate as a workspace member makes the canon's own present-tense catalogue false and costs every future reader a verification pass.
- **The internal fixed buffers in `vehje_runtime_execute`** (finding 6). Nothing in the record licenses the runtime sizing its own arenas; the standing call says the opposite in words. This was convenience at the ABI seam, and the ABI seam is the one place convenience compounds into a contract.
- **Recursion on IR depth in the new Zig evaluator** (finding 7). The project measured this wall, wrote "the only route" into its canon, ratified a fix for the same defect in Rust, and then wrote the new evaluator recursively anyway. That is reintroducing a closed defect class in a fresh artifact, and it is the clearest case in this tree of the source ignoring the design record it sits next to.
- **The `dispatch` unconditional `Ok`** (finding 5). Marked, but a marked green lie is still a green lie at a refusal boundary; return the named error.
- **The "arc-redirect insight" re-sequencing** (workspace commit `7977b08`): op's recorded 2026-07-25 arc scoped CFG-of-blocks lowering, serialization, and a Zig CFG interpreter; an agent's own call then redirected to the Arena tree-walk as "the simpler first-runnable path". The Arena tier is a real baseline tier of the ABI design, so the destination is defensible; the *call* is unratified and self-described as the agent's insight, which is the maximally-suspect rung. It should be surfaced for confirmation, not laundered by the fact that it worked.
- **Growing the language inside a sketch** (finding 9). Licensed per-commit, unlicensed as a trajectory: the workspace's own convention says sketches probe feasibility, and 5646 lines with a second evaluator and second checker is an implementation wearing a sketch's exemptions (no lints, no design rounds, no CL claims). The promotion path exists; take it.

## Where the canon is genuinely ambiguous

Each of these is the lead designer's call. I state the tradeoff and no preference.

1. **The per-script analysis locus.** `negative:38` kills the dual-locus with "Rust never runs per-script analyses, the runtime does, for all scripts", while the same ratified canon extends the Rust check pass as the graded spine's live implementation (`positive:27`: effect and lease "computed by the join fold in the shipped check"; canon §11: wire binding-time into the check pass, wire check to signature). Three readings fit different subsets of the letter: (a) the Rust `check`/`infer` is interim scaffolding and the one analysis implementation lands runtime-side, driven by the extracted Analyzers slice, with the Rust locus invoking it over FFI for bundled scripts; (b) analyses are one *definition* with generated projections into both artifacts, the same shape the canon fixes for the relational engine ("emitting into both loci", `202607241545:193`); (c) the Rust pass is the permanent Bundler-grade analysis home and the runtime carries only the load verifier. The live ratifications narrow the frame (`live:3` makes Rust the extractor) but do not decide this, and findings 8's routing question and the whole shape of the Analyzers slice hang on it. It also decides whether the sketch's `check.zig` is a consumer-side prototype of (a)/(b) or a wrong-side artifact under (c).
2. **The front-end locus for arriving scripts.** The specialisation round explicitly holds this open (`202607260500_topic...md:122-124`). The tree demonstrates both shapes: a Rust front end (sketch `202607260000_clause-frontend`, quarantined outside `crates/`) and a Zig front end inside the runtime (sketch `202607260900`). `live:1` places interop definition in the Rust artifact but does not place per-script parsing; `GrammarHook::HandWritten` (`vehje-signature`) does not say hand-written on which side. Tradeoff: runtime-side parsing serves HostLoader-arriving scripts with one implementation but puts a parser under the no-alloc runtime discipline for every consumer; dev-time parsing keeps the runtime lean but reintroduces a second per-script locus for any script that arrives after ship.
3. **Where artifact C lives.** The extension pattern says consumers ship as separate repos; the standing call says the Clause runtime is "a different artifact from the framework"; nothing ratified says separate *repo* versus a consumer tree inside this one, and repo creation elsewhere in this workspace has been op-gated. The sketch pair is currently squatting in `mock/research/sketches/`; its promotion target needs a named home before round `202607260500`'s src CL lands Clause semantics anywhere permanent.
4. **The letter of "comptime-specialised" versus the licensed generic core.** `live:2` plus the round's recorded resolution ("an implementation detail... settled by benching", `202607260500_topic...md:101-106`) read together as: the property (self-sufficient runtime specialised to Rust-extracted data at our build) is mandate, the mechanism (comptime versus load-time table versus other) is bench-decided. If that reading is op's intent, `positive:45`'s "comptime-specialised" letter should be amended by a superseding round, because the canon is letter-governed (PE4) and the next auditor will otherwise read the winning non-comptime mechanism, or today's zero-comptime core, as drift.
5. **The Arena-tier-first sequencing** (unlicensed-mechanisms list, last-but-one item). If op confirms it, record the confirmation; if not, the CFG chain from the 2026-07-25 arc resumes as scoped. One sentence from op closes it either way.
