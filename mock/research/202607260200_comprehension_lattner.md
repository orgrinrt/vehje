# The vehje arc: strategic comprehension (Chris Lattner)

**Date:** 2026-07-26
**Status:** research. A strategic mapping of the whole arc against the canonical design; not a design round.
**Method:** the canon read in full (`canon/the-soul-of-vehje-positive-catalogue.md`, `canon/the-inverse-of-vehje-negative-catalogue.md`), op's standing calls (`202607260100_op-standing-design-calls.md`), the normative grammar (`original-docs/CLAUSE_EBNF.md`), the census and its satellite memos, and then the shipped source verified directly (crates, runtime-zig, benches, the clause-frontend sketch). Every claim below is cited; where I could not verify today, it says so.

## The complete shape in one paragraph

vehje turns a language definition into certified data rather than a compiler: every operation it knows (effect, host-call, macro, proof obligation) is discharged by one handler discipline at the earliest binding time its inputs are known, proven statically, then erased, and what remains ships as validated data that one general no-heap Zig runtime specialises to itself across an output spectrum from interpretation to native (`canon/the-soul-of-vehje-positive-catalogue.md:13-15`). The framework owns the substrate (a twelve-plus-one-form Core, four passes, a graded proof spine, a tier-tagged C ABI, the general runtime) and deliberately owns no grammar, no family, and no target; the first-party language, Clause, is one consumer among a census, and op's acceptance condition is one composed sentence: a standard library, written in Clause, exercising the full pre-redesign grammar (`original-docs/CLAUSE_EBNF.md`), running on a runtime that computes without host help (`202607260100_op-standing-design-calls.md:114-118`).

## What is being built

**The framework/language split, as the canon draws it.** vehje is a framework, not a language (`canon/the-soul-of-vehje-positive-catalogue.md:45`). A grammar plugs into the input side and lowers surface syntax into the shared IR; a target plugs into the output side, declares the family set it `Supports` and the effect set it `Permits`, and anything outside is refused with the offending construct named (inclusion, not coverage). Two artifacts ship: a dev-time Rust compiler that emits validated data and structural proofs and never sees an end-user script, and a shipped Zig runtime, one hand-authored engine comptime-specialised to the Rust-emitted data, `no_std`, no alloc, no collector, no null, host-owned memory throughout. What each side owes the other is precise: the framework owes every consumer the Core forms, the passes, the proof spine, the extension points (family hooks, `Target`, `Grammar`), the wire contract, and a runtime that is computationally self-sufficient (op call 2: the host configures, lends allocations, and receives values; it never supplies arithmetic, `202607260100:27-48`). The consumer owes the framework a grammar, a family (node kinds plus effect classification), family checks, and targets, all in a separate repo. The line op call 2 does *not* move: the framework still owns no family; arithmetic belongs to the first-party Clause *runtime artifact*, a different thing from the framework's general engine (`202607260100:44-48`).

**The layers, top to bottom.** (1) The Clause front end: lexer, parser, resolver, HM type checker with trait bounds, monomorphiser, lowering to Core; everything in it erases before emission (census tiers: resolve erases naming, macro expansion erases macros, monomorphisation erases types, target lowering erases attributes, `202607251530_language-completeness-census.md:15-22`). (2) The Core IR: thirteen forms now, the original twelve plus `Perform` admitted by algebra as `Handle`'s missing introduction (`vehje-ir/src/node.rs:146-164`), with a fourth caller-lent clause region (`node.rs:186`). (3) The compile passes: resolve (with handler scopes), the graded check (a four-coordinate judgment: binding, effect, lease, assurance), lower (MacroExpand, ConstFold, CSE, ANF catamorphism), emit/serialize. (4) The wire: the tier-tagged residual (`Tier::Arena` flat arena, `Tier::Bytecode` CFG-of-blocks, native as a spectrum point) plus the value image crossing both directions. (5) The Zig runtime: today a tree-walk evaluator over the serialized arena with a propagating unwind carrier for effects; eventually the certified-generation composed runtime specialised per language. (6) The optimisation posture, bench-settled: fold+CSE+DCE always on, in-place reuse baked in, interning and dedup refused for runtime values, batched-column SIMD ABI as the big lever (`canon/the-soul:35`, `202607251610_baked-in-optimisation-mandate.md`).

**The proof spine, priced honestly.** One graded (co)modal judgment is the intended unification; today `effect` and `lease` are computed and `binding`/`assurance` are hard-coded constants (`vehje-typecheck/src/lib.rs:367-368`). The canon says the spine earns the word theorem the day an axis-interaction rule exists in code with a red test (`canon/the-soul:27`); the first such rule now exists: the latent-effect promotion at `Lambda` plus the escape check at `Handle`, constructing the previously never-constructed `UnplaceableLease` (`vehje-typecheck/src/lib.rs:339`, `vehje-typecheck/src/handlers.rs:1-34`). That is one interaction rule of a family; the spine is still two live axes of four.

## Dependency order

The census's central discovery is that most of the grammar never reaches the Core, so the owed work collapses to a short forced chain plus a genuinely parallel front-end track (`202607251530:9, 77-83`).

**Done, in the order it landed (2026-07-25, all verified in source):** the compound operand/return escape and the value arena (records/sequences/strings cross the host boundary as a validated value image, `runtime-zig/src/value_arena.zig`, `value_image.zig`); `Project` evaluation with named refusals (`runtime.zig:291-314`); the non-resuming `Handle`/`Perform` mechanism end to end (clause region, effect scope chain, escape rule, unwind carrier that propagates and never jumps, `runtime.zig:355-401`, `vehje-typecheck/src/handlers.rs`).

**The forced chain still ahead, framework side:**

1. **Loops usable (task #49).** `loop`/`while` need no Core form (a recursive binding plus the exit as an effect), but the tree-walk has no tail-call elimination and the environment arena never pops, so a three-binding loop body dies at roughly 256 iterations against the 1024-slot region (`202607252100_handle-clause-representation.md:95-99`, `runtime.zig` env model). The fix is a trampoline plus iteration-binding reclamation, and the reclamation proof is the escape half of the reach mask that survived the #46 sketch. Forced before any real program with a loop; forced before the stdlib.
2. **The pattern representation round (task #43).** `Match` stores arms as a bare node list; the representation is a Core design decision, not an implementation gap (`vehje-ir/src/node.rs:115`, `202607251530:63`). It gates `Match` evaluation, `for` patterns, `let` patterns, parameter patterns, and the natural lowering of `?`. The dynamic-index fork (`a[i]`, `202607251530:69`) belongs in the same round because both touch what elimination means; that co-location is conventional, not forced.
3. **The binding-time axis.** Macros are not blocked on a Core form; they are blocked on the axis the IR already declares and `check` hard-codes (`vehje-ir/src/grade.rs`, `vehje-typecheck/src/lib.rs:364-368`). Forced before `macro` is real; `MacroExpand::apply` is still a dispatching no-op (`vehje-lower/src/lib.rs:432`).
4. **Runtime self-sufficiency (op call 2).** Arithmetic today lowers to `Raw` and crosses the C ABI to a handler in a test file (`sketches/202607260000_clause-frontend/tests/run.rs:60-84`; `runtime.zig:410` dispatches `Raw` to the host or refuses `NoHost`). The correction is not a default handler; it is that the first-party Clause runtime ships its own computation. This is the first real exercise of the certified-generation path (family semantics landing runtime-side), and nothing of it exists yet.
5. **The stdlib in Clause (op call 3).** The acceptance test for everything above; cannot start until the grammar expresses enough and cannot run until call 2 lands (`202607260100:55-65`). Nothing exists.

**The parallel front-end track (genuinely unforced ordering against the above).** Generics, traits, associated types, inference, and monomorphisation all erase before emission, so they wait on nothing in the runtime chain (`202607251530:83`). The sketch has the lexer and the full parser including generics, traits, associated types, and typed `macro` declarations, and a lowering that runs real programs end to end (recursion, closures) while refusing what the runtime cannot yet take (`sketches/202607260000_clause-frontend/src/lower/expr.rs:183-197`). Owed next in-track: resolve (multi-segment paths currently refuse, `lower/mod.rs:69-71`), the HM checker, the trait solver, monomorphisation, exhaustiveness. Mutual recursion is a catalogued red (`tests/run.rs:244`, task #51): `Let { rec }` binds one name, not a group.

**Framework tail, order mostly conventional:** the CFG-of-blocks lowering as the `Tier::Bytecode` structure (design pinned at `202607251003_cfg-of-blocks-lowering-design.md`; no producer exists, `vehje-runtime-abi/src/wire/residual.rs:121`); the check-to-signature wiring (the dep is declared and doc-comment-only today, `vehje-typecheck/Cargo.toml:11`); the emitter-seam closure (runtime-gen still ignores its signature and hashes the whole package, `vehje-runtime-gen/src/lib.rs:77,108`); PE1's vehje-schedule dissolution (decided, not executed, see contradictions); the PE2 CR1 representation bench (ordered, not run); the reuse-bit emission (escape filter plus an ANF last-use backward scan, per the corrected #46 sketch); the N-buffer arena bench (`canon/the-inverse:82`); the diagnostics host-lent budget discipline (canon J, nothing built).

**One ordering the record itself proved:** the value-arena work correctly ran the dedup and string cells *before* building the arena (`202607251610:62`), which is the bench-first discipline working; the arena landed once, shaped by two refusals.

## What is missing

Judged against the canon plus the normative grammar, not against the code's ambitions. Known-absent items are listed tersely; the flagged items at the end are, as far as I can find, absent from every written owed-list.

**Known and named:** `Match`/`Iter`/`Interp` evaluation (`runtime.zig:436` falls to `Unsupported`); float and char literals plus the determinism call floats force (`202607251530:71`); the mutation split (local `mut` as rebinding, places as effects) as a *position*, not yet a ratified design (`202607251530:73-75`); usable loops; patterns; the binding-time axis; macro expansion; the CFG/bytecode tier; CR1 continuation reinstatement (scoped honestly as unproven, `canon/the-soul:25`); the graded spine's two dead axes; the signature-driven projections (`canon/the-soul:31`); the distribution-composition entry point (`vehje/src/lib.rs:106` FIXME); the differential harness (`vehje-runtime-gen/src/lib.rs:89`); `vehje-fixpoint`'s zero in-tree consumers (grep verified today, still true); diagnostics discipline (canon J); the stdlib and the runtime's own arithmetic (op calls 2 and 3, one day old).

**Flagged: absent and, as far as I can tell, not yet written down as absent.**

1. **The type-system middle of the front end has no design artifact.** The census erases generics/traits/assoc types via "monomorphisation" in one line (`202607251530:19`) and the consumer study allocates one sentence to HM (`202607251149:21`), but nobody has designed the actual machinery: instantiation discovery, a unification store under no-alloc (substitution tables want exactly the buffers the discipline forbids), bounds solving, associated-type projection, coherence and `sealed`/supertrait enforcement (the old grammar's `CL_MISSING_SUPERTRAIT_IMPL`, `CLAUSE_EBNF.md:153-156`), and exhaustiveness checking (promised front-end-side, `202607251149:31`). By line count this is plausibly the largest single unbuilt component in the arc, and it has the thinnest design record of anything on the critical path to op call 1. The pattern round (#43) covers representation, not the usefulness algorithm.
2. **The token-stream half of macros is undesigned.** The grammar has typed `macro` declarations (a function at a compile stage; the census maps this to the binding-time axis) but *invocation* passes a raw `TokenStream` body with `$` interpolation (`CLAUSE_EBNF.md:218-225, 389-391`). How a typed macro receives a token stream, where token streams live under no-alloc, and how hygiene behaves at re-lex is nowhere; the `Sym` generative domain answers binder hygiene, not token capture. The binding-time axis alone does not close macros.
3. **The executed pipeline bypasses the proof spine, and no document says so.** The frontend e2e goes parse, lower, `serialize`, Zig, host (`tests/run.rs:1-17`), never touching `resolve_into`/`check`/`Checked`; and `serialize` itself takes an arena with no `Checked` or `Graded` gate (`vehje-runtime-abi/src/wire/serialize.rs:312`). Meanwhile `vehje::run` goes resolve, check, mint, emit but threads no ANF and produces no residual (`vehje/src/lib.rs:68` FIXME, and its emit path ends at `DebugTarget`). So there are two half-pipelines: the one that proves does not execute, and the one that executes does not prove. For a system whose centre of gravity is prove-then-erase, the missing junction (where `Checked` gates the wire, and what the witness covers across the lowering rewrite, named "open design" at `202607241000:63-65`) is the deepest unbuilt seam in the architecture, and its absence is only implied, never stated.
4. **Definite-assignment analysis.** The old grammar allows uninitialized `let` and defers the analysis to type inference (`CLAUSE_EBNF.md:279-283`); no census row, no memo, no task carries it forward.
5. **The `Iter` protocol is undefined.** The census marks `for` owed "(evaluation, patterns)" but `Iter` folds "a sequence" with no stated protocol for what a family-introduced sequence yields per step, how ranges (`Raw` producing a sequence, `202607251530:46`) enumerate without materialising, or how the loop-carried accumulator interacts with the reuse analysis. The CFG memo gives `Iter` a terminator shape (`202607251003:45`) but the evaluation semantics have no home.

## What the benches and sketches established

The canon's own preamble governs: a bench certifies only the artifact it ran; extrapolate no further (`canon/the-soul:7-9`).

**Measured and load-bearing (committed cells with findings):** the batched-column C ABI crossing is effectively free (~9 ns) and vertical SoA SIMD gives ~4.8x, the single biggest lever; fold+CSE+DCE always-on with CSE kept for a 76% node-count reduction, not latency; plain switch fastest on the lean straight-line IR, threading winning only real control flow; register beats stack every profile (1.41x to 3.06x); direct instruction selection ties copy-and-patch warm within 1% and compiles ~2x cheaper; native over the best interpreter is a modest 1.5x to 2.0x range, not a keystone; a 50k-node script is compile-dominated at ~3.4 ms (all `canon/the-soul:35`, backed by `mock/benches/results/` and the carrier matrix trail). From the mandate arc, three decisive cells: in-place reuse 9.7x at zero sharing and never losing (`record-update-reuse`); record dedup is an *exclusion*, not a tradeoff, because the dedup table is itself a referrer, and reuse-plus-dedup is worse than doing nothing (`dedup-vs-reuse`, `202607251610:64-88`); interning constructed strings loses 2.2x to 3.1x in all three regimes, including the one built to overturn the verdict (`string-interning`, `202607251610:89-111`, results in `mock/benches/results/INDEX.md`). Also: field-access strategy settled (0.54 ns static offset, inline cache second, self-disabling at polymorphic sites); inline operands beat pool indirection 4.4 vs 10.7 ns/node; the specialisation dispatch skeleton is ~1 KB plus ~1 byte/family (`runtime-binary-size/findings.md`); bounded multi-shot *re-execution* enumerates at ~2.5 ns/resumption (`multishot-scaling/findings.md`, an SK2 expansion; note it predates op call 5's every-bench-in-the-harness rule and ships a standalone CSV).

**Measured with a scope tag that matters:** the 8M-node/16M-edge/~50 ms fixpoint figure certifies a standalone Zig prototype, not the shipped `vehje-fixpoint::Engine`, which still has zero consumers (`canon/the-inverse:69`; grep re-verified today). The whole prototype-versus-shipped distinction now lives in the assurance ladder precisely because of this cell.

**Refuted by measurement (the inverse catalogue's Part E, all confirmed against findings):** eqsat as the research keystone (zero-or-negative marginal, the "142x win" was pessimisation misread); tail-threading as default; copy-and-patch as THE accelerator; the stack-bytecode middle tier; eval-all branch strategy; semi-naive delta on realistic shallow graphs; CSE-for-speed; and from the mandate arc, both interning candidates as runtime defaults (`canon/the-inverse:50-58`, `202607251610`).

**Refuted by sketch:** the lease-mask-to-uniqueness derivation. The mandate memo recorded it as intended; the sketch (`sketches/202607252030_lease-masks-are-escape-not-uniqueness.md`) showed the inverse reading counts ancestor chains, not holders, and the deeper category error (reach is escape, uniqueness is last use). The memo was corrected in place (`202607251610:32`), which is the record working as designed: a memo contradicted by its own sketch, and the memo says so. What survives is a two-part shape: reach as a sound escape filter, plus a new ANF-cheap last-use backward scan, with the branch-join liveness meet still an open call.

**Assumed, not measured (the honest gaps):**

1. **The cost-model k-sweep, "the design's own central measurement," still does not exist** (`canon/the-inverse:66`; no cell found today). Every setup cost is hidden at a single warm point; the tier breakeven k* is unknowable, which also keeps copy-and-patch's residual case (Part G) undecidable.
2. **The CR1 continuation-representation bench op ordered run "now" (PE2) has not run.** No capture-and-reinstate versus CPS/defunctionalisation cell exists under `mock/benches/` (searched; `multishot-scaling` measures re-execution enumeration, a different question). The reserved `resume` field and the novelty claim both ride this bench (`canon/the-soul:25`, `202607252100:70`).
3. **The unwind-carrier shape was asserted, not benched.** The handle memo says the union-return versus error-plus-out-parameter choice "is benched, not asserted" (`202607252100:121`); the implementation shipped the error-with-payload-beside form on a soundness rationale (try-returns-immediately) with no cell. The rationale is good; the hot-path cost claim is unmeasured.
4. The native range's two baselines (1.5x vs 2.0x) still owe their reconciling cell (`canon/the-soul:35`); the N-buffer arena count has no precedent (`canon/the-inverse:82`); record width on a real census corpus, dedup's memory axis, and narrow-record dedup are named unmeasured boundaries.

## Open questions for a roadmap author

1. **Where does `Checked` gate the wire?** Today nothing between the proof spine and `serialize` enforces prove-then-erase on the path that executes (finding 3 under "missing"). This is the junction question the whole architecture turns on, and it interacts with the ANF-threading FIXME (`vehje/src/lib.rs:68`) and the open "what the witness covers across a lowering rewrite" design gate (`202607241000:63-65`). I would put it first: everything downstream is a client of the answer.
2. **Does `Raw`-with-host-handler collapse into `Perform` with the host as the outermost clause provider?** The handle memo's own open question (`202607252100:135`), now sharpened by op call 2: if the Clause runtime ships arithmetic, does `Raw` remain the pure-family vehicle and `Perform` the effectful one, and which does a host *service* become? The purity-of-arithmetic objection that chose `Perform`'s shape cuts here too.
3. **What artifact is "the Clause runtime"?** Op call 2 assigns computation to the first-party runtime, distinct from the framework's engine; the certified-generation design says family semantics reach the runtime as Rust-emitted data specialised by Zig comptime. Whether Clause arithmetic is the first exercise of that certgen path or a hand-authored family in a consumer repo decides a large amount of build order, and no memo takes a position.
4. **Tier::Arena tree-walk versus linear stream** (the CFG memo's block-model fork, `202607251003:60-67`): the proposed reading (tree-walk for Arena, linear for Bytecode) is written as a proposal awaiting op confirmation.
5. **The effect-mask formulation and width are one decision** (`202607252100:137`): under the shipped scope-chain, 64 slots is generous; do not let a future mask-subtraction refactor silently reopen it.
6. **Ratify the mutation split and the float representation.** Both touch axioms (immutability underlying the lease proof; determinism underlying reproducibility); both currently rest on census positions (`202607251530:71-75`).
7. **Schedule the un-designed middle:** HM/traits/monomorphisation under no-alloc, the macro token-stream story, `Iter` semantics, definite assignment (findings 1, 2, 4, 5 under "missing"). The front-end track is currently sprinting on parsing, which was the easy third.
8. **Execute the already-decided:** PE1 (delete vehje-schedule), PE2 (the CR1 bench), the `vehje/src/lib.rs:6-7` doc claim, and a superseded-banner on `202607241000`. Each is one small round; each currently makes the record lie slightly.
9. **Stdlib scope.** Op call 3 makes the stdlib the acceptance test without naming its contents; the roadmap needs the list (which types, which string/sequence/outcome surface, how much of it forces `Iter`/patterns/effects) because the stdlib's shape back-propagates into the owed-mechanism order.
10. **Diagnostics before the surface grows further** (canon J): the front end is exactly where the no-alloc diagnostics budget will be smuggled around first if it is not designed now; the sketch's named refusals are good bones, but there is no registry, no suggestion machinery, no span-link discipline yet.
