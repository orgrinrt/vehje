# Full carrier composition-matrix: review context

## The artefact
The COMPLETE interpreter-composition benchmark matrix in `mock/benches/`, branch
`feat/extension-point-contract`. Judge whether it is sound, fair, correct, genuinely
representative, and complete enough to launch a full measurement run on.

## What it is
A minimal "carrier IR" (17 opcodes) is the shared substrate for comparing interpreter-
composition techniques. The matrix is generated by `mock/benches/src/bin/gen_matrix.rs`
(Rust; replaces retired Python `gen_carrier_*.py`), which drives the mockspace bench-harness
`matrix` generator to write one cdylib variant crate per composition plus `[bench.*]` sections
in `bench.toml`. One flexible template carries per-cell `{prep}` (pre-timed: program gen,
decode/predecode/compile/JIT, scratch alloc) and `{body}` (the one measured call per iteration,
folding into `acc`). Every variant is timed with `mockspace_bench_core::timed!` under a realistic
surrounding workload; each dispatch shape reaches operands through the shared unchecked
`access::rload/rstore` and folds one post-pass `access::checksum` (the fidelity gate).

## The families (45 benches, ~213 variants)
- wire dispatch: `carrier_dispatch_<profile>` x {switch, fntable, ifchain, ifchain_ascending,
  ifchain_linear (black_box-barrier true cascade), bittree, threaded (preserve-none), null-floor}.
- predecoded dispatch: `carrier_predecode_<profile>` x {switch, fntable, regcache, null, threaded, direct}.
- CFG register-VM: `carrier_cfg` x {switch, fntable, threaded, trace (superblock)}.
- record layout: `carrier_layout_<profile>` x {REC12,16,20,24,32}, fixed switch.
- value representation: `carrier_valrepr` x {static, tagged, nanbox}.
- residual encoding: `carrier_residual_<profile>` x {register/SSA, stack bytecode}.
- optimize stage: `carrier_optimize_<profile>` x {none, CSE, fold, DCE, eqsat, CSE+eqsat, all},
  measured by DOWNSTREAM interp cost over the resulting program (checksum_at over live-outs).
- near-native tier: `carrier_native_<profile>` x {interp, copypatch (direct codegen), stencil
  (copy-and-patch), jit-feature-gated}.
- vertical/SoA SIMD: `carrier_vertical_<profile>` x {scalar (1 input/call), vert4, vert8
  (W inputs/call, per-input = time/W)}.
- native ceiling: `carrier_native_ceiling` x {interp, native madd loop} over the madd program.
- 6 program profiles (`GenParams::profile`): real, madd, tight, scatter, wideselect, leaf.

## The question (neutral)
Evaluate whether the full matrix is ready to run: is every cell a sound, fair, representative
implementation of the technique it claims; are the comparisons honest (no accidental asymmetry in
prep vs timed region, seed handling, scratch allocation inside vs outside the timed block, per-call
work parity, baseline choice); is the coverage complete against the mandate or is anything a
caricature / missing / mislabelled; and what, if anything, must change before the run. Reach your
own conclusion from the source (`gen_matrix.rs`, the carrier `src/`, a generated variant's `lib.rs`,
`bench.toml`) and by running `cargo test` in `mock/benches/carrier`.
