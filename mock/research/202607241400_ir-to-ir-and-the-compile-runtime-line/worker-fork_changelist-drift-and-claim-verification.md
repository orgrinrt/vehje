## Part B: where the changelists are wrong, and how (the mandate's core)

Two changelist defects are the drift seeds. Both are cases where the CL translated a topic MANDATE into a WEAKER verification that the implementation could pass while missing the mandate. This is exactly the failure op suspected: the CL, not the topic, is where intent leaked.

### Defect 1: the src CL reduced "the interpreter IS a CFG of blocks" to "the struct HAS block-table fields"

- Topic mandate (`202607240100:117-124`): the runtime interpreter is a CFG of straight-line blocks with terminators, back-edges, block-argument-passed loop-carried values, a frame stack. This is a STRUCTURAL commitment about how execution works.
- Src CL verification (`202607240200:133-137`): "`Residual` carries block and function tables ... the batched-column entry signature exists ... `Tier` narrows to the internal execution form." Every clause is a TYPE-SURFACE existence check. None requires a pass that CONSTRUCTS a `BlockTable` from a `vehje-ir::Node` tree.
- Result: the implementation added `Block`/`BlockTable`/`Function`/`FunctionTable`/`TerminatorKind` as types and a flat tree-re-tag encoder (`FlatArenaEncoder`), which satisfies the CL (fields exist) while missing the topic (no CFG lowering exists). The CL's verification was satisfiable by dead type surface.
- **How to fix the CL contract:** a `## CHANGE:` for the CFG must verify CONSTRUCTION, not declaration, e.g. "`grep BlockTable::new` returns a call site in the lowering path; a program with a loop round-trips through a populated `BlockTable`." Since that pass does not exist and is real work (closure conversion plus control-flow construction, Fallin Finding C), the honest CL entry is a BACKLOG item plus a `// FIXME:` at the type definitions, NOT a green type-surface check. The remedy now: add the FIXME markers today, and open a topic deciding whether `Tier::Arena` needs a real CFG (then name the owning pass and its binding time) or is a tree-walker (then move `Block`/`Function` off the unconditional `Residual` into a `Tier::Bytecode`-gated variant).

### Defect 2: the src CL CLAIMED "check reads the vehje-signature lease-rule schema" with no verification that catches its absence

- Topic mandate (`202607240100:296`): the check pass reads the language's lease-rule schema and per-family axiom table from `vehje-signature`. This is the crate's whole justification (`:276-279`).
- Src CL claim (`202607240200:102`): "lease inference is a reach-mask fixpoint query on `vehje-fixpoint` using the binder rule; reads the `vehje-signature` lease-rule schema." The clause asserts the read as if done.
- Result: the implementation wired the fixpoint lease query but NOT the signature read (no `use vehje_signature` in `vehje-typecheck/src/`). The CL's own claim is false against the shipped source, a `cl-claim-sketch-discipline` violation, and nothing verified it because the CL wrote the claim as prose, not as a grep-checkable `## CHANGE:` with a verification command.
- **How to fix the CL contract:** the claim needed a verification like "`grep 'vehje_signature::' vehje-typecheck/src` returns the schema read at the lease-rule site." That grep would have failed at lock and blocked the false claim. The remedy now: wire the read (adopt Fallin Finding D, add `binding_time_ceiling: BindingTime` to `vehje-signature::Operation`, which forces check to actually consult the signature at the lease/effect site), turning the inert crate into the live single-source the round's soul requires.

## Part C: how the changelist defects cascaded into the subsequent rounds

This is the mechanism that produced the current "incomplete, spirit-drifted" state op feels.

- **Defect 1 (CFG) cascaded through the deepdive round (#31).** Because the src CL certified the CFG type surface as present, the later doc round elaborated the CFG as SHIPPING CONTRACT in prose: `vehje-runtime-abi/DESIGN.md.tmpl` now states "the residual is a control-flow-graph-of-blocks program, not a flat value ... the debt that the runtime contains a compile stage lands" here, and `DEEPDIVE_DISPATCH_AND_DECODE` describes the block/terminator execution as if real. The `design-doc-source-mismatch` lint cannot catch this because the backticked types (`Block`, `BlockTable`) DO exist in source, as dead surface. So each round deepened the documented commitment while the impl stayed a flat encoder, and the gap became invisible: a reader today sees a DESIGN asserting a CFG interpreter, types backing it, and a green lint, and has no signal it is unbuilt. That is precisely the drift-into-incompleteness op describes, and its origin is Defect 1.
- **Defect 2 (signature) cascaded through the graded-check rounds (#29, #30).** Because the CL's "check reads the schema" claim went unverified, the subsequent rounds that sealed the `Checked` witness and filled the graded inference built the check pass with INLINE logic and never went back to wire the signature read. Each round that grew the check pass without the schema read deepened the bypass, so the round's deepest commitment (one signature is the single source, projected) hollowed a little more with every round that treated the check as self-contained. The soul did not die in one act; it was bypassed incrementally because the first CL never forced the connection.

The pattern is one thing: a CL that verifies EXISTENCE OF SURFACE rather than SATISFACTION OF THE MANDATE lets the implementation ship the surface and skip the mandate, and every later round then builds on the surface as if the mandate were met. The two live wounds (CFG unbuilt, signature unread) are not independent mistakes; they are the same CL-verification weakness, twice.
