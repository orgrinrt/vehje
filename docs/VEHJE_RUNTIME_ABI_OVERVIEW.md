# vehje-runtime-abi. Design

C ABI contract between the Rust compiler and any runtime
backend (Zig today; possibly others tomorrow). Pure type
surface + `extern "C"` entry points. No runtime logic.

## Scope

- `#[repr(C)]` struct mirrors of vehje-ir types: `AbiSpan`,
 `AbiToken`, `AbiNode`, `AbiDiagnostic`.
- `extern "C"` entry points: init / shutdown / invoke_macro /
 eval_scratch / expand_generative / last_error.
- `abi_version: u32` as the first field on every public struct.
- `From` impls between `vehje-ir` types and their Abi mirrors.

## Round-skeleton scope

Phase 6 skeleton round (2026-04-20) ships a narrower instance
of the above:

- `VehjeResult` `#[repr(i32)]`. result code carrier.
- `VehjeRuntime` `#[repr(C)]` opaque handle (`[u8; 0]`
 private field).
- `VehjeDiagnostic` `#[repr(C)]` carrier: flat `AbiSpan`
 (`{ file, start, end }`), pointer + length message, kind
 enum.
- `VehjeDiagnosticKind` `#[repr(i32)]`. `Error`, `Warning`,
 `Info`.
- Three `extern "C"` entries: `vehje_runtime_new`,
 `vehje_runtime_free`, `vehje_runtime_execute`.
 All stubbed: `new` returns null, `free` is a no-op, `execute`
 returns `VehjeResult::Err`.

Full `AbiToken` / `AbiNode` / richer `AbiSpan` wrapping around
`FileId` / `ByteOffset`, `From` conversion impls, and the
init / shutdown / invoke_macro / eval_scratch /
expand_generative / last_error entry points are BACKLOG.

## Non-scope

- Actual runtime logic (`mock/runtime-zig/`).

## Dependencies

- `vehje-ir` for the mirrored types.
- `#![no_std]`, no alloc. FFI stays bare-types.

## Rules

- No `Option`, `Vec`, `String`, `Box` in ABI types.
- No enum discriminants > u64.
- Little-endian fixed; big-endian refuses load (BACKLOG).
- Every struct has `abi_version: u32` first (BACKLOG;
 skeleton types omit the version prefix until the first
 real-backend round surfaces the bump-compatibility need).

## FFI-wire primitive policy

`vehje-runtime-abi` defines the C-ABI surface for the Zig runtime.
Every type that crosses the `extern "C"` boundary has a wire-stable
layout requirement that bare Rust primitives satisfy by construction
but arvo types satisfy only where a `#[repr(transparent)]` newtype
preserves the underlying primitive's width byte-for-byte.

Two-tier policy (mirrors the policy established for
`hilavitkutin-extensions`):

1. **arvo newtype where wire-identical.** `USize` is
 `#[repr(transparent)]` over `usize` and can stand in for a wire
 `usize`. A `CapabilityId`-shaped type over `u64` likewise stands
 in for wire `u64`. Use the arvo newtype wherever the FFI wire
 type matches exactly and the arvo type carries semantic weight.

2. **Bare primitive with single-token allow where not.**
 `VehjeResult` is `#[repr(i32)]` and returns via the scalar
 register on every ABI target. Wrapping it changes MSVC Windows
 x64 layout. `i32` / `u32` scalars that transit `extern "C"` fn
 signatures without a wire-stable arvo newtype available stay
 bare with a `// lint:allow(arvo-types-only) tracked: #207`
 inline annotation.

Only the single-token allow form is supported. Multi-token variants
(`lint:allow(a, b, c)`) are not parsed reliably and should not be
introduced. If multiple lints need acknowledgement on a single line,
repeat the annotation once per lint, or reshape the code to remove
the need.

A future `arvo::UWire<N>` primitive (see arvo BACKLOG) provides
fixed-width wire-stable newtypes without a `S: Strategy` axis and
flips the bare sites. Until then, bare-with-allow is the policy.
