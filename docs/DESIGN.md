# vehje. Architecture Design

> The embeddable, multi-input, multi-output IR framework. A grammar plugs
> in on the input side and lowers its surface syntax into a shared IR; a
> target plugs in on the output side, declares what it supports, and emits.
> vehje owns the shared substrate, the proof axes, the output machinery, the
> runtime ABI, and an incremental scaling mechanism, not any one language.

## What vehje is

vehje is a framework, not a language. Its identity is the type system as the
verification layer and certified generation as the mechanism. Its surface is a
shared Core IR, the machinery to lower into it and fold out of it, the graded
proof that a program is safe on every axis, a runtime ABI, an incremental
scaling mechanism, and the two contracts by which a grammar plugs into the
input side and a target plugs into the output side. It ships no first-party
surface syntax, no family, and no target as part of the core.

vehje serves a spectrum of consumers equally. The representative and largest
lean toward authoring and templating, where the speed concern is the compile
stage and the emit rather than runtime logic; a native and just-in-time
endgame exists as one point on the output spectrum, never the driver.

## Two artifacts

There are exactly two artifacts, and Rust is entirely out of the runtimes.

The dev-time compiler is a Rust program that compiles a language definition (a
grammar, its families, its effects, its lease rules, its targets), proves the
language's disciplines sound, and emits validated data (the family table, the
effect masks, the lease-rule schema, the wire layout) together with proofs
carried in the structure of what it emits. It never sees a script and never
ships. The Rust crate ecosystem is this compiler.

The shipped artifact is a composed runtime written in Zig: one hand-authored
general engine (a parser, the analyzers, a macro expander, an interpreter, the
output targets) that the Zig compiler specialises at build time to the
validated data the Rust compiler emitted. It runs every program, whether the
program was bundled at build or arrives at load, and it carries no Rust
compiler and no LLVM at the consumer. The dev-time compiler emits data, not
runtime source: the specialised runtime is produced from that data, which is
the route chosen over emitting foreign source because it is the one that stays
certifiable.

Certified generation means the language's typestate proves the composition
sound at language-compile time, and the proof is compiled into the structure
of the generated runtime: illegal states are unrepresentable, dispatch over
the family set is total, and the inclusion check folds to a constant. The Rust
compiler typing its own data is the first certification and the Zig compiler
typing the specialised engine is the second, both at build, neither at the
consumer. "Certified" scopes to structural well-formedness plus per-instance
re-checking plus translation validation; semantics are checked by a
differential harness; termination is not claimed.

## The two contracts

A grammar owes the framework well-formed IR: it lowers its surface syntax into
the shared Core forms plus its own family node kinds. The framework mandates
only that contract and does not police how a grammar is defined. It offers
opt-in lex and parse building blocks and a node builder as libraries, never a
mandatory front-end. Grammar is separate from a family: a family is an
IR-and-semantics unit, a grammar is a front-end that produces IR.

A target declares what it supports, and everything else is a proof obligation
against that declaration. A target names a type-level `Supports` set of the
families it handles and a `Permits` set of the effects it allows; emission is
bounded on the program's families being included in `Supports` and its
unhandled effects in `Permits`. The guarantee is inclusion, not coverage: a
program using a family or effect outside a target's declaration is refused,
with the construct named, never silently degraded. Output generation is one
spectrum from interpretation to transpilation, and a target is a point on it;
a single typed escape hatch offers the representations a value can be for a
value the model does not know. The set machinery is `hilavitkutin-api`'s
`AccessSet` typestate, reused with vehje's own family and effect markers.

## The compile pipeline and the runtime execution model

The dev-time compiler runs a program through parse, resolve, check, lower, and
emit. Parsing produces the Core IR (for a bundled program on the Rust side, for
an arriving program in the composed runtime). Resolve is name resolution over
the Core binders on a flat shadow-stack scope chain. Check discharges the
graded proof axes as bottom-up bitmask propagations. Lower folds constants,
shares common subexpressions, and expands macros, with a cheap bounded subset
for the load-time path and a heavier equality-saturation form for the build-time
path. The proofs discharge during the graded fold and erase into region
structure, so the emitted residual carries no prover.

The runtime executes the residual as a bounded strategy portfolio: it
interprets a control-flow graph of straight-line blocks, and tiers hot regions
to native machine code where a per-region grade proves it wins. "Native" is a
method-agnostic point at the far end of the output spectrum, not a privileged
tier. A produced value crosses back through a reserve-then-commit sink into a
value-arena; the host-to-runtime interface takes a column of records per call
so the runtime can vectorise across them.

## The Core forms

The Core substrate is twelve evaluation forms: `Lit`, `Var`, `Let`, `Lambda`,
`Apply`, `Project`, `If`, `Match`, `Iter`, `Interp`, `Raw`, and `Handle`.
Eleven are the evaluation shape a grammar lowers into; the twelfth, `Handle`,
is user-defined resumable algebraic-effect handlers. `Raw` is the one typed
escape hatch through which a family's own node kinds attach. `Match` is Core
because destructuring does not desugar to `If` cleanly; there is no `Seq`
because content is a monoid and concatenation suffices.

## The graded proof spine

The static proof axes plus assurance are one graded judgment. Binding time is a
modality over the knowledge-source lattice (language-author, bundler,
host-loader, runtime); effect is a graded monad, the operations of the handler
discipline; lease and usage is a coeffect whose grade is a reachability
qualifier; assurance is a grade, a projection of the binding-time lattice
crossed with the property. There is one soundness theorem, with the per-axis
results as corollaries. The grades live in the proof; at runtime the axes are
concrete closed enums and bitmasks, and the whole graded apparatus is compiled
away, so the runtime inherits proven-safe programs and re-runs nothing except a
structural rejection of malformed input and the numeric and lease dynamic
residuals.

Reachability types are the primary lease paradigm: the lease grade is a
fixed-capacity bitmask over in-scope binders, the same machinery as the family
and effect axes. The immutable strictly-nested depth-lease is the degenerate
qualifier that ships first; the grade lattice grows into the full qualifier
additively. There is no collector: reachability-proven leases become region
markers freed on stack discipline, and a per-reference generational check is
the dynamic residual only where a value escapes past what the type can express.
Absence is an explicit `Maybe` value, never a nullable reference.

## The framework crate surface

- `vehje-ir`. The shared program-level representation: the twelve Core forms,
  the `Family` trait plus effect classification, the grade vocabulary, one
  structural-hash definition, the node builder, arena, and interner.
- `vehje-signature`. The language-level definition: the graded algebraic
  signature and its projections, split from the per-program IR.
- `vehje-fixpoint`. The generic no-alloc semi-naive relational-fixpoint engine
  and the incremental scaling layer, over caller-provided columnar storage.
- `vehje-resolve`. The Core resolve pass on a borrowed non-allocating scope
  chain.
- `vehje-check`. The graded judgment: lease and reachability inference, effect
  inclusion, binding-time discharge, and the checked witness.
- `vehje-lower`. The lowering stage: the cheap bounded const-fold and CSE
  subset, with equality saturation as a deferred second stratum.
- `vehje-schedule`. The pass-DAG ordering of consumer family passes over
  `arvo-graph`.
- `vehje-codegen`. The output machinery: the one generic fold, the `Target`
  contract, inclusion gating, and compile-time target composition.
- `vehje-runtime-gen`. Runtime generation: the validated-data package, the
  content-addressed manifest, and the differential-check contract.
- `vehje-runtime-abi`. The wire family: the residual and value arenas, the
  reserve-commit sink, and the batched-column entry.
- `vehje-runtime-driver`. Compiler-side embedding, dispatch, and the safe
  value-arena reader.
- `vehje`. The two public contracts, the orchestration, the
  distribution-composition entry point, and a reference distribution.

Every framework crate is `no_std` and alloc-free, with a documented
`#[repr(C)]` wire exception in `vehje-runtime-abi` and a `std` role for the
embedding in `vehje-runtime-driver`.

## The incremental scaling mechanism and the framework scope

The framework owns an incremental scaling mechanism (content-addressed keying,
cross-artifact dedup by structural hashing, and differential recompute over a
host-declared artifact set) so that a growing stack of arriving artifacts does
not bloat load times. The framework owns the mechanism; the host owns the load
policy and the storage backend.

The framework is core plus mechanism only. Everything above it, a language's
grammar, its families, an output family, a language, a grammar-as-data tool, is
an ordinary crate that anyone publishes and anyone depends on, on the same
footing as any other. The framework provides, promotes, defers, tracks, and
privileges no consumer surface.

## Foundations

- `arvo` (sibling repo). Numeric primitives plus analysis. `arvo-graph` backs
  the pass and relational engines, `arvo-bitmask` backs the grade and access
  bitmasks, and the content-hash primitive backs the one structural-hash
  definition.
- `hilavitkutin` (sibling repo). `hilavitkutin-api` provides the `AccessSet`
  typestate the axes reuse and the columnar and sink contracts the compile
  stage builds on, and `hilavitkutin-str` provides the interner string type.

Reuse arvo and hilavitkutin. Do not reimplement graph or DAG topology, bitmask
operations, sparse storage, content hashing, the set typestate, or the columnar
contracts.

## Consumers (separate repos, not this repo)

Grammars, families, and targets are consumers, each a separate repo. The known
census spans a first-party general-purpose language (named later), several
game-configuration and scripting languages, a native target, a lint-authoring
surface, and a procedural-documents surface. None is a framework crate.

## Not in this repo

- Any consumer's front-end, family, or targets.
- Game-specific vocabulary, bind targets, or content.
- The shipped runtime itself, which is a separate build artifact.
