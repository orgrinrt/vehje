# clause-codegen — Design

Target-agnostic codegen. Consumes a `Resolved` bundle from
clause-resolve (later: a scheduled / typed IR from clause-schedule
+ clause-typecheck). Defines the `CodegenTarget` extension-point
contract; targets opt-in by implementing the trait and being
registered in the const `TargetRegistry`.

## Scope

- `CodegenTarget` — extension-point trait.
- `TargetRegistry` — registered codegen targets (built-in + plugin).
- `CodegenCtx` — read-only carrier every target sees.
- `CodegenArtifact` + `ArtifactKind` — per-file output bundle.
- `CodegenError` — codegen error variants.
- Two built-in target ZST stubs: `NativeTarget`, `JominiTarget`.

## Non-scope

- Concrete target backends (real LLVM/cranelift lowering for
  `NativeTarget`; Clausewitz script emission for `JominiTarget`
  via the future `clause-jomini` sibling repo). Each ships in
  its own follow-up round or its own repo.
- Pass DAG scheduling (clause-schedule).
- Target-specific IR lowering (BACKLOG).
- Target-selection priority chain (CLI → package → workspace →
  builtin) (deferred BACKLOG).

## Extension-point contract (R3, finalised 2026-04-26)

`CodegenTarget` is a trait that game-specific target repos
(`clause-jomini`, future `clause-w3`, etc.) implement.

R3 finalised a richer shape:

```rust
pub trait CodegenTarget: Send + Sync + 'static {
    const NAME: &'static str;
    const VERSION: u32;

    fn accepts(&self, kind: AstNodeKind) -> bool;
    fn stages(&self) -> &'static [Stage];

    fn compile(
        &self,
        unit: &TypedUnit,
        ctx: &mut CodegenCtx<'_>,
    ) -> Result<CodegenOutput, Diagnostic>;

    fn render_diagnostic(&self, err: &TargetError) -> Diagnostic;
}
```

Stages: PreTypecheck / PostTypecheck / CodegenPre / Codegen /
Link. Targets opt in via `stages()`.

The skeleton round (202604263900) lands a narrower
instance-method shape that is object-safe directly in the const
`&'static dyn CodegenTarget` registry without `const-in-trait`
gymnastics:

```rust
pub trait CodegenTarget: Sync {
    fn name(&self) -> &'static str;
    fn emit(&self, ctx: &CodegenCtx) -> Result<CodegenArtifact, CodegenError>;
}
```

The R3 full shape (associated-const `NAME` / `VERSION`,
`accepts(kind)`, `stages()`, `CodegenOutput` with `manifest` +
`references`, `render_diagnostic`) is BACKLOG — lands when real
target backends surface the need.

`TargetRegistry` is const-sized
`&'static [&'static dyn CodegenTarget]`. The `dyn CodegenTarget`
is the ONE exception to the no-dyn discipline; acceptable because
(a) it's static-lifetime, (b) const-sized, (c) limited to the
registry iteration surface while individual `emit` calls
monomorphise via impl bound elsewhere. This mirrors the
`ValidatorRegistry` pattern in clause-typecheck.

Target selection priority: CLI `--target <name>` wins; then
package-level `[targets]` in Clause.toml; then `[workspace.targets]`;
then the built-in fallback. Implementation deferred BACKLOG —
skeleton round exposes only `lookup(name)` + `emit_for(name, ctx)`.

`CodegenCtx<'a>` this round bundles only `&'a Resolved`. R3's
`&mut DiagnosticSink`, `&mut ArtefactCache`, `&Workspace` fields
are BACKLOG.

`CodegenArtifact { kind, bytes, diagnostics }` is the skeleton
payload. R3's fuller `CodegenOutput { bytes, manifest,
references }` is BACKLOG.

Built-in targets: `NativeTarget` (future Rust/LLVM or cranelift
backend) and `JominiTarget` (future Clausewitz engine bytecode,
to be moved out to a `clause-jomini` sibling repo once it has a
real body). Both are stubs this round — `emit` returns an empty
`CodegenArtifact`.
