# vehje-lower. Design

The lowering stage the pre-round surface lacked. After the retirement of
"codegen" as one word for three operations, lowering (constant folding, common-
subexpression elimination, and macro expansion) is its own operation: it
rewrites the program, where checking discharges the judgment and emission
produces target output. Folding it into either would re-fuse what the design
deliberately split.

Lowering has two strata along one seam. The cheap runtime subset ships now and
is what serves the authoring and templating majority, whose speed concern is the
compile stage and the emit. The heavier dev-time equality-saturation e-graph is
deferred (it is the flagged original research) and lands behind the same fold
interface, so nothing downstream changes when it arrives.

## The lowering entry and its strata

- `Lower`. The stage entry: it takes a `LowerStrategy` and rewrites the IR in
  place through the arena, returning the new root. The strategy is where the two
  strata plug in, so a caller chooses the cheap subset or (later) saturation
  without the stage changing shape.
- `LowerStrategy`. The strategy the entry dispatches on: `Cheap` ships now;
  `Saturate` is the deferred dev-time e-graph stratum (named in BACKLOG, the
  variant reserved so its arrival is additive).

## The cheap subset (ships now)

- `ConstFold`. A bounded single bottom-up pass that folds an operation whose
  operands are all statically known to a literal, using the binding-time grade
  to decide "statically known".
- `Cse`. Common-subexpression elimination by hash-consing over `vehje-ir`'s one
  `StructuralHash`: a subtree that hashes equal to an earlier one is replaced by
  a reference to it, so repeated structure is shared rather than recomputed. Its
  benefit is node-count reduction, not per-op time (an optimising backend
  already removes the recompute), which is exactly what keeps a load-time
  artifact from bloating.
- `Anf`. The output normal form is A-normal form: every intermediate is named
  and evaluation order equals binding order, so effect order is explicit in the
  residual and no separate sequencing form is needed.
- `RuleTable`. The fixed rule set the cheap subset applies, and the crate's
  validated-data slice: the same table `vehje-runtime-gen` packages for the
  runtime's load-time lowering of arriving scripts, so the Rust crate is the
  definition and the Zig stage is the specialised execution.

## Macro expansion as handler dispatch

- `MacroExpand`. Macro expansion is a compile-stage-effect operation the compile
  stage handles, one instance of the handler discipline rather than a separate
  mechanism. A macro is a rewrite handled at the compile-stage handler; its
  effect is discharged here, so the residual carries no unexpanded macro.

## Non-scope

- The dev-time equality-saturation e-graph (deferred, BACKLOG).
- The check pass's proof discharge (`vehje-check`); lowering reads the grade
  annotations check writes, it does not compute them.
- Output generation (`vehje-codegen`).

## Dependencies

`vehje-ir` for the IR, the structural hash, and the grade annotations;
`vehje-fixpoint` for the relational engine the later saturation stratum queries;
`arvo` and `notko` for the primitives. `#![no_std]`, no alloc.
