# vehje-schedule. Design

The framework's compile-side pass scheduler. A DAG that orders a consumer's
family passes against the Core stages by declared dependencies, over
`arvo-graph`, walked once (single-shot topological walks). This is the
compile side; the runtime side uses hilavitkutin's morsel-driven execution,
not this crate. `#![no_std]`, no alloc.

The remit is narrowed. The compile-and-verify side is one object, not a pass
pipeline sequencing resolve and check as peers, so what this crate orders is
the genuine extension mechanism: a consumer's family passes (family-specific
checks, certified IR-to-IR macro passes) ordered against the Core stages. If
family passes turn out to be handler instances of the compile-stage effect
discipline, this scheduler folds into the orchestrator; it is kept because it
exists, is small, and deleting it now bets on an unproven unification.

## Scope

- `Pass`. A registered compile pass: a name, a declared read set and write
 set over the IR, and its dependencies. The framework's Core stages and a
 consumer's family passes register together.
- `PassDag`. The directed acyclic graph of passes, built from registration
 plus dependency declaration, backed by an `arvo-bitmask` `BitMatrix` over
 a compile-time capacity.
- `Schedule`. The topological order produced by `arvo-graph::topo_sort`.
 A cycle is the `valid_count < N` signal that sort returns; the crate
 reports it as a schedule diagnostic naming the passes in the cycle.
- Schedule diagnostics (cycle, missing dependency).

## Non-scope

- Concrete pass bodies (each pass is its own crate or a consumer's family
 pass).
- Runtime execution of a residual (the Zig runtime, `vehje-runtime-*`).
- Codegen (`vehje-codegen`).

## Dependencies

- `vehje-ir` for the IR the passes read and write.
- `arvo-graph` for `topo_sort` and DAG analysis.
- `arvo-bitmask` for the `BitMatrix` adjacency and the read/write sets.
- `#![no_std]`, no alloc. The DAG is a compile-time-capacity `BitMatrix`;
 the topological order is a stack `[NodeId; N]` from `arvo-graph`.

## Module layout

- `pass.rs`. The `Pass` contract and its read/write/dependency declaration.
- `dag.rs`. `PassDag` construction and integrity.
- `schedule.rs`. The `arvo-graph` topological walk and cycle reporting.
- `error.rs`. Schedule diagnostics.
- `lib.rs`. Re-exports and the top-level schedule entry.
