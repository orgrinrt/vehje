# vehje-codegen. Design

The framework's output machinery. It consumes a checked IR from the Core
passes and provides the contract by which a target plugs in, declares what
it supports, is inclusion- and effect-checked against that declaration, and
emits.

Output generation is one spectrum from interpretation to transpilation, and a
target is a point on it: an interpretation target reduces everything to a
value, a transpilation target reduces nothing and re-expresses the IR in
another surface, and every real target is a staging choice between. A
structurally different target forks upstream of the shared IR and pays an
honest fidelity gap rather than silently dropping. The one generic fold and
the `Target` contract are the same whichever point on the spectrum a target
sits at; the fold covers the twelve Core forms plus a program's families, and
`Raw` is where a family's own sub-structure attaches.

## The spine

A target declares what it supports, and everything else is a proof
obligation against that declaration. A target names a type-level set of
families it handles and a type-level set of effects it permits; emission
is bounded on the program's families being included in the target's set,
and the program's effects in the target's permitted set. The guarantee is
inclusion, not coverage: a program using a family or effect outside a
target's declaration is refused, with the construct named, never silently
degraded.

## Scope

- `Target`. The output plug-in contract. It extends `vehje-ir`'s
 `TargetSets`, whose associated `type Supports` (a family set) and
 `type Permits` (an effect set) are the type-level sets built from the
 `vehje-ir` family and effect markers over the reused `AccessSet`
 machinery. The sets living on the shared carrier trait is what lets the
 witness mint derive them from the target rather than take them as free
 parameters. A total fold method over the Core substrate plus the declared
 families, writing bytes through a caller-provided sink.
- `Checked`. The typestate witness that a program has been inclusion- and
 effect-checked against a specific target. It is minted by `vehje-check` (the
 witness belongs with the prover) and re-exported here; `check_for` wraps the
 sanctioned mint, deriving the inclusion bounds from the target through
 `TargetSets` and requiring the `Graded` evidence a clean check returns. `emit`
 accepts only a `Checked`, and a `Checked` is producible only by running the
 check for that target. The obligation to check is enforced at compile time; for
 a statically known program the check discharges at compile time, for a
 runtime-parsed program it is a bitmask comparison the typestate makes
 unskippable.
- The generic fold. One fold over the Core substrate plus a program's
 families, parameterised by the target, monomorphised per target. A
 target is total over the families it declares. `fold_core` descends into a
 `Raw` node's payload, folding its child handles so the target's `visit` sees
 them, rather than treating `Raw` as a leaf; the `visit` closure is itself the
 family fold hook (it runs on every node, including a `Raw` and its payload
 children), so no separate codegen hook trait is needed.
- Compile-time target composition. A distribution links the targets it
 supports; a generated match resolves a target name to a monomorphised
 emit. No `dyn`, no trait objects, no plugin shared-object loading at the
 compiler layer. Target selection by name is a runtime string resolving
 through the generated match; the emit itself is monomorphised.
- `CodegenError`. Error variants carrying context (the refused construct,
 the target, the missing family or effect), not a bare string.

## Non-scope

- Concrete target backends. Each target (a native code target, a
 game-configuration emitter, the document writers) ships in its own consumer
 repo with its own `Target` impl.
- The pass DAG (`vehje-schedule`) and the Core passes (`vehje-resolve`,
 `vehje-check`).
- The residual serialization and the C ABI (`vehje-runtime-abi`); this
 crate produces the `Checked` residual, the ABI crate lowers it.

## Dispatch: compile-time composition, no `dyn`

The framework posture is explicit: no `dyn Trait` / `TypeId` / `std::any`
in framework code, compile-time dispatch wins, single static binary, no
plugin shared-object loading at the compiler layer. Those jointly mandate
a compile-time-composed target set. A distribution is a crate that links
its targets and composes them; adding a target is a crate dependency plus
a rebuild, the rustc model. The runtime (Zig) is exempt and may load
dynamically for evaluation; the rule cuts along the compiler/runtime seam.
The previously shipped `dyn CodegenTarget` registry is drift this design
corrects.

## Renderers are total over the declared family set

A target must handle every constructor in the families it declares, and
that totality is checked. Totality is over the declared set, not a closed
universe: a target declaring `Supports = (Core, Doc)` must be total over
those, with no obligation toward a family it never claimed. This composes
with inclusion rather than conflicting; it is the same inclusion move one
level down.

## Dependencies

- `vehje-ir`. The Core substrate, the `Family` and effect markers, the
 family-set and effect-set typestate.
- `hilavitkutin-api`. The `AccessSet` inclusion machinery (reused, not
 reinvented).
- `#![no_std]`, no alloc. Byte output flows through a caller-provided
 sink; no heap-backed buffer is owned here.

## Module layout

- `target.rs`. The `Target` trait, `Supports` / `Permits` associated sets.
- `check.rs`. The inclusion and effect checks, `Checked` gating, the
 two-stage (static discharge and runtime bitmask) proof.
- `fold.rs`. The one generic fold over Core plus families.
- `compose.rs`. Compile-time target composition and name resolution.
- `error.rs`. `CodegenError`.
- `lib.rs`. Re-exports and the top-level emit entry.
