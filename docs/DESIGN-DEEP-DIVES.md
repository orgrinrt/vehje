# Deepdive: certified generation and the two-artifact model

vehje's identity is the type system as the verification layer and certified
generation as the mechanism. This deepdive states the two-artifact model, what
certified generation actually certifies, and why the proof is compiled away
rather than carried.

## Two artifacts, and Rust entirely out of the runtimes

There are exactly two artifacts. The dev-time compiler is a Rust program that
compiles a language definition (a grammar, its families, its effects, its lease
rules, its targets), proves the language's disciplines sound, and emits validated
data (the family table, the effect masks, the lease-rule schema, the wire layout)
plus proofs carried in the structure of what it emits. It never sees a script and
never ships. The Rust crate ecosystem is this compiler.

The shipped artifact is a composed runtime written in Zig: one hand-authored
general engine (a parser, the analyzers, a macro expander, an interpreter, the
output targets) that the Zig compiler specialises at build time to the validated
data the Rust compiler emitted. It runs every program, whether bundled at build
or arriving at load, and it carries no Rust compiler and no LLVM at the consumer.

The crux precision, re-confirmed by the certified-generation sketch: the Rust
compiler emits data, not runtime source. The specialised runtime is produced from
that data by the Zig compiler's own comptime, which is the route chosen over
emitting foreign source because a metaprogram emitting foreign source is the
harder-to-certify path. The runtime internally has a compile stage and an execute
stage, two stages of one artifact, not two loci and not Rust. A host embedding
the runtime over the wire ABI may itself be written in Rust, but that host is a
consumer, not part of the runtime.

## What "certified" means, precisely

Certified generation means the language's typestate proves the composition sound
at language-compile time, and the proof is compiled into the structure of the
generated runtime rather than shipped as a checker. Concretely: illegal states
are unrepresentable in the generated engine, dispatch over the family set is
total, and the inclusion check folds to a constant mask comparison. The Rust
compiler typing its own generator and data is the first certification; the Zig
compiler typing the specialised engine is the second; both are at our build,
neither at the consumer.

The scope is stated honestly. "Certified" is partial evaluation plus per-instance
re-type-checking plus translation validation, not typed metaprogramming and not
verified compilation in the CompCert sense. It scopes to structural
well-formedness: the generated engine cannot represent an unhandled, unpermitted
operation, or a family it does not support, or a program whose effect set is not
included in a target's permitted set. Semantics are checked by a differential
harness (the grade-0 shadow of the assurance-indexed logical relation), not
proven. Termination is not claimed; there is a runtime budget, not a totality
axiom.

## The handoff and the manifest

The one place the story could leak is the handoff from the Rust-emitted data to
the specialised Zig runtime. It is closed by a content-addressed manifest
(`vehje-runtime-gen`): the manifest hashes each validated-data slice and the whole
package over the one structural-hash primitive, so the specialised runtime proves
at its own build that it was specialised from exactly this package. This is the
cheaper manifest-check interim of the full lens-projection handoff (both sides
generated projections of the one signature, differential-checked structurally),
which is the open handoff-staging question. The differential test over a census
corpus is defence in depth on the data handoff, not the primary assurance a
two-backend design would be forced to lean on, because the dual-locus split
dissolved to one comptime-specialised engine and one shared object is bit-identical
whether a Rust dev host or a C runtime host links it.

## Why compile the proof away

The runtime is a fast evaluator with no collector, no null, and no re-run of the
proof. Every static axis (family inclusion, effect inclusion, lease and region
validity, and assurance) is discharged before lowering and erased into the
structure of the residual and the generated engine, so the runtime inherits
proven-safe programs and re-runs nothing except the genuinely-unknowable-until-load
structural rejection of malformed input and the numeric and lease dynamic
residuals. This is what lets the type-system-as-verification identity coexist with
a runtime small and fast enough for the authoring and templating majority: the
verification is real and total, and none of it is present at the consumer.

# Deepdive: value transport and the batched-column ABI

A produced value crosses from the runtime back to the host through a
value-arena and a reserve-then-commit sink, and the host-to-runtime interface
takes a column of records per call. This deepdive states the transport shape,
why it is one protocol for two boundaries, and the bench evidence that settled
the batched-column entry.

## The value-arena and the one-shot coroutine

The value is a value-arena: fixed-width value-node records, a flat child-index
pool, a self-contained byte blob, and relative index links, the same structural
family as the residual wire form, reused for produced values rather than IR. It
is closed and versioned (the framework owns producer and reader, so there are no
vtables), and evaluation-orthogonal (a native strategy emits the same
value-arena the interpreter does). The value serialises depth-first, children-before-parents, so
a parent records already-emitted child indices with no back-patching; a typed
structural decode over an untrusted arena is then linear and acyclic by
construction (child-before-parent makes acyclicity a single monotone index
check), which is what makes the untrusted-load path safe and fast.

The streaming producer is a defunctionalised one-shot coroutine whose suspended
frames are the chunks: each chunk is a self-contained mini value-arena, a parent
refers to an already-emitted child by chunk and index, and frontier boundedness
is the linearity of the continuation, which proves the cross-chunk lemma and the
oversized-subtree property as one linearity statement. This is the same
bounded-frontier one-shot-coroutine abstraction the compile-stage streaming uses,
so the frontier bound, the depth-cap sizing, and the acyclicity argument are
proven once and used at both ends. Region structure rides the arena: each value
node carries a region id through a region-table indirection, and region open and
close markers free a region's segment on stack discipline, no collector.

## Wire layout and the untrusted path

The zero-copy read the "wire form equals in-process form" claim depends on rests
on a declared, stable layout: the value-node records (`ValueNode` and the
`ValueList`, `BlobSpan`, `Region`, and `ValueTag` it composes) carry an explicit
`#[repr(C)]` layout, and `ValueTag` a stable declared `#[repr(C)]` discriminant
(the C-ABI default width; narrowing to a compact fixed width is part of the open
wire-spec decision below), so the
runtime reads a record at a fixed offset rather than at whatever offset the
default Rust representation happens to pick. The `ValueRef` and `RegionId` index
newtypes are `#[repr(transparent)]`. `ValueArena` itself is the in-process view
(it holds Rust slices over the lent backing), not a crossed wire type.

The untrusted-load safety has two halves, and only one has landed. The
child-before-parent order makes acyclicity a single monotone index check (the
structural half, in place). The bounds half is that every index read is checked:
`ValueArena::try_get` returns `Maybe<ValueNode>` for the untrusted path, and the
child accessor is clamped to the live pool, so a malformed arena yields a
`Maybe`/empty slice rather than a panic. The full validation pass
(`Reader::validate`) and a typestate that makes an unvalidated arena unreadable
through the safe path are the frontier: they are FIXME'd and tracked, because the
out-of-process residual story they belong to is not yet built. `get` stays the
trusted-path accessor, valid only after validation; `try_get` is the interim safe
option.

Two wire-spec details are deliberately still open (flagged for op, not decided
here): the exact `ValueTag` discriminant width, and the per-record byte layout at
the batched column entry's `BatchColumn.records` (the descriptor is specified;
the per-record shape the host fills is owed). Whether the wire form is host-native
(same architecture both sides, so the `USize` platform-width fields are fine) or a
cross-platform serialized form (which would need fixed-width fields) is the same
open question.

## One sink, two boundaries

The transfer contract is reserve-then-commit, an iteratee, a host-lent
object-capability whose backpressure is inherent. In-process it is a
`#[repr(C)]` struct of two function pointers plus opaque userdata; out-of-process
it is the executable's stdout pipe, where the OS pipe buffer is the
backpressure. Whole-value mode is the degenerate single-reserve case. The
backing memory is host-lent up front, so the runtime holds no output memory
after a call, which is what the no-alloc discipline forces and what makes the
wire form equal to the in-process form.

## The batched-column entry, and the bench evidence

vehje's real workload is per-record column evaluation: one residual over a
column of many records. The biggest measured throughput lever is vertical SIMD
interpretation (up to about 4.8x on a symmetric baseline), which needs the
boundary to take a column of W records per call so the runtime can vectorise
across them. So the decision is to expose one runtime-W batched column entry
taking W at least two.

The bench arc settled the shape and, importantly, its justification. The crossing
itself is nearly free (about 9 ns warm), which kills two tempting but wrong
designs: it kills "FFI is expensive, so the ABI must batch to amortise the
crossing" (the crossing is negligible against any interpret payload), and it
kills "the ABI must ship per-W monomorphised symbols" (a runtime-W entry with an
internal loop pays essentially nothing over the monomorphised forms at this
crossing cost). So the batched entry is justified by the vectorisation it enables
(the SoA win survives the object boundary byte-exact, 2.3x to 4.1x across residual
sizes), not by crossing cost, at every interpret tier. Crossing amortisation
becomes a live term only at the native and copy-and-patch strategy, where the payload
is cheap enough (a tiny native kernel amortises the crossing about 3x from W=1 to
W=256, and under realistic call-target misprediction the per-record crossing is
about 6x its warm cost), so the batched entry is justified there for the
complementary reason. Either way the runtime, not the ABI, owns the SIMD width.

The return contract follows from this: fallibility is a value property (an
`Outcome`-shaped value in the value-arena where a record fails), batch completion
is a stream property on the sink, and the SoA lane mask is an internal
mask-and-continue mechanism, so there is no separate status vector crossing the
boundary. Raw bench data lives in the bench history; the full-arc findings topic
is the durable record.

# Deepdive: the graded proof spine

The three static proof axes plus assurance are one graded (co)modal judgment,
unified by construction rather than by analogy. This deepdive states the
judgment, why the axes compose, what lives in the proof versus in the runtime
types, and the proof-document target. It is the theory the check pass
implements; the pass ships the concrete runtime shadow of it, and the full
metatheory is a bounded writing task drafted alongside.

## One judgment, four coordinates

A term's typing is one judgment whose context carries a per-binder coeffect
grade and whose conclusion carries an effect grade, a modal grade, and, per
property, an assurance grade.

- Binding time is a graded necessity modality over the knowledge-source
  join-semilattice. The sources are the language author, the bundler, the
  host-loader, and the runtime, joined rather than chained, so a template known
  at build with data arriving at the host is a join, not a special case. The
  modal grade is when a value's inputs are known.
- Effect is a graded monad, the operations a construct invokes, which after the
  handler unification is graded algebraic effects: an effect is an operation, a
  handler services it, and inclusion-not-coverage is restated as the unhandled
  operations being included in a target's permitted set.
- Lease and usage is a coeffect (per-operand, not per-op), whose grade is a
  reachability qualifier. Making the lease a coeffect rather than an effect is
  the one place grading changes a design decision: it recovers the per-operand
  precision an effect-only filing loses. The reachability-lease deepdive covers
  this axis in full.
- Assurance is itself a grade, and the novel move at the spine is that it is not
  an independent axis but a projection of the modal grade crossed with the
  property. A property whose inputs are all early-bound discharges statically
  (high assurance, folded to a compile error); a property whose inputs arrive
  late is a bounded dynamic residual (low assurance). So "discharge each property
  at the earliest binding time its inputs are known" becomes a computation of the
  assurance grade from the knowledge-source lattice, and the guarantee inventory
  is a computed grade vector rather than a hand-curated list.

Effects and coeffects combine by the graded adjunction, which is demonstrated
implementable in the literature. There is one soundness theorem, with the
per-axis results (staging soundness, the gradual guarantee, region soundness) as
corollaries and the axis interactions (what happens when effect, coeffect, and
binding time meet on `Apply`) as its typing rules rather than unwritten case
analyses.

## In the proof, not in the runtime types

The scoping discipline is load-bearing: the grades live in the proof and in this
design's coherence argument, never in the runtime types. At the machine level
the axes are concrete closed enums and fixed-capacity bitmasks (about two enums
and two bitmasks), and the entire graded apparatus is compile-side and compiled
away. The runtime inherits proven-safe programs on every axis and re-runs
nothing except the genuinely-unknowable-until-load structural rejection of
malformed input and the numeric and lease dynamic residuals. This is why the
check pass can ship the concrete grade computation now while the full logical
relation remains a proof-document artifact: the shippable core is the grade
enums, the bitmask joins, and the inclusion checks, and the metatheory certifies
them without the runtime carrying any of it.

## The proof-document target

The proof document is `lambda_veh`: a two-level core over the twelve forms with
a region store indexed by a live-depth stack. Its theorems are T1 (staging
soundness), T2 (the gradual guarantee per axis), and T3 (region soundness,
restricted to the LIFO chain), plus the crux immutability lemma, the cross-chunk
lemma (discharged by construction), and backward-link acyclicity as the
load-checker totality argument. The store typing and reachability-respects-lease
invariants are fixed; only the per-family axiom table is experiment-dependent, so
the document drafts in parallel with the experiments. The highest-value original
work is the assurance-indexed gradual logical relation parametric over the
generated signature: it holds as a proof where assurance is high and degrades to
its operational shadow, the differential test, where assurance is low, so proof
and test are one object at two grades. The differential test ships (as the
runtime-generation differential harness); the full relation is deferred.

# Deepdive: the reachability lease axis

The lease axis proves region validity without a collector. Reachability types are
the primary paradigm: a value's lease grade is the set of binders it can reach,
and the compiler proves that a value never outlives the binders it reaches, so
regions free on stack discipline. This deepdive states the coeffect, the bounds
that keep it no-alloc, the sharing discipline, and the avoidance boundary where a
static proof gives way to a per-reference dynamic residual.

## The lease is a coeffect, and reachability supplies its grade

The arc arrived independently at "the lease is a coeffect" (per-operand usage,
not per-op world-change), and reachability types are a coeffect, so they are the
same structure approached from two directions. The lease coeffect's grade is a
reachability qualifier realised as a fixed-capacity bitmask over in-scope
binders, the same shape and inclusion primitive as the family and effect axes.
Three axes, one bitmask machinery, one inclusion check. The immutable
strictly-nested depth-lease (the qualifier collapsed to lexical nesting) is the
degenerate case and the risk valve: it ships first on the proven-cheap
metatheorem, and the grade lattice grows into the full qualifier additively,
unlocking the mutable, aliased, and escaping cases. The mutable-consumer
extension is the bet, over a proven floor, gated on the avoidance-rate
experiment.

## The two bounds that keep it no-alloc

A reachability qualifier is richer than a scalar depth, so both the naming set
and the escape set need bounds or the inference is not no-alloc.

The naming set (the in-scope binders a node reaches, width at most the per-scope
binder width) is bounded by the reachability-type binder rule, not by a bare
in-scope filter. At `Let` and `Lambda`, the reach set is not the naive union of
the children's reach sets; it is the body's reach set with the bound variable
eliminated by substitution, where the body reaches the variable spliced in the
bound expression's reach set, then the variable dropped. This is the avoidance
operation from reachability types. A filter that drops the variable without
splicing under-approximates and is unsound the other way (a value reaching
through the bound variable into a still-live outer binder would lose that reach
and be judged safe when it is not), which is why the sound rule fires at the
binder node and plain child-propagation plus the in-scope filter carries the
already-scoped set upward.

The escape set (the out-of-scope binders a value reaches) is bounded by region
promotion: the live-region count is bounded by the program's let-and-region
structure. Sharing uses Perceus exact-meet, not shared-implies-promoted (an
ML-Kit-style leak) and not copy-everything (exponential): a shared node gets the
exact meet of its referrers' reach-sets by a reversed referrer count finalised at
emission, which is reference counting as compile-time finalisation, and the same
information licenses in-place reuse.

## The effect-coeffect interaction, and where it gets its numbers

The effect-coeffect interaction is graded def-use, not a distributive law.
Retention through a host boundary is itself an effect, so the link-or-consume bit
is a monotone function of the operand's declared effect, read from the
`vehje-signature` lease-rule schema. This collapses the single most realistic
unsoundness vector into the already-tested effect table: where the effect is
precise, the link bit is a lookup; where it is coarse, the reachability grade
refines it. The measured cost is the same bottom-up bitmask join as effect
inference, differing only in payload.

## The avoidance boundary and the generational residual

Reachability inference is compile-side and erased into certified region structure,
so the runtime inherits proven-valid references with no collector and no
refcount. At the avoidance boundary, where a value escapes and its type cannot be
expressed without the escaped binder, the property's assurance grade drops and a
per-reference generational-reference check is the dynamic residual for exactly
that un-placeable reference, not a whole-value collapse. Avoidance succeeds gives
a static proof (high grade); avoidance fails gives the generational check (low
grade). This is the graded-assurance dial made concrete on the lease axis: the
residual has a home rather than being a parallel fallback. The closure-escape
case that `Lambda` makes first-class is the hardest case the forms surface, and
it is exactly what reachability types were built for. Absence, throughout, is an
explicit `Maybe` value, never a nullable reference.

The region-leak history is the cautionary tale banked: pure region inference
leaks (ML Kit needed a collector back, Cyclone shipped a hybrid). vehje's
position holds the immutable core pure-static and makes the mutable and escaping
fallback a reachability-type and generational-reference discipline, never a
collector. A CHERI output target is an optional hardware assurance grade for the
lease axis, additive rather than core.
