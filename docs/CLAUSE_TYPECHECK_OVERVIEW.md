# clause-typecheck — Design

Type checking, generic resolution, coherence checking, bind-target
resolution, and the validator framework. Consumes the `Resolved`
bundle from clause-resolve; produces a typed graph plus a flat
vec of `Diagnostic`.

## Scope

- `TypeChecker` — top-level state + drive loop (future round).
- `TypeEnv` — type environment per scope (future round).
- `Generics` — generic parameter handling, substitution, bounds
  (future round).
- `Coherence` — overlap detection for trait impls (ships this
  round as a ZST validator stub; body is future round).
- `BindTarget` — resolution of target-language types (generic
  scaffolding; concrete targets land in clause-jomini and friends
  via the extension point from R3).
- **Validator framework** — ships this round in skeleton form
  (trait + registry + 10 ZST stubs, each returning `Vec::new()`).
- Type diagnostics (currently: each validator constructs its own
  `Diagnostic` and the registry flattens; sink API is BACKLOG).

## Non-scope

- Pass DAG scheduling (clause-schedule).
- Codegen (clause-codegen).
- Concrete target bind-table content (extension crates).

## Dependencies

- `clause-ir`, `clause-syntax`, `clause-resolve`.
- arvo for numeric / newtype discipline.
- arvo-bitmask for validator access sets (one validator ↔ one
  AccessSet over Namespace/Scope entries; surfaces in a future
  round).
- `std` allowed (host-side compiler crate, not embedded).

## Module layout (skeleton round, 2026-04-20)

- `validator.rs` — `Validator` trait.
- `registry.rs` — `ValidatorRegistry` with const `VALIDATORS`
  list and `run_all` collector.
- `ctx.rs` — `ValidatorCtx<'a>` carrier.
- `strict1.rs` … `strict7.rs` — one ZST per STRICT validator.
- `coherence.rs` — `Coherence` ZST.

## Validator framework — current shape (skeleton round)

`Validator` is a trait; `ValidatorRegistry` hosts a const
`&[&'static dyn Validator]` slice with ten entries. Same
`&'static dyn` exception as clause-codegen's `TargetRegistry` —
confined to the registry iteration surface, static-lifetime.

```rust
pub trait Validator: Sync {
    fn name(&self) -> &'static str;
    fn validate(&self, ctx: &ValidatorCtx) -> Vec<Diagnostic>;
}

pub struct ValidatorCtx<'a> {
    resolved: &'a Resolved,
}

impl ValidatorCtx<'_> {
    pub fn new(resolved: &Resolved) -> ValidatorCtx<'_> { /* ... */ }
}

pub struct ValidatorRegistry;

impl ValidatorRegistry {
    pub const VALIDATORS: &[&'static dyn Validator] = &[
        &Strict1, &Strict2, &Strict3, &Strict4,
        &Strict5, &Strict6, &Strict7,
        &Coherence, &OrphanRule, &BindTargetShape,
    ];

    pub fn run_all(ctx: &ValidatorCtx) -> Vec<Diagnostic> { /* ... */ }
}
```

Core validators (ship in clause-typecheck, bodies TBD):
- STRICT1 `no-shadow` — variable shadowing detection.
- STRICT2 `unused` — dead binding detection.
- STRICT3 `assign-to-immut` — immutable binding reassignment.
- STRICT4 `int-overflow` — compile-time integer-overflow audit.
- STRICT5 `use-after-move` — move-semantics invariant check.
- STRICT6 `ambiguous-imports` — use-tree ambiguity.
- STRICT7 `clippy-batch` — curated style / bug-prone batch.
- `coherence` — trait-impl overlap detection.
- `orphan-rule` — foreign-type / foreign-trait impl guard.
- `bind-target-shape` — target-registry entry-format check.

Each validator's `validate` this round returns `Vec::new()` —
the skeleton keeps `run_all` safe (no `todo!()` panic) so
downstream consumers can exercise the registry surface.
