# vehje-typecheck. Design

The framework's Core-level check pass (the `vehje-check` role; the crate
directory retains the `vehje-typecheck` name until a later cosmetic
rename). It checks the resolved Core IR, generic over the family set, with
family-extension hooks. Like resolve, it is framework-owned because the
shared passes are what make the shared IR real rather than nominal. The
design authority is `202607192320`. `#![no_std]`, no alloc.

## Scope

- The check walk over the Core forms: the shared, target-agnostic checks
 every consumer's IR must pass (well-formed binders, arity, the family and
 effect classifications being consistent with the nodes that carry them).
- Family-extension hooks: a family's own checks (a language's coherence and
 orphan rules, a Clausewitz family's routing checks, a doc family's block
 nesting rules) extend the walk. The Core pass runs the shared checks and
 dispatches to the family checks for family nodes.
- Check diagnostics, carrying the construct and the rule violated.

## Non-scope

- Any one consumer's type system (generics, traits, coherence as surface
 features). Those are a consumer family's checks, plugged in through the
 extension hooks, not Core.
- Resolution (`vehje-resolve`), scheduling (`vehje-schedule`), emission
 (`vehje-codegen`).

## Dependencies

- `vehje-ir` for the Core IR and the family and effect classifications.
- `hilavitkutin-api` for the family-set typestate.
- `hilavitkutin-str` for interned identity.
- `notko` for `Maybe` / `Outcome`.
- `#![no_std]`, no alloc.
