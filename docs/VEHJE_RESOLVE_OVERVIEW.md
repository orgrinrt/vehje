# vehje-resolve. Design

Module resolution, use-tree expansion, visibility, scope
construction, and manifest-driven crate graph. Consumes AST
from vehje-syntax; produces a `Resolved` bundle carrying the
AST plus a `ScopeTree` and a per-`NodeId` resolution map.

## Scope

- `Resolver`. top-level state: `ScopeTree` + cursor. Drives
 the walk; each deferred resolution rule lands as its own
 micro-round that extends the walk.
- `ScopeTree`. lexical scope hierarchy with `ScopeId` (from
 vehje-ir) keys, backed by a `Vec<Scope>`.
- `Scope`. `parent: Maybe<ScopeId>` plus a symbol map keyed
 by `Str` (interned). Backing storage is a skeleton
 `HashMap<Str, Symbol>` until the scheduler wires it through
 a Column (#131); see SHAME.md.
- `Symbol`. name (`Str`) + scope + node + kind
 (`SymbolKind::{Type, Value, Module, Import, Function,
 Const}`). `Str` is 4 bytes Copy, so `Symbol` is `Copy`.
- `Resolved`. `Ast + ScopeTree + Vec<Maybe<Symbol>>` (resolution
 map indexed by `NodeId`, skeleton backing; see SHAME.md).
 This round produces an empty map.
- **Manifest parsing**. `Vehje.toml` parser lives here (not its
 own crate); drives the crate graph. `crate_name` and `version`
 are `Str`; `dependencies` is a skeleton `Vec<Str>` until the
 scheduler/persistence spine lands (see SHAME.md). Skeleton
 stub returns default `Manifest` on empty input,
 `ManifestError::NotImplemented` otherwise.
- Resolve diagnostics (`UnresolvedIdentifier`,
 `DuplicateDefinition`); enumeration expands as the resolution
 rules land.

## Non-scope

- Any real resolution rule beyond opening the root scope
 (top-level items, local bindings, path lookup, use-tree
 expansion, visibility, generics, traits, hygiene). each lands
 as its own follow-up round. See BACKLOG.
- Real TOML parsing. skeleton stubs; `toml_edit` integration
 lands as a follow-up round.
- Type checking (vehje-typecheck).
- Trait resolution (vehje-typecheck).
- Pass DAG scheduling (vehje-schedule).

## Dependencies

- `vehje-ir` for `NodeId`, `ScopeId`, `Span`, `Diagnostic`.
- `vehje-syntax` for `Ast`, `AstNode`.
- `hilavitkutin-str` for the `Str` interned handle (symbol
 names, manifest fields).
- `notko` for `Maybe` / `Outcome`.
- `std`. host-side compiler crate. `Scope` uses `HashMap` and
 `ScopeTree`/`Resolved` use `Vec`. The embedded-friendly
 `no_std` / fixed-arena discipline that applies to `vehje-ir`,
 `vehje-lex`, `vehje-syntax` does NOT apply here: resolve is
 executed in the compiler binary, not in the runtime.

## Module layout

This round ships:

- `resolver.rs`. `Resolver` struct + stub `resolve` driver.
- `scope.rs`. `Scope` + `ScopeTree`.
- `symbol.rs`. `Symbol` + `SymbolKind`.
- `resolved.rs`. `Resolved` bundle type.
- `manifest.rs`. `Manifest` + `parse_manifest` stub.
- `error.rs`. `ResolveError` + `ManifestError`.
- `lib.rs`. module decls, re-exports, top-level `resolve`.

`binding.rs`, `use_tree.rs`, `visibility.rs`, `diagnostics.rs`
are deferred to the follow-up rounds that first need them.
