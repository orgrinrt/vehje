# vehje-runtime-driver. Design

The compiler-side dispatch over the tier-tagged C ABI. It takes a `Checked`
residual, serializes it at the chosen tier through `vehje-runtime-abi`,
hands it to the embedded Zig runtime, and maps the runtime's result and
diagnostics back to `vehje-ir` diagnostics. The design authority is the ABI
topic (`202607192340`). `#![no_std]`, no alloc.

## Scope

- The dispatch entry: hand a `Checked` residual to the runtime at a chosen
 tier and read back its outcome.
- Result and diagnostic mapping from the ABI's wire diagnostics to
 `vehje-ir::Diagnostic`.
- The embedding of the Zig runtime artifact. The Zig runtime is a separate
 build artifact compiled to a static library the driver links; it is not
 dlopen'd at the compiler layer. Multiple runtime backends, if they ever
 exist, compose at compile time (the target model), never through `dyn` or
 a shared-object registry.

## Non-scope

- The wire format and tier tags (`vehje-runtime-abi`).
- Runtime execution semantics (the Zig runtime).
- The residual's construction (`vehje-codegen`).

## Dependencies

- `vehje-ir` for the diagnostic type.
- `vehje-runtime-abi` for the tier-tagged wire form.
- `#![no_std]`, no alloc. No `dyn`, no `libloading` at the compiler layer;
 the runtime is statically linked.

## Deferred (BACKLOG)

The tier-1 and tier-2 dispatch paths (behind the reserved tier tags). The
Zig runtime build integration.
